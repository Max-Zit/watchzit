Instalace agentů

Agent WatchZit je volitelný. Hlásí to, co síť zvenku nevidí: CPU, paměť, disky, rozhraní a služby počítačů s Windows a Linuxem, každou minutu, přes jedno odchozí spojení.

Registrační kódy

V části Agenti vytvořte registrační kód: název, kolik dní platí, kolik počítačů ho smí použít a skupinu, do které přijdou nová zařízení. Kód se zobrazí jen jednou; obsahuje adresu serveru a otisk certifikátu agentů, takže agent důvěřuje jen vašemu serveru.

Windows

Stáhněte MSI ze stránky Agenti a nainstalujte ho; vyžádá si kód. Na mnoha počítačích ho instalujte potichu (GPO, Intune, skript):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

Agent běží jako služba WatchZitAgent.

Linux

Stránka Agenti ukazuje příkaz, který stáhne agenta z portu agentů, ověří jeho SHA-256 a nainstaluje ho s kódem (služba systemd watchzit-agent):

curl -fsSk https://<server>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Nebo nainstalujte balíček deb či rpm z vydání (amd64 a arm64, z GitHubu), pak agenta zaregistrujte a spusťte; aktualizace přicházejí přes správce balíčků nebo vlastní aktualizace agenta:

sudo apt install ./watchzit-agent_<verze>_amd64.deb      # nebo: sudo dnf install ./watchzit-agent-<verze>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

Co agent hlásí

  • Zatížení CPU (a na Linuxu průměrné zatížení), paměť a swap, každý disk, každé síťové rozhraní s provozem — samy se z nich stanou kontroly s grafy.
  • Inventář: operační systém, model CPU, paměť, výrobce, model, sériové číslo, adresy, služby.
  • Stroje Hyper-V (Windows) a kontejnery Docker (Linux), každých pět minut, s jejich stavem, CPU, pamětí a adresami; zobrazují se na stránce zařízení a v polích hypervizorů na mapách.
  • Sledované služby: zvolte je na stránce zařízení v části Sledovat služby; služba, která se zastaví, otevře problém.
  • Sledované procesy: v části Sledovat procesy na stránce zařízení zadejte názvy programů (například nginx, sqlservr.exe, java); každý dostane kontrolu s počtem běžících instancí, jejich CPU a pamětí, a když žádná neběží, otevře se problém.
  • Chybové zprávy systému — kritické a chybové události z logů Windows Systém a Aplikace a zprávy s prioritou err a horší ze žurnálu systemd — se s každým hlášením dostanou do Logy (druh Agenti); spouštěč logů se zdrojem Agenti z nich otevírá problémy.

Pokud existuje zařízení se stejnou adresou nebo názvem, agent se k němu připojí; jinak se vytvoří nové zařízení.

Aktualizace agentů

Agent starší než server dostane při připojení agenta ve verzi serveru (nejvýše jednou za hodinu): stáhne instalátor ze serveru přes vlastní šifrované, připnuté spojení, ověří jeho velikost a SHA-256 a nainstaluje ho. Agenti Windows nainstalovaní z MSI spustí nové MSI; linuxoví agenti (systemd) ověří, že se nový program spustí, nahradí se jím a systemd je restartuje. Stránka Agenti označuje starší agenty; správci tam v části Aktualizace agentů vypínají automatické aktualizace a jedním kliknutím aktualizují všechny agenty online. Agenti starší než 1.2 aktualizace ještě neznají a je třeba je jednou aktualizovat ručně.

Vzdálené kolektory

Zařízení v jiné síti — na pobočce, u zákazníka za NAT, v uzavřené správcovské VLAN — často z konzole dosažitelné není. Nainstalujte agenta na libovolný počítač v té síti (Linux nebo Windows; stačí malý virtuální stroj nebo počítač třídy Raspberry Pi) a klikněte na Použít jako vzdálený kolektor v části Agent na stránce jeho zařízení. Pak ho zvolte v poli Sledováno z u zařízení této sítě (nebo pro mnoho najednou v seznamu zařízení v Změnit vybrané). Kolektor dostane jejich kontroly — ping, TCP, SNMP, webové stránky a scénáře, certifikáty, DNS, databáze, RouterOS, JSON API — s potřebnými hesly a nastavením SNMP, spouští je v jejich intervalech a výsledky posílá přes vlastní šifrované spojení. V lokalitě nepotřebuje žádný otevřený port a nemá vlastní webové rozhraní; vše se nastavuje v konzoli.

Když je spojení s konzolí přerušeno, kolektor kontroly dál spouští; výsledky (až za jeden den, nejnovějších 200 000) na něm čekají a dorazí, jakmile se spojení obnoví, takže v grafech nevznikne mezera. Kontroly jeho zařízení mezitím ukazují neznámý místo nefunguje (v lokalitě může být vše v pořádku) a kontrola agenta kolektoru otevře problém. Uchované výsledky nepřežijí restart kolektoru: své kontroly si pak znovu načte z konzole.

Záložní kolektor: nainstalujte agenta na druhý počítač v lokalitě, také z něj udělejte kolektor a zvolte ho jako Záložní vedle Sledováno z (nebo pro mnoho zařízení v seznamu zařízení v Změnit vybrané → Záložní kolektor). Dokud je první offline, spouští jejich kontroly záložní; když se první vrátí, znovu je převezme.

Zjišťování a SNMP: v Zařízení → Zjišťování zvolte kolektor vedle nového rozsahu: prohledá tuto síť své lokality a zařízení, která z ní přidáte, jsou sledována z něj. Zjišťování SNMP na stránce zařízení a čtení údajů, rozhraní a VLAN také probíhá přes kolektor. Kontroly hypervizorů zůstávají u konzole. Přestat sbírat vrátí zařízení konzoli.

Síť

Agenti se připojují k portu agentů 8444. V Nastavení → Síť a přístup nastavte veřejnou adresu pro agenty, pokud agenti dosáhnou na server pod jiným názvem (například přes firewall), a omezte sítě, ze kterých se agenti smějí připojovat.

Odebráním agenta na stránce zařízení se jeho klíč stane neznámým; chcete-li agenta znovu používat, zaregistrujte počítač novým kódem.
