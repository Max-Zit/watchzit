Řešení potíží a časté dotazy

Ping hlásí „ICMP is not allowed“

Server potřebuje oprávnění posílat ICMP. Služba z balíčku ho má (CAP_NET_RAW). Jinde ho udělte příkazem setcap cap_net_raw+ep /usr/bin/watchzit-server nebo povolte neprivilegovaný ping: sysctl net.ipv4.ping_group_range="0 2147483647".

SNMP ukazuje „no answer“

  • Zkontrolujte v profilu komunitu nebo uživatele SNMPv3, protokoly a hesla.
  • Povolte na zařízení adresu serveru WatchZit (mnoho zařízení odpovídá jen uvedeným manažerům) a na firewallech UDP 161.
  • Když je uživatel v3 neznámý nebo je heslo špatné, zpráva to uvede.

Agent se nepřipojí

  • Počítač musí dosáhnout na port agentů 8444 serveru; zkontrolujte Nastavení → Síť a přístup (povolené sítě, veřejná adresa pro agenty).
  • Windows: Get-Service WatchZitAgent a log v C:\ProgramData\WatchZit Agent. Linux: journalctl -u watchzit-agent.
  • „the server does not know this agent“: zařízení bylo odebráno; zaregistrujte ho znovu s novým kódem.

Oznámení nepřicházejí

  • Odešlete test z Nastavení → Oznámení; seznam kanálů ukazuje poslední chybu.
  • Problémy v údržbě nebo za nefunkčním zařízením se neodesílají; zkontrolujte nejnižší závažnost kanálu.

Zablokoval jsem si přístup

Po příliš mnoha neúspěšných přihlášeních se adresa na čas zablokuje. Na serveru: watchzit-server --unblock-ip all. Pokud vás povolené sítě vylučují: watchzit-server --reset-allowlist.

Kde jsou logy?

journalctl -u watchzit-server a /var/lib/watchzit/logs/server.log; pomocník aktualizací zapisuje /var/log/watchzit-helper/helper.log. Nastavení → Diagnostika ukazuje nejnovější řádky a dá ZIP bez tajných údajů k odeslání podpoře.

Časté dotazy

Potřebují zařízení agenta? Ne. Kontroly pingu, portů, SNMP, webu, DNS, databází a API běží ze serveru; agent přidává to, co ví jen samotný počítač.

Kolik zařízení? Jeden server zvládne tisíce kontrol za minutu; měření se komprimují, takže i rok dat zabere málo místa.
