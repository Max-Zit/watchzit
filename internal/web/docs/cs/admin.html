Uživatelé, nastavení a aktualizace

Kdo smí co dělat, jak je konzole chráněna a jak WatchZit zůstává aktuální.

Každý uživatel se přihlašuje heslem a dvoufázovým přihlášením (ověřovací aplikace); záložní kódy pomohou při ztrátě telefonu. Správci přidávají uživatele v části Uživatelé a resetují hesla a dvoufázové přihlášení. Protokol auditu zaznamenává každou změnu; jeho záznamy jsou zřetězené, takže změny v protokolu jsou poznat.

Active Directory / LDAP a jednotné přihlášení

Kromě místních účtů se uživatelé mohou přihlašovat adresářovým účtem. Místní účty fungují vždy, takže se správce přihlásí, i když adresář nebo poskytovatel identity nefunguje. Uživatelské jméno, které patří místnímu účtu, adresářové přihlášení nikdy nepřevezme.

  • Active Directory / LDAP (Nastavení → Active Directory / LDAP): server (ldaps://dc1.example.local nebo ldap:// se StartTLS — hesla nikdy nejdou sítí nešifrovaně), volitelně certifikát firemní certifikační autority, servisní účet, který smí číst uživatele a skupiny, základní DN a filtr uživatelů (Active Directory (&(objectClass=user)(sAMAccountName={username}))). Ve službě Active Directory se sledují i vnořené skupiny. Heslo ověří adresář; WatchZit se přesto zeptá na svůj vlastní druhý faktor. Test ověří účet bez přihlášení a ukáže skupiny a roli, kterou by dostal.
  • Jednotné přihlášení (Nastavení → Jednotné přihlášení): OpenID Connect (Microsoft Entra ID, Google, Okta, Keycloak …: vydavatel, ID klienta a tajný klíč; jako adresu přesměrování zaregistrujte https://<konzole>/login/sso/callback) nebo SAML 2.0 (ADFS, Entra ID, Okta …: URL nebo XML metadat poskytovatele identity; zadejte mu https://<konzole>/login/sso/metadata, adresa odpovědi je /login/sso/saml). Přihlašovací stránka dostane tlačítko. Na vlastní druhý faktor WatchZit se ptá navíc jen tehdy, když to zaškrtnete; jinak rozhoduje politika poskytovatele identity.
  • Skupiny a role: při každém přihlášení určují roli skupiny — správci, operátoři nebo pozorovatelé, vyhrává nejvyšší — a uživatelé, kteří nejsou v žádné ze skupin, dostanou výchozí roli, nebo se nemohou přihlásit. Skupina je její název nebo úplné DN, případně název nebo ID, které posílá poskytovatel identity (Entra ID posílá ID).
  • Adresářové účty se vytvářejí při prvním přihlášení a v seznamu uživatelů mají označení LDAP nebo SSO. Nemají heslo WatchZit; zakažte je ve WatchZit, chcete-li je nepustit dovnitř, i když je adresář pustí.

Nastavení

  • Síť a přístup — porty konzole a agentů, sítě, ze kterých se k nim smí připojit, veřejná adresa pro agenty.
  • Přihlášení a zabezpečení — délka relace, kolik neúspěšných přihlášení adresu zablokuje, a rušení blokování.
  • Naměřená data — jak dlouho se uchovávají surové, pětiminutové a hodinové hodnoty a kolik zabírají místa.
  • Certifikát — vlastní certifikát konzole, vámi nahraný nebo od Let's Encrypt (viz níže).
  • Vlastní pole — vaše vlastní pole zařízení (viz Zařízení).
  • Diagnostika — kde jsou logy, nejnovější řádky logu serveru s filtrem a ZIP pro podporu (logy, zařízení, agenti, problémy, protokol auditu) s odstraněnými hesly, komunitami, tokeny, registračními kódy a klíči; uložené konfigurace zařízení nejsou zahrnuty.
  • SNMP, Oznámení, Nástroje, Kioskové displeje — viz jejich kapitoly.

Aktualizace

Nastavení → Aktualizace a server ukazuje běžící verzi a nejnovější vydání. Při instalaci z linuxových balíčků se WatchZit aktualizuje sám:

  1. Přijímají se jen vydání podepsaná klíčem vydání WatchZit.
  2. Pomocník s právy roota zálohuje databázi a program, nainstaluje nový balíček a ověří, že se konzole spustí.
  3. Pokud se nespustí, sám se vrátí ke staré verzi.

Kanál aktualizací určuje, co konzole instaluje: Oficiální verze, nebo Testování — kandidáty na vydání, kteří přicházejí před oficiálním vydáním, pro testovací konzoli. Produkční konzole nechte na oficiálních verzích.

Aktualizace lze instalovat kliknutím nebo automaticky ve zvolenou hodinu. Zdrojem může být zrcadlo nebo místní složka (WATCHZIT_UPDATE_SOURCE v /etc/watchzit/server.env). Na stejné stránce se nastavuje časové pásmo serveru a restartuje služba.

Bez přístupu k internetu: v části Instalovat ze souborů nahrajte manifest.json, manifest.json.sig a balíček serveru (.deb nebo .rpm) vydání, stažené na jiném počítači. Zkontrolují se jako při stažení a nainstalují se stejně.

Operační systém a SSH

Stejná stránka ukazuje aktualizace operačního systému serveru (Debian, Ubuntu, AlmaLinux, Rocky Linux): kolik jich čeká a kolik z nich jsou bezpečnostní aktualizace, zda jsou zapnuté automatické bezpečnostní aktualizace a kdy naposledy proběhly. Nainstalovat všechny aktualizace je nainstaluje hned; když vyžadují restart, stránka to oznámí a Restartovat server ho restartuje. Seznam se sám obnovuje dvakrát denně, nebo tlačítkem Zkontrolovat nyní.

Na appliance WatchZit stránka nastavuje také jeho síť (DHCP nebo pevná adresa, brána, DNS, název — nastavení, která appliance odříznou, se po 30 sekundách vrátí) a SSH: zapnuto nebo vypnuto a jeho port; port, který server SSH odmítne, ponechá staré nastavení. Na jiných serverech to patří operačnímu systému. SSH na appliance nepovoluje přihlášení jako root ani přesměrování (SSH tunely přes něj).

Certifikát

Po instalaci konzole používá vlastní certifikát, na který prohlížeče upozorňují. V Nastavení → Certifikát:

  • Nahrát certifikát vaší firmy: certifikát s řetězcem a soukromý klíč v PEM (soubory nebo vložený text), pro název DNS — nebo IP adresu —, který prohlížeče používají. Před použitím se zkontroluje.
  • Let's Encrypt: zadejte název a e-mailovou adresu. Let's Encrypt ověří název přes port 80 tohoto serveru (dosažitelný z internetu), nebo, když je konzole interní, pomocí DNS záznamu přes Cloudflare (API token s oprávněním Zone → DNS → Edit). Certifikát se sám obnoví 30 dní před vypršením.
  • Obsluhovat port 80 navíc přesměruje do konzole prohlížeče, které zadají http://.

Důvěryhodný certifikát se použije, když se konzole otevře pod svým názvem; při otevření přes IP adresu používá konzole dál vlastní certifikát. Agentů se to netýká: používají vlastní certifikát portu agentů, který si připnuli při registraci. Chcete-li používat standardní port, nastavte port konzole na 443 v Síť a přístup.

Záloha konzole

Nastavení → Záloha konzole zálohuje celou konzoli: databázi se všemi měřeními, tajný klíč uložených hesel, klíč launcheru a certifikáty, kterým agenti důvěřují — vše, co nový server potřebuje, aby práci převzal. Zálohy se zapisují do backups v datovém adresáři každý den ve zvolenou hodinu (a tlačítkem Zálohovat nyní); uchovávají se nejnovější (ve výchozím stavu 7).

  • Šifrování: s heslem (alespoň 12 znaků) se soubor zašifruje (AES-256-GCM). Heslo uchovávejte jinde: bez něj zálohu obnovit nelze.
  • Kopie SFTP: každá záloha se také zkopíruje do složky na jiném serveru (heslo nebo soukromý klíč). První Otestovat složku SFTP ukáže klíč hostitele serveru, kterému máte důvěřovat; kopie jdou jen na server s tímto klíčem. Složka uchovává stejný počet záloh jako server.
  • E-mail při neúspěšné záloze pošle upozornění přes SMTP server z Nastavení → Oznámení.
  • Obnovení probíhá při zastaveném serveru: na appliance položkou nabídky nastavení Restore a console backup; u linuxových balíčků systemctl stop watchzit-server, pak watchzit-server --data-dir /var/lib/watchzit --restore FILE jako uživatel watchzit s načteným /etc/watchzit/server.env (šifrovaná záloha čte heslo z WATCHZIT_BACKUP_PASSPHRASE nebo --restore-passphrase-file) a potom server spusťte. Obnovení nahradí vše v jedné transakci; záloha starší verze se při spuštění serveru převede na aktuální. Agenti fungují dál: důvěřují stejnému certifikátu.

Zabezpečení

  • Konzole používá jen HTTPS, přísnou Content Security Policy a ochranu proti požadavkům z cizích webů; odpovídá jen povoleným sítím.
  • Hesla se hashují algoritmem Argon2id; uložená tajemství (SNMP, hesla databází a API, kanály) se šifrují tajným klíčem serveru.
  • Agenti se identifikují vlastním klíčem; serveru důvěřují podle připnutého otisku jeho certifikátu agentů.
  • Zranitelnosti hlaste soukromě: viz SECURITY.md v repozitáři.
