REST-API

Scripts en andere systemen lezen via een JSON-API apparaten, controles, grafieken en problemen uit, bevestigen problemen en plannen onderhoud.

Tokens

Maak een token aan onder Mijn account → API-tokens: een naam en hoeveel dagen het geldig is. Het wordt één keer getoond. Een token handelt als u, met uw rol (het token van een kijker kan alleen lezen); trek het in wanneer het niet meer nodig is. Mislukte tokens tellen als mislukte aanmeldingen en blokkeren het adres een tijdlang.

Stuur het mee in een header; de API accepteert nooit de sessiecookie van de console:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Eindpunten

VerzoekAntwoord
GET /api/v1/statusversie, apparaten per status, open problemen per ernst
GET /api/v1/devicesapparaten; filters q, status, group
GET /api/v1/devices/{id}een apparaat met zijn controles en de id's van hun reeksen
GET /api/v1/series/{id}?range=24hde punten van een reeks: tijd, minimum, gemiddelde, maximum
GET /api/v1/problemsopen problemen; view=history, severity, device
POST /api/v1/problems/{id}/ackbevestigen: {"note": "…"}
GET /api/v1/maintenanceonderhoudsvensters
POST /api/v1/maintenanceer een plannen: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Tijden zijn in RFC 3339 (2026-11-01T22:00:00+01:00). Fouten zijn {"error": "…"} met een passende HTTP-status. Wijzigingen worden met de naam van het token in het auditlogboek vastgelegd.
