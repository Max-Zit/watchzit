问题、告警与通知

触发器监视检查结果并产生问题。条件结束时问题会自动关闭；问题未解决期间可以对其进行确认，并且它会被发送到您的通知渠道。

您也可以添加自己的触发器：一个值（CPU 负载、响应时间、流量、连接数 …），高于或低于某个阈值，持续至少若干分钟（短暂波动不会产生问题），一个严重程度，以及适用于所有设备、某个组还是某一台设备。

没有新数据会在某项检查在您设定的分钟数内没有获得新值时产生问题——例如停止上报的代理、不再响应 SNMP 的设备、已停止的数据源；如有需要，可将其限定于特定检查类型。

数值将达到阈值（预测）则着眼于未来：它对该数值最近一周（至少六小时的历史）拟合一条直线，当该直线在您设定的天数内达到阈值时产生问题——例如十天后将满的磁盘、正在填满的存储池、持续上升的温度。问题会显示当前值、每天的变化速度以及预计达到的日期；当趋势不再能按时达到阈值时，问题关闭。

数值在该时段异常（自动学习）不需要阈值：WatchZit 根据最近四周学习该数值在一周中每个小时的常见水平——繁忙的周一早上不同于安静的周日夜晚——当数值明显偏离时（偏高、偏低或两者）就会打开问题。灵敏度决定偏离多少才算异常：高也会报告较小的变化，低只报告大的变化。有一周历史数据后开始比较；问题中会写明该时段的常见值和正常范围。

单项检查。设备页面上检查旁边的铃铛按钮可为该检查单独添加一个触发器——对于 SNMP OID 数值（以 °C 表示的温度、以 V 表示的电压）这是必需的，因为每个数值都有自己的单位；对于某个重要的磁盘或端口也很方便。此类触发器会在“适用于”中列出设备和检查；它会随其检查一起被删除。

问题

问题列出所有未解决的问题，最严重的排在最前；菜单中的数字表示已发送的问题数量（有严重问题时显示为红色）。确认问题并附上备注，让其他人知道已有人在处理。已解决的问题会在历史记录中保留一年。

依赖

在设备上设置依赖于（例如分支机构的路由器）。当该路由器宕机时，其后面的设备仅被视为不可达：它们的问题会被记录但不会发送——您只会收到一条关于路由器的消息，而不是五十条。在地图上，这类设备显示为带虚线轮廓的灰色而不是红色，其面板会说明问题出在上游。

如需一次为整个网络设置依赖，请打开地图并点击依赖：从网络所依托的设备（默认是线缆最多的路由器或防火墙；如有需要可选择其他设备）开始沿线缆追溯，系统会为每台设备建议其前一台设备——交换机依赖于路由器，无线接入点依赖于交换机，虚拟机依赖于其服务器。电源、HA 和 VXLAN 线缆不计入。没有依赖的设备会被勾选；已依赖其他设备的设备会显示但不勾选。点击设置勾选的依赖。

维护

在问题 → 维护中为设备或组计划维护窗口。在此期间，设备仍会被监控，问题也会被记录，但不会发送任何通知；维护结束时仍未解决的问题会在那时发送。可用性报告会单独显示维护时间。重复可让窗口每天、每周或每月重复出现（夜间备份、每月补丁日），并可选择设置结束日期；列表会显示下一个窗口，移除会结束整个系列。

通知

位于设置 → 通知（管理员）：

  • 邮件服务器——支持 STARTTLS、TLS 或不加密的 SMTP；密码加密存储。可发送测试邮件。
  • 渠道——电子邮件收件人、Webhook（JSON；设置密钥后会在 X-WatchZit-Signature 中使用 HMAC-SHA256 签名）、Slack、Microsoft Teams、Discord、Telegram（来自 @BotFather 的机器人令牌和聊天 ID）、ntfy（通过 ntfy.sh 或您自己的 ntfy 服务器推送到手机）、PagerDuty（Events API v2 集成密钥；问题会创建和解决事件）、通过 Twilio 发送短信（帐户 SID、认证令牌、发送方、电话号码）或通过自有网关发送短信（任意 HTTP 地址，在消息所在位置使用 {text}）。每个渠道都有最低严重程度，并且可以在问题解决时发送通知。
  • 通知的语言以及其中链接所使用的控制台地址。

升级与值班

在渠道的升级与值班时间中设置：

  • 延迟通知（分钟）——该渠道只会收到超过该时间后仍未解决的问题，例如一线人员未响应时，15 分钟后通知团队负责人。重复间隔会在问题未解决期间再次通知。
  • 已确认的问题不会被升级或重复通知，除非开启了包括已确认的问题。
  • 仅在某些日期和时间会使该渠道成为值班渠道：例如周一至周五 18 点到 08 点以及整个周末向夜班发送短信。在值班时间之外开始的问题，如果到值班开始时仍未解决，就会在那时送达。如需轮班，请为每个人或团队添加一个渠道，并设置各自的日期和时间。
  • 收到问题通知的渠道也会在问题解决时收到通知；其他渠道则不会。

Syslog 和 SNMP trap

设备可以将其日志消息和 SNMP trap 发送到 WatchZit。在设置 → Syslog 和 trap中开启：默认情况下，syslog 使用 UDP 514，trap（SNMP v1 和 v2c，会应答 inform）使用 UDP 162，可选择只接收指定团体名的 trap，保留 30 天。请在服务器防火墙中开放这些端口，并在设备上将 WatchZit 设为目标，例如在 MikroTik 上使用 /system logging action set remote remote=<服务器> 以及动作为 remote 的日志规则，在 FortiGate 上使用 config log syslogd setting，在 Linux 上添加一行 rsyslog 配置 *.* @<服务器>:514。

  • 日志按从新到旧的顺序列出消息，可按搜索内容、设备、来源（syslog 或 trap）以及最低重要级别（0 emergency … 7 debug）筛选。来自非设备地址的消息会显示其地址。每个设备页面都有一个日志按钮。
  • 类别为 Syslog 消息或 trap 的触发器会在消息包含某段文本（或匹配斜杠之间的正则表达式，例如 /link (down|failure)/）且级别不低于所选级别时产生问题。只要此类消息持续到来，问题就保持未解决；在触发器设定的时间内没有此类消息时，问题关闭。这些问题在报告中不计为停机时间。

流量流（NetFlow、IPFIX、sFlow）

路由器、交换机和防火墙可以报告经过它们的流量。在设置 → 流量流中开启采集器：默认情况下，NetFlow v5、NetFlow v9 和 IPFIX 使用 UDP 2055，sFlow v5 使用 UDP 6343，保留 7 天（1–90）。请在服务器防火墙中开放这些端口，并将 WatchZit 设为采集器，例如在 MikroTik 上使用 /ip traffic-flow set enabled=yes 和 /ip traffic-flow target add dst-address=<服务器> port=2055 version=ipfix，在 FortiGate 上使用 config system netflow，在支持 sFlow 的交换机上将 sFlow 代理的采集器设为本服务器。

  • WatchZit 按分钟和导出器，以会话（源、目标、协议和服务端口——两个端口中较小的那个）为单位汇总流量。每分钟保留每个导出器最大的 1,000 个会话；其余部分合并为一行不含地址的记录，因此总量保持准确。采样流量（sFlow，或设置了采样率的 NetFlow）会乘以采样率。
  • 流量流显示最近一小时、6 小时、一天或一周内某个或所有导出器的流量随时间的变化，以及排名靠前的源、目标、服务、导出器和会话。控制台中设备的地址会显示为该设备。导出器的设备页面上有一个流量流按钮。
  • 来自非设备地址的流量会被忽略，除非开启了也接收非设备地址的消息。
