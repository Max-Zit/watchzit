安装代理

WatchZit 代理是可选的。它上报网络从外部看不到的信息：Windows 和 Linux 计算机的 CPU、内存、磁盘、接口和服务，每分钟一次，通过一条出站连接传输。

注册码

在代理中创建注册码：名称、有效天数、可使用它的计算机数量，以及新设备所属的组。注册码只显示一次；其中包含服务器地址和代理证书的指纹，因此代理只信任您的服务器。

Windows

从代理页面下载 MSI 并安装；安装时会要求输入注册码。如需在大量计算机上安装，可使用静默安装（GPO、Intune、脚本）：

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

代理以服务 WatchZitAgent 的形式运行。

Linux

代理页面会显示一条命令，它从代理端口下载代理、校验其 SHA-256，并使用注册码进行安装（systemd 服务 watchzit-agent）：

curl -fsSk https://<服务器>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

也可以安装该版本的 deb 或 rpm 软件包（amd64 和 arm64，来自 GitHub），然后注册并启动；更新通过包管理器或代理自身的更新机制进行：

sudo apt install ./watchzit-agent_<版本>_amd64.deb      # 或：sudo dnf install ./watchzit-agent-<版本>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

代理上报的内容

  • CPU 负载（Linux 上还有平均负载）、内存和交换空间、每块磁盘、每个网络接口及其流量——它们会自动成为带图表的检查。
  • 清单：操作系统、CPU 型号、内存、厂商、型号、序列号、地址、服务。
  • Hyper-V 虚拟机（Windows）和 Docker 容器（Linux），每五分钟一次，包括其状态、CPU、内存和地址；它们显示在设备页面和地图上的虚拟化主机框中。
  • 监视的服务：在设备页面的监视服务中选择；服务停止时会产生问题。
  • 监视的进程：在设备页面的监视进程中输入程序名称（例如 nginx, sqlservr.exe, java）；每个程序都会获得一项检查，记录运行的实例数及其 CPU 和内存，没有实例运行时会产生问题。
  • 系统的错误消息——Windows 系统和 Application 日志中的严重和错误事件，以及 systemd 日志中优先级为 err 及更高的消息——会随每次上报发送到日志（类别代理）；来源为代理的日志触发器可据此产生问题。

如果已存在地址或名称相同的设备，代理会加入该设备；否则会创建新设备。

代理更新

版本低于服务器的代理在连接时（最多每小时一次）会获得与服务器版本相同的代理：它通过自身加密且已固定证书的连接从服务器下载安装程序，校验其大小和 SHA-256 后进行安装。使用 MSI 安装的 Windows 代理会运行新的 MSI；Linux 代理（systemd）会先确认新程序能够启动，再替换自身，并由 systemd 重新启动。代理页面会标记较旧的代理；管理员可在该页面的代理更新中关闭自动更新，并一键更新所有在线代理。1.2 之前的代理尚不支持更新，需要手动更新一次。

远程采集器

位于其他网络中的设备——分支机构、NAT 后面的客户站点、封闭的管理 VLAN——通常无法从控制台访问。在该网络中的任意一台计算机上安装代理（Linux 或 Windows；一台小型虚拟机或 Raspberry Pi 级别的机器即可），然后在其设备页面的代理框中点击用作远程采集器。接着在该网络的设备上将其选为监控来源（或在设备列表的更改所选中一次为多台设备设置）。采集器会接收这些设备的检查——Ping、TCP、SNMP、网页和场景、证书、DNS、数据库、RouterOS、JSON API——以及它们所需的密码和 SNMP 设置，按各自的间隔运行，并通过自身的加密连接发送结果。它在站点上不需要开放任何端口，也没有自己的 Web 界面；一切都在控制台中设置。

与控制台的连接中断时，采集器会继续运行检查；结果（最多一天，最新的 200,000 条）在采集器上等待，连接恢复后再送达，因此图表不会出现空缺。在此期间，其设备的检查显示为未知而不是故障（站点本身可能正常），而采集器的代理检查会产生问题。保留的结果在采集器重启后不会保留：它会重新从控制台获取检查。

备用采集器：在站点的第二台计算机上安装代理，同样将其设为采集器，并在监控来源旁边将其选为备用（或在设备列表中通过更改所选 → 备用采集器为多台设备设置）。第一个采集器离线期间，由备用采集器运行检查；第一个恢复后会重新接管。

发现和 SNMP：在设备 → 发现中，于新范围旁选择采集器：它会扫描其站点的该网络，从中添加的设备由它监控。设备页面上的 SNMP 发现以及事实、接口和 VLAN 的读取也通过采集器进行。虚拟化平台检查仍由控制台执行。停止采集会将设备交还给控制台。

网络

代理连接到代理端口 8444。当代理通过其他名称访问服务器时（例如经过防火墙），请在设置 → 网络与访问中设置代理公共地址，并限制允许代理连接的网络。

在设备页面上移除代理后，其密钥将变为未知；如需再次使用该代理，请使用新的注册码重新注册该计算机。
