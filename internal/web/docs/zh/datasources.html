数据源

图表和仪表板也可以显示来自 WatchZit 外部的时间序列：您自己数据库中的表、Prometheus、InfluxDB 或任何返回 JSON 的地址——与代理和检查的数值并列显示。

添加数据源

管理员在设置 → 数据源中添加数据源：

类别地址登录方式
PostgreSQLhost 或 host:port（5432），以及数据库用户和密码
MySQL / MariaDBhost 或 host:port（3306），以及数据库用户和密码
Microsoft SQL Serverhost 或 host:port（1433），以及数据库SQL Server 用户和密码
PrometheusURL，例如 http://prometheus:9090；也支持 Thanos、VictoriaMetrics、Mimir无、用户和密码，或 Bearer 令牌
InfluxDBURL，例如 http://influx:8086，以及数据库（InfluxDB 2/3：bucket）InfluxDB 1：用户和密码；2 和 3：仅需令牌
JSON over HTTP您的服务的基础 URL无、用户和密码，或 Bearer 令牌

测试连接会在不保存的情况下尝试这些设置。密码或令牌会加密存储，且不会再次显示；将该字段留空即可保留原值。

对于 SQL 数据库，请选择加密方式：服务器提供时（默认）、始终加密并接受任意证书、始终加密并要求受信任的证书，或从不加密。对于 https:// 地址，可以接受自签名证书。

请为控制台提供一个只能读取所需表的用户。WatchZit 在只读事务中运行 PostgreSQL 和 MySQL 查询；SQL Server 没有这种机制，因此在那里只能依靠用户权限来保护数据。操作员编写查询；查看者只能查看图表。

图表中的查询

在设备页面上点击编辑图表，然后点击图表上的 ✎ 或添加图表。在数据源下点击添加查询，选择数据源并编写查询。试运行会在页面的时间范围内运行查询，并显示其返回的序列（及其数据点数量）或数据库的错误。一个图表最多可以显示 6 个查询，与设备的数值并列显示，每个查询都可设置序列名称、单位和颜色。

在仪表板上添加小部件数据源图表。

结果会缓存 20 秒，因此在多个屏幕上显示的仪表板只会查询数据库一次。一次查询最多返回 200,000 行和 50 个序列，最长可运行 20 秒；数值会按图表宽度进行抽稀。

SQL（PostgreSQL、MySQL、SQL Server）

查询返回一个时间列（名为 time，或第一个包含时间的列；也可以是 Unix 秒或毫秒），一个或多个数值列（每列一个序列），以及可选的用于命名序列的文本列（metric，或第一个文本列），适用于每个序列每个时间点一行的表。请按时间排序。

宏会将图表的时间范围代入查询：

宏展开为
$__timeFilter(col)col 介于范围的开始和结束之间
$__timeGroup(col)col 向下取整到图表的间隔；$__timeGroup(col, 300) 取整到 5 分钟
$__timeFrom、$__timeTo以时间类型表示的开始和结束
$__unixFrom、$__unixTo以 Unix 秒表示的开始和结束
$__interval_s以秒为单位的图表间隔

示例：

-- 每个间隔的订单数（PostgreSQL、MySQL、SQL Server 通用）
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- 每个仓库一个序列
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

编写 PromQL，例如 rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8。每个序列按 Prometheus 的写法命名（name{label="value"}）；在编辑器中设置的序列名称会替换它。步长随图表宽度而定。

InfluxDB

使用 $timeFilter 和 $__interval 编写 InfluxQL：

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 和 3 通过其 1.x API 响应 InfluxQL：如果 bucket 尚未映射到数据库，请在那里进行映射。

JSON over HTTP

查询是附加到地址上的路径或参数（例如 /api/temps?room=server）；WatchZit 会以 Unix 秒添加 from、to 和 step，并读取以下任一格式的响应（时间以秒或毫秒表示）：

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
