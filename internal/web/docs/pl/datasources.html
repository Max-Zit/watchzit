Źródła danych

Wykresy i pulpity mogą pokazywać także szeregi czasowe spoza WatchZit: tabele twoich własnych baz danych, Prometheus, InfluxDB lub dowolny adres odpowiadający w JSON — obok wartości z agentów i sprawdzeń.

Dodawanie źródła danych

Administratorzy dodają źródła danych w Ustawienia → Źródła danych:

Testuj połączenie sprawdza ustawienia bez ich zapisywania. Hasło lub token są przechowywane w postaci zaszyfrowanej i nigdy nie są ponownie wyświetlane; zostaw pole puste, aby je zachować.

Dla baz SQL wybierz szyfrowanie: gdy serwer je oferuje (domyślnie), zawsze z dowolnym certyfikatem, zawsze z zaufanym certyfikatem lub nigdy. Dla adresów z https:// można zaakceptować certyfikat z podpisem własnym.

Daj konsoli użytkownika, który może tylko odczytywać potrzebne jej tabele. WatchZit wykonuje zapytania PostgreSQL i MySQL w transakcji tylko do odczytu; SQL Server nie ma takiej możliwości, więc tam dane chronią wyłącznie uprawnienia użytkownika. Operatorzy piszą zapytania; obserwatorzy widzą tylko wykresy.

Zapytania na wykresach

Na stronie urządzenia kliknij Edytuj wykresy, a następnie ✎ na wykresie lub Dodaj wykres. W sekcji Źródła danych kliknij Dodaj zapytanie, wybierz źródło danych i napisz zapytanie. Wypróbuj uruchamia je w zakresie czasu strony i podaje zwrócone szeregi (z liczbą ich punktów) lub błąd bazy danych. Wykres może pokazywać do 6 zapytań obok wartości urządzenia, każde z nazwą szeregu, jednostką i kolorem.

Na pulpitach dodaj widżet Wykres ze źródła danych.

Odpowiedzi są przechowywane przez 20 sekund, więc pulpit na kilku ekranach odpytuje bazę danych tylko raz. Zapytanie zwraca najwyżej 200 000 wierszy i 50 szeregów i może trwać do 20 sekund; wartości są przerzedzane do szerokości wykresu.

SQL (PostgreSQL, MySQL, SQL Server)

Zapytanie zwraca kolumnę czasu (o nazwie time lub pierwszą kolumnę zawierającą czas; działają też sekundy lub milisekundy Unix), jedną lub więcej kolumn liczbowych (każda to szereg) oraz opcjonalnie kolumnę tekstową, która nazywa szeregi (metric lub pierwsza kolumna tekstowa), dla tabel z jednym wierszem na szereg i czas. Sortuj według czasu.

Makra wstawiają zakres czasu wykresu do zapytania:

MakroZamienia się na
$__timeFilter(col)col między początkiem a końcem zakresu
$__timeGroup(col)col zaokrąglone w dół do interwału wykresu; $__timeGroup(col, 300) do 5 minut
$__timeFrom, $__timeTopoczątek i koniec jako czas
$__unixFrom, $__unixTopoczątek i koniec w sekundach Unix
$__interval_sinterwał wykresu w sekundach

Przykłady:

-- zamówienia na interwał (tak samo w PostgreSQL, MySQL i SQL Server)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- jeden szereg na magazyn
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Pisz w PromQL, na przykład rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Każdy szereg jest nazwany tak, jak zapisuje go Prometheus (name{label="value"}); nazwa szeregu w edytorze ją zastępuje. Krok dopasowuje się do szerokości wykresu.

InfluxDB

Pisz w InfluxQL z $timeFilter i $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 i 3 odpowiadają na InfluxQL przez swoje API 1.x: zmapuj tam bucket na bazę danych, jeśli nie jest jeszcze zmapowany.

JSON przez HTTP

Zapytanie to ścieżka lub parametry dodawane do adresu (na przykład /api/temps?room=server); WatchZit dodaje from, to i step w sekundach Unix i odczytuje dowolną z tych odpowiedzi (czasy w sekundach lub milisekundach):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
