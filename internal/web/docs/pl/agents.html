Instalacja agentów

Agent WatchZit jest opcjonalny. Raportuje to, czego sieć nie widzi z zewnątrz: CPU, pamięć, dyski, interfejsy i usługi komputerów z Windows i Linuksem, co minutę, przez jedno połączenie wychodzące.

Kody rejestracji

W sekcji Agenci utwórz kod rejestracji: nazwę, liczbę dni ważności, liczbę komputerów, które mogą go użyć, oraz grupę, do której trafią nowe urządzenia. Kod jest wyświetlany tylko raz; zawiera adres serwera i odcisk certyfikatu agentów, więc agent ufa wyłącznie twojemu serwerowi.

Windows

Pobierz MSI ze strony Agenci i zainstaluj go; poprosi o kod. Na wielu komputerach instaluj go w trybie cichym (GPO, Intune, skrypt):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

Agent działa jako usługa WatchZitAgent.

Linux

Strona Agenci pokazuje polecenie, które pobiera agenta z portu agentów, sprawdza jego SHA-256 i instaluje go z kodem (usługa systemd watchzit-agent):

curl -fsSk https://<serwer>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Możesz też zainstalować pakiet deb lub rpm z wydania (amd64 i arm64, z GitHuba), a następnie zarejestrować i uruchomić agenta; aktualizacje przychodzą przez menedżer pakietów lub przez własne aktualizacje agenta:

sudo apt install ./watchzit-agent_<wersja>_amd64.deb      # lub: sudo dnf install ./watchzit-agent-<wersja>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

Co raportuje agent

  • Obciążenie CPU (a na Linuksie także średnie obciążenie), pamięć i swap, każdy dysk, każdy interfejs sieciowy z ruchem — same stają się sprawdzeniami z wykresami.
  • Inwentarz: system operacyjny, model CPU, pamięć, producent, model, numer seryjny, adresy, usługi.
  • Maszyny Hyper-V (Windows) i kontenery Docker (Linux), co pięć minut, z ich stanem, CPU, pamięcią i adresami; widać je na stronie urządzenia i w polach hiperwizorów na mapach.
  • Obserwowane usługi: wybierz je na stronie urządzenia w sekcji Obserwuj usługi; zatrzymanie usługi otwiera problem.
  • Obserwowane procesy: w sekcji Obserwuj procesy na stronie urządzenia wpisz nazwy programów (na przykład nginx, sqlservr.exe, java); każdy otrzymuje sprawdzenie z liczbą działających instancji, ich CPU i pamięcią, a brak działającej instancji otwiera problem.
  • Komunikaty o błędach systemu — zdarzenia krytyczne i błędy z logów Windows System i Aplikacja oraz komunikaty o priorytecie err i wyższym z dziennika systemd — trafiają z każdym raportem do Logi (rodzaj Agenci); wyzwalacz logów ze źródłem Agenci otwiera na ich podstawie problemy.

Jeśli istnieje urządzenie o tym samym adresie lub nazwie, agent się do niego dołącza; w przeciwnym razie tworzone jest nowe urządzenie.

Aktualizacje agentów

Agent starszy niż serwer otrzymuje przy połączeniu agenta w wersji serwera (najwyżej raz na godzinę): pobiera instalator z serwera przez własne szyfrowane, przypięte połączenie, sprawdza jego rozmiar i SHA-256 i go instaluje. Agenci Windows zainstalowani z MSI uruchamiają nowy MSI; agenci Linux (systemd) sprawdzają, czy nowy program się uruchamia, zastępują się nim i są restartowani przez systemd. Strona Agenci oznacza starszych agentów; administratorzy wyłączają tam automatyczne aktualizacje w sekcji Aktualizacje agentów i jednym kliknięciem aktualizują wszystkich agentów online. Agenci w wersji starszej niż 1.2 nie znają jeszcze aktualizacji i trzeba ich raz zaktualizować ręcznie.

Zdalne kolektory

Urządzenie w innej sieci — w oddziale, u klienta za NAT, w zamkniętym VLAN-ie zarządzania — często jest nieosiągalne z konsoli. Zainstaluj agenta na dowolnym komputerze w tej sieci (Linux lub Windows; wystarczy mała maszyna wirtualna lub komputer klasy Raspberry Pi) i kliknij Użyj jako zdalnego kolektora w sekcji Agent na stronie jego urządzenia. Następnie wybierz go w polu Monitorowane z na urządzeniach tej sieci (albo dla wielu naraz na liście urządzeń w Zmień zaznaczone). Kolektor otrzymuje ich sprawdzenia — ping, TCP, SNMP, strony i scenariusze WWW, certyfikaty, DNS, bazy danych, RouterOS, API JSON — wraz z potrzebnymi hasłami i ustawieniami SNMP, wykonuje je w ich interwałach i wysyła wyniki przez własne szyfrowane połączenie. Nie potrzebuje otwartego portu w lokalizacji i nie ma własnego interfejsu WWW; wszystko ustawia się w konsoli.

Gdy połączenie z konsolą jest przerwane, kolektor nadal wykonuje sprawdzenia; wyniki (do jednej doby, najnowsze 200 000) czekają na nim i docierają po przywróceniu połączenia, więc na wykresach nie ma luk. Sprawdzenia jego urządzeń pokazują w tym czasie nieznany zamiast nie działa (w lokalizacji może być wszystko w porządku), a sprawdzenie agenta kolektora otwiera problem. Zachowane wyniki nie przetrwają restartu kolektora: pobiera on wtedy swoje sprawdzenia z konsoli od nowa.

Kolektor zapasowy: zainstaluj agenta na drugim komputerze w lokalizacji, również zrób z niego kolektor i wybierz go jako Zapasowy obok Monitorowane z (albo dla wielu urządzeń na liście urządzeń w Zmień zaznaczone → Zapasowy kolektor). Gdy pierwszy jest offline, zapasowy wykonuje ich sprawdzenia; gdy pierwszy wróci, znów je przejmuje.

Wykrywanie i SNMP: w Urządzenia → Wykrywanie wybierz kolektor obok nowego zakresu: skanuje on tę sieć swojej lokalizacji, a urządzenia dodane z tego zakresu są z niego monitorowane. Wykrywanie SNMP na stronie urządzenia oraz odczyt informacji, interfejsów i VLAN-ów również przechodzą przez kolektor. Sprawdzenia hiperwizorów pozostają przy konsoli. Przestań zbierać oddaje urządzenia z powrotem konsoli.

Sieć

Agenci łączą się z portem agentów 8444. W Ustawienia → Sieć i dostęp ustaw publiczny adres dla agentów, gdy agenci docierają do serwera pod inną nazwą (na przykład przez zaporę), i ogranicz sieci, z których mogą się łączyć.

Usunięcie agenta na stronie urządzenia sprawia, że jego klucz staje się nieznany; aby znów używać agenta, zarejestruj komputer nowym kodem.
