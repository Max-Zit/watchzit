API REST

Les scripts et autres systèmes lisent les appareils, les contrôles, les graphiques et les problèmes, prennent en charge des problèmes et planifient des maintenances via une API JSON.

Jetons

Créez un jeton dans Mon compte → Jetons d'API : un nom et sa durée de validité en jours. Il n'est affiché qu'une fois. Un jeton agit en votre nom, avec votre rôle (le jeton d'un lecteur ne peut que lire) ; révoquez-le lorsqu'il n'est plus nécessaire. Les jetons refusés comptent comme des connexions échouées et bloquent l'adresse pendant un moment.

Envoyez-le dans un en-tête ; l'API n'accepte jamais le cookie de session de la console :

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Points d'accès

RequêteRéponse
GET /api/v1/statusversion, appareils par état, problèmes ouverts par gravité
GET /api/v1/devicesappareils ; filtres q, status, group
GET /api/v1/devices/{id}un appareil avec ses contrôles et les identifiants de leurs séries
GET /api/v1/series/{id}?range=24hles points d'une série : temps, minimum, moyenne, maximum
GET /api/v1/problemsproblèmes ouverts ; view=history, severity, device
POST /api/v1/problems/{id}/ackprendre en charge : {"note": "…"}
GET /api/v1/maintenancefenêtres de maintenance
POST /api/v1/maintenanceen planifier une : {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Les dates sont au format RFC 3339 (2026-11-01T22:00:00+01:00). Les erreurs prennent la forme {"error": "…"} avec un statut HTTP correspondant. Les modifications sont inscrites dans le journal d’audit avec le nom du jeton.
