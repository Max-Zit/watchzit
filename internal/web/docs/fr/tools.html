Ouvrir les appareils

Depuis la page d'un appareil ou le panneau latéral de la carte, vous ouvrez un appareil avec le bon programme : son interface web, SSH, le Bureau à distance, WinBox, VNC ou vos propres outils.

Le MaxZit Launcher

Un navigateur ne peut pas démarrer de programmes ; c'est donc un petit programme Windows qui s'en charge : le MaxZit Launcher. Installez-le une fois par ordinateur depuis la page Launcher — l'installateur (MSI), avec un court assistant d'installation, le place dans Applications avec son icône, d'où il peut aussi être désinstallé ; il s'installe pour votre utilisateur Windows, sans droits d'administrateur — puis cliquez sur Associer cet ordinateur. Le launcher affiche l'empreinte du serveur ; elle doit correspondre à celle de la page.

Les boutons Ouvrir avec fonctionnent alors. Lorsqu'une console change d'adresse (ou est restaurée ailleurs à partir d'une sauvegarde), cliquez de nouveau sur Associer cet ordinateur : le launcher la reconnaît grâce à sa clé et demande s'il doit utiliser la nouvelle adresse. La première fois, le navigateur demande s'il peut ouvrir le launcher ; autorisez-le.

Le même launcher sert aussi PassZit : dans le menu de l'extension PassZit, cliquez sur Associer au MaxZit Launcher et acceptez dans la fenêtre du launcher. PassZit ouvre alors le Bureau à distance, SSH, WinSCP, WinBox, VNC et Telnet avec l'identifiant du coffre — le Bureau à distance via une information d'identification Windows qui n'existe que quelques secondes, un mot de passe ou une clé SSH via un fichier que vous seul pouvez lire et qui est supprimé juste après le démarrage. Le launcher remplace l'ancien WatchZit Launcher et passzit-helper : son installation reprend leurs paramètres et leurs associations. Lorsque PassZit est associé et que l'adresse de la console fait partie de ses consoles MaxZit de confiance, les boutons Ouvrir avec de WatchZit ouvrent une session déjà connectée avec l'identifiant correspondant du coffre ; sans PassZit, ou sans identifiant pour cet appareil, ils s'ouvrent comme avant. La console ne transmet à PassZit que l'outil, l'adresse, le port, le nom d'utilisateur et le nom de l'appareil — jamais un mot de passe. À côté des boutons Ouvrir avec, un petit badge PassZit indique que PassZit est déverrouillé et se chargera de la connexion ; PassZit verrouillé signifie qu'il faut d'abord le déverrouiller. Si PassZit n'est pas configuré pour cette console, un petit message explique comment l'autoriser ; Ne plus afficher le masque dans ce navigateur.

Comment la sécurité est assurée

  • Chaque clic produit un lien signé par votre serveur, valable une minute et utilisable une seule fois ; le launcher n'accepte que les liens des serveurs que vous avez associés.
  • Les adresses et noms d'utilisateur sont vérifiés selon des jeux de caractères stricts ; les programmes démarrent avec une liste d'arguments, jamais via un shell.
  • Les mots de passe ne sont jamais enregistrés ni envoyés : c'est le programme qui les demande.
  • Avant la première exécution d'un programme ajouté par votre administrateur, le launcher vous demande confirmation.

Vos propres outils

Dans Paramètres → Outils, les administrateurs désactivent des outils intégrés, les limitent à certains types d'appareils et ajoutent les leurs : un chemin de programme (par exemple %ProgramFiles%\Mozilla Firefox\firefox.exe) et des arguments avec {host}, {port}, {user} et {name}. Le nom d'utilisateur et les ports de chaque appareil se règlent dans l'Accès à distance de l'appareil, où vous décochez aussi les outils dont un appareil ne dispose pas — un serveur Proxmox ou Linux n'a pas de Bureau à distance — ou cochez un outil que son type ne reçoit pas par défaut ; les boutons de la page de l'appareil et des cartes n'affichent alors que les outils cochés.

Liens sur chaque appareil

Toujours dans Paramètres → Outils, Liens sur chaque appareil ajoute à chaque page d'appareil des boutons qui ouvrent l'appareil dans un autre programme, dans le navigateur, par exemple RMMZit ou BackupZit. Indiquez un nom et une adresse ; {name}, {address} et {id} sont remplacés par le nom, l'adresse et le numéro de l'appareil, par ex. https://rmm.example.com:8443/devices?q={name}. Seules les adresses http:// et https:// sont acceptées.
