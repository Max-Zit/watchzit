Installer les agents

L'agent WatchZit est facultatif. Il remonte ce que le réseau ne peut pas voir de l'extérieur : CPU, mémoire, disques, interfaces et services des ordinateurs Windows et Linux, chaque minute, par une seule connexion sortante.

Codes d'inscription

Dans Agents, créez un code d'inscription : un nom, sa durée de validité en jours, le nombre d'ordinateurs qui peuvent l'utiliser et le groupe dans lequel arrivent les nouveaux appareils. Le code n'est affiché qu'une fois ; il contient l'adresse du serveur et l'empreinte du certificat des agents, de sorte que l'agent ne fait confiance qu'à votre serveur.

Windows

Téléchargez le MSI depuis la page Agents et installez-le ; il demande le code. Pour de nombreux ordinateurs, installez-le en mode silencieux (GPO, Intune, un script) :

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

L'agent s'exécute en tant que service WatchZitAgent.

Linux

La page Agents affiche une commande qui télécharge l'agent depuis le port des agents, vérifie son SHA-256 et l'installe avec le code (service systemd watchzit-agent) :

curl -fsSk https://<serveur>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Vous pouvez aussi installer le paquet deb ou rpm de la version (amd64 et arm64, depuis GitHub), puis inscrire l'agent et le démarrer ; les mises à jour arrivent par le gestionnaire de paquets ou par les mises à jour propres de l'agent :

sudo apt install ./watchzit-agent_<version>_amd64.deb      # ou : sudo dnf install ./watchzit-agent-<version>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

Ce que remonte l'agent

  • La charge du CPU (et la charge moyenne sous Linux), la mémoire et le swap, chaque disque, chaque interface réseau avec son trafic — ils deviennent d'eux-mêmes des contrôles avec graphiques.
  • Inventaire : système d'exploitation, modèle de CPU, mémoire, fabricant, modèle, numéro de série, adresses, services.
  • Les machines Hyper-V (Windows) et les conteneurs Docker (Linux), toutes les cinq minutes, avec leur état, leur CPU, leur mémoire et leurs adresses ; ils apparaissent sur la page de l'appareil et dans les cadres d'hyperviseur sur les cartes.
  • Services surveillés : choisissez-les sur la page de l'appareil dans Surveiller des services ; un service qui s'arrête ouvre un problème.
  • Processus surveillés : dans Surveiller des processus sur la page de l'appareil, saisissez des noms de programmes (par exemple nginx, sqlservr.exe, java) ; chacun reçoit un contrôle indiquant combien d'instances tournent, leur CPU et leur mémoire, et l'absence d'instance ouvre un problème.
  • Les messages d'erreur du système — événements critiques et d'erreur des journaux Windows System et Application, et messages de priorité err ou pire du journal systemd — arrivent dans Journaux (genre Agents) à chaque envoi ; un déclencheur de journal avec la source Agents en tire des problèmes.

S'il existe déjà un appareil ayant la même adresse ou le même nom, l'agent s'y rattache ; sinon, un nouvel appareil est créé.

Mises à jour des agents

Un agent plus ancien que le serveur reçoit, lorsqu'il se connecte (au plus une fois par heure), l'agent de la version du serveur : il télécharge l'installateur depuis le serveur par sa propre connexion chiffrée et épinglée, vérifie sa taille et son SHA-256, puis l'installe. Les agents Windows installés avec le MSI exécutent le nouveau MSI ; les agents Linux (systemd) vérifient que le nouveau programme démarre, se remplacent et sont redémarrés par systemd. La page Agents signale les agents plus anciens ; les administrateurs y désactivent les mises à jour automatiques dans Mises à jour des agents et mettent à jour tous les agents en ligne en un clic. Les agents antérieurs à la version 1.2 ne connaissent pas encore les mises à jour et doivent être mis à jour une fois à la main.

Collecteurs distants

Un appareil situé dans un autre réseau — une agence, un site client derrière un NAT, un VLAN d'administration fermé — n'est souvent pas joignable depuis la console. Installez l'agent sur n'importe quel ordinateur de ce réseau (Linux ou Windows ; une petite VM ou une machine de la classe d'un Raspberry Pi suffit) et cliquez sur Utiliser comme collecteur distant dans le cadre Agent de la page de son appareil. Choisissez-le ensuite dans Surveillé depuis sur les appareils de ce réseau (ou pour plusieurs à la fois dans la liste des appareils, via Modifier la sélection). Le collecteur reçoit leurs contrôles — ping, TCP, SNMP, pages et scénarios web, certificats, DNS, bases de données, RouterOS, API JSON — avec les mots de passe et paramètres SNMP nécessaires, les exécute à leurs intervalles et envoie les résultats par sa propre connexion chiffrée. Il n'a besoin d'aucun port ouvert sur le site et n'a pas d'interface web propre ; tout se règle dans la console.

Tant que la connexion à la console est coupée, le collecteur continue d'exécuter les contrôles ; les résultats (jusqu'à une journée, les 200 000 plus récents) attendent sur le collecteur et arrivent dès que la connexion revient, si bien que les graphiques n'ont pas de trou. Pendant ce temps, les contrôles de ses appareils affichent inconnu au lieu d'en panne (le site va peut-être très bien), et le contrôle d'agent du collecteur ouvre un problème. Les résultats en attente ne survivent pas à un redémarrage du collecteur : celui-ci récupère alors à nouveau ses contrôles auprès de la console.

Collecteur de secours : installez l'agent sur un deuxième ordinateur du site, faites-en aussi un collecteur et choisissez-le comme Secours à côté de Surveillé depuis (ou pour plusieurs appareils dans la liste des appareils, via Modifier la sélection → Collecteur de secours). Tant que le premier est hors ligne, le collecteur de secours exécute leurs contrôles ; quand le premier revient, il les reprend.

Découverte et SNMP : dans Appareils → Découverte, choisissez le collecteur à côté d'une nouvelle plage : il analyse ce réseau de son site, et les appareils que vous en ajoutez sont surveillés depuis lui. La découverte SNMP de la page de l'appareil et la lecture des informations, des interfaces et des VLAN passent aussi par le collecteur. Les contrôles d'hyperviseur restent sur la console. Arrêter la collecte rend les appareils à la console.

Réseau

Les agents se connectent au port des agents 8444. Dans Paramètres → Réseau et accès, définissez l'adresse publique des agents lorsque les agents atteignent le serveur sous un autre nom (par exemple à travers un pare-feu), et limitez les réseaux d'où les agents peuvent venir.

Supprimer l'agent sur la page de l'appareil rend sa clé inconnue ; pour réutiliser l'agent, inscrivez l'ordinateur avec un nouveau code.
