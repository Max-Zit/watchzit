Sources de données

Les graphiques et tableaux de bord peuvent aussi afficher des séries temporelles venant de l'extérieur de WatchZit : des tables de vos propres bases de données, Prometheus, InfluxDB ou toute adresse qui répond en JSON — à côté des valeurs des agents et des contrôles.

Ajouter une source de données

Les administrateurs ajoutent des sources de données dans Paramètres → Sources de données :

GenreAdresseConnexion
PostgreSQLhôte ou hôte:port (5432), et la base de donnéesutilisateur et mot de passe
MySQL / MariaDBhôte ou hôte:port (3306), et la base de donnéesutilisateur et mot de passe
Microsoft SQL Serverhôte ou hôte:port (1433), et la base de donnéesutilisateur SQL Server et mot de passe
Prometheusl'URL, par exemple http://prometheus:9090 ; également Thanos, VictoriaMetrics, Mimiraucune, utilisateur et mot de passe, ou un jeton bearer
InfluxDBl'URL, par exemple http://influx:8086, et la base de données (InfluxDB 2/3 : le bucket)InfluxDB 1 : utilisateur et mot de passe ; 2 et 3 : le jeton seul
JSON sur HTTPl'URL de base de votre serviceaucune, utilisateur et mot de passe, ou un jeton bearer

Tester la connexion essaie les paramètres sans les enregistrer. Le mot de passe ou le jeton est stocké chiffré et n'est plus jamais affiché ; laissez le champ vide pour le conserver.

Pour les bases de données SQL, choisissez le chiffrement : lorsque le serveur le propose (par défaut), toujours avec n'importe quel certificat, toujours avec un certificat de confiance, ou jamais. Pour les adresses en https://, un certificat auto-signé peut être accepté.

Donnez à la console un utilisateur en lecture seule sur les tables dont elle a besoin. WatchZit exécute les requêtes PostgreSQL et MySQL dans une transaction en lecture seule ; SQL Server n'offre rien de tel, seuls les droits de l'utilisateur y protègent donc les données. Les opérateurs écrivent les requêtes ; les lecteurs ne voient que les graphiques.

Requêtes dans les graphiques

Sur la page d'un appareil, cliquez sur Modifier les graphiques, puis sur ✎ sur un graphique ou sur Ajouter un graphique. Dans Sources de données, cliquez sur Ajouter une requête, choisissez la source de données et écrivez la requête. Essayer l'exécute sur la période de la page et indique les séries qu'elle renvoie (avec leur nombre de points) ou l'erreur de la base de données. Un graphique peut afficher jusqu'à 6 requêtes à côté des valeurs de l'appareil, chacune avec un nom de série, une unité et une couleur.

Sur les tableaux de bord, ajoutez le widget Graphique d'une source de données.

Les réponses sont conservées 20 secondes, si bien qu'un tableau de bord affiché sur plusieurs écrans n'interroge la base de données qu'une fois. Une requête renvoie au plus 200 000 lignes et 50 séries et peut durer 20 secondes ; les valeurs sont réduites à la largeur du graphique.

SQL (PostgreSQL, MySQL, SQL Server)

La requête renvoie une colonne de temps (nommée time, ou la première colonne contenant des horodatages ; les secondes ou millisecondes Unix fonctionnent aussi), une ou plusieurs colonnes numériques (une série chacune) et, éventuellement, une colonne de texte qui nomme la série (metric, ou la première colonne de texte) pour les tables à une ligne par série et par instant. Triez par temps.

Les macros insèrent la période du graphique dans la requête :

MacroDevient
$__timeFilter(col)col entre le début et la fin de la période
$__timeGroup(col)col arrondi à l'intervalle du graphique ; $__timeGroup(col, 300) à 5 minutes
$__timeFrom, $__timeTole début et la fin sous forme d'horodatage
$__unixFrom, $__unixTole début et la fin en secondes Unix
$__interval_sl'intervalle du graphique en secondes

Exemples :

-- commandes par intervalle (identique pour PostgreSQL, MySQL et SQL Server)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- une série par entrepôt
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Écrivez du PromQL, par exemple rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Chaque série est nommée comme Prometheus l'écrit (name{label="value"}) ; un nom de série saisi dans l'éditeur le remplace. Le pas suit la largeur du graphique.

InfluxDB

Écrivez de l'InfluxQL avec $timeFilter et $__interval :

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 et 3 répondent à l'InfluxQL via leur API 1.x : associez-y le bucket à une base de données s'il ne l'est pas encore.

JSON sur HTTP

La requête est un chemin ou des paramètres ajoutés à l'adresse (par exemple /api/temps?room=server) ; WatchZit ajoute from, to et step en secondes Unix et lit n'importe laquelle de ces réponses (horodatages en secondes ou en millisecondes) :

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
