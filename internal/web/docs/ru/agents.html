Установка агентов

Агент WatchZit необязателен. Он сообщает то, что сеть не видит снаружи: CPU, память, диски, интерфейсы и службы компьютеров Windows и Linux — каждую минуту, через одно исходящее соединение.

Коды регистрации

В разделе Агенты создайте код регистрации: имя, сколько дней он действует, сколько компьютеров могут им воспользоваться и в какую группу попадают новые устройства. Код показывается один раз; он содержит адрес сервера и отпечаток сертификата агентов, поэтому агент доверяет только вашему серверу.

Windows

Загрузите MSI со страницы «Агенты» и установите его; установщик запросит код. Для многих компьютеров устанавливайте его в тихом режиме (GPO, Intune, скрипт):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

Агент работает как служба WatchZitAgent.

Linux

Страница «Агенты» показывает команду, которая загружает агент с порта агентов, проверяет его SHA-256 и устанавливает с кодом (служба systemd watchzit-agent):

curl -fsSk https://<сервер>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Или установите пакет deb или rpm из выпуска (amd64 и arm64, с GitHub), затем зарегистрируйте и запустите агент; обновления приходят через менеджер пакетов или собственные обновления агента:

sudo apt install ./watchzit-agent_<версия>_amd64.deb      # или: sudo dnf install ./watchzit-agent-<версия>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

Что сообщает агент

  • Загрузку CPU (и среднюю нагрузку на Linux), память и swap, каждый диск, каждый сетевой интерфейс с трафиком — они сами становятся проверками с графиками.
  • Инвентаризацию: операционная система, модель CPU, память, производитель, модель, серийный номер, адреса, службы.
  • Машины Hyper-V (Windows) и контейнеры Docker (Linux) — каждые пять минут, с состоянием, CPU, памятью и адресами; они показываются на странице устройства и в блоках гипервизоров на картах.
  • Отслеживаемые службы: выберите их на странице устройства в разделе Отслеживать службы; остановка службы открывает проблему.
  • Отслеживаемые процессы: в разделе Следить за процессами на странице устройства введите имена программ (например, nginx, sqlservr.exe, java); каждая получает проверку с числом запущенных экземпляров, их CPU и памятью, а отсутствие запущенных открывает проблему.
  • Сообщения об ошибках системы — критические события и ошибки журналов Windows Система и Application, а также сообщения с приоритетом err и выше из журнала systemd — с каждым отчётом попадают в Журналы (вид Агенты); триггер по журналу с источником Агенты открывает по ним проблемы.

Если устройство с таким же адресом или именем уже существует, агент присоединяется к нему; иначе создаётся новое устройство.

Обновления агентов

Агент, который старше сервера, при подключении (не чаще раза в час) получает агент версии сервера: он загружает установщик с сервера через собственное зашифрованное соединение с закреплённым сертификатом, проверяет его размер и SHA-256 и устанавливает его. Агенты Windows, установленные через MSI, запускают новый MSI; агенты Linux (systemd) проверяют, что новая программа запускается, заменяют себя и перезапускаются systemd. Страница Агенты помечает устаревшие агенты; администраторы отключают там автоматические обновления в разделе Обновления агентов и обновляют все агенты в сети одним щелчком. Агенты версий до 1.2 ещё не умеют обновляться и обновляются один раз вручную.

Удалённые коллекторы

Устройство в другой сети — в филиале, на площадке клиента за NAT, в закрытом VLAN управления — часто недоступно с консоли. Установите агент на любой компьютер в той сети (Linux или Windows; достаточно небольшой ВМ или машины класса Raspberry Pi) и нажмите Использовать как удалённый коллектор в блоке «Агент» на странице его устройства. Затем выберите его в поле Мониторинг с у устройств этой сети (или для многих сразу в списке устройств в разделе Изменить выбранные). Коллектор получает их проверки — ping, TCP, SNMP, веб-страницы и сценарии, сертификаты, DNS, базы данных, RouterOS, JSON API — вместе с нужными паролями и настройками SNMP, выполняет их со своими интервалами и отправляет результаты через собственное зашифрованное соединение. Ему не нужен открытый порт на площадке, и у него нет своего веб-интерфейса; всё настраивается в консоли.

Пока связь с консолью прервана, коллектор продолжает выполнять проверки; результаты (до суток, не более 200 000 новейших) ждут на нём и поступают, когда связь восстанавливается, поэтому в графиках не остаётся пробелов. Тем временем проверки его устройств показывают Неизвестно вместо «не работает» (на площадке всё может быть в порядке), а проверка агента самого коллектора открывает проблему. Накопленные результаты не сохраняются при перезапуске коллектора: он снова получает свои проверки с консоли.

Резервный коллектор: установите агент на второй компьютер площадки, тоже сделайте его коллектором и выберите его как Резервный рядом с Мониторинг с (или для многих устройств в списке устройств в разделе Изменить выбранные → Резервный коллектор). Пока первый не в сети, их проверки выполняет резервный; когда первый возвращается, он снова берёт их на себя.

Обнаружение и SNMP: в разделе Устройства → Обнаружение выберите коллектор рядом с новым диапазоном: он сканирует эту сеть своей площадки, а добавленные из неё устройства отслеживаются через него. Обнаружение SNMP на странице устройства и считывание сведений, интерфейсов и VLAN тоже идут через коллектор. Проверки гипервизоров остаются за консолью. Прекратить сбор возвращает устройства консоли.

Сеть

Агенты подключаются к порту агентов 8444. В разделе Настройки → Сеть и доступ задайте Публичный адрес для агентов, если агенты обращаются к серверу по другому имени (например, через межсетевой экран), и ограничьте сети, из которых могут подключаться агенты.

Удаление агента на странице устройства делает его ключ неизвестным; чтобы снова использовать агент, зарегистрируйте компьютер с новым кодом.
