REST API

Скрипты и другие системы через JSON API читают устройства, проверки, графики и проблемы, подтверждают проблемы и планируют обслуживание.

Токены

Создайте токен в разделе Моя учётная запись → API-токены: имя и сколько дней он действует. Он показывается один раз. Токен действует от вашего имени и с вашей ролью (токен наблюдателя может только читать); отзовите его, когда он больше не нужен. Неверные токены считаются как неудачные попытки входа и на время блокируют адрес.

Передавайте токен в заголовке; API никогда не принимает сеансовый cookie консоли:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Конечные точки

ЗапросОтвет
GET /api/v1/statusверсия, устройства по состоянию, открытые проблемы по уровню
GET /api/v1/devicesустройства; фильтры q, status, group
GET /api/v1/devices/{id}устройство с его проверками и ID их рядов
GET /api/v1/series/{id}?range=24hточки ряда: время, минимум, среднее, максимум
GET /api/v1/problemsоткрытые проблемы; view=history, severity, device
POST /api/v1/problems/{id}/ackподтверждение: {"note": "…"}
GET /api/v1/maintenanceокна обслуживания
POST /api/v1/maintenanceпланирование окна: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Время указывается в формате RFC 3339 (2026-11-01T22:00:00+01:00). Ошибки возвращаются как {"error": "…"} с соответствующим статусом HTTP. Изменения записываются в журнал аудита с именем токена.
