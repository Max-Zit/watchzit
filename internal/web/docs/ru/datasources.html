Источники данных

Графики и дашборды могут показывать и временные ряды извне WatchZit: таблицы ваших собственных баз данных, Prometheus, InfluxDB или любой адрес, отвечающий в формате JSON, — рядом со значениями агентов и проверок.

Добавление источника данных

Администраторы добавляют источники данных в разделе Настройки → Источники данных:

Проверить подключение пробует настройки без сохранения. Пароль или токен хранится в зашифрованном виде и больше никогда не показывается; оставьте поле пустым, чтобы сохранить прежнее значение.

Для баз данных SQL выберите шифрование: если сервер его предлагает (по умолчанию), всегда с любым сертификатом, всегда с доверенным сертификатом или никогда. Для адресов с https:// можно принять самоподписанный сертификат.

Дайте консоли пользователя, которому разрешено только чтение нужных ей таблиц. WatchZit выполняет запросы PostgreSQL и MySQL в транзакции только для чтения; в SQL Server такого механизма нет, поэтому там данные защищают только права пользователя. Запросы пишут операторы; наблюдатели только видят графики.

Запросы на графиках

На странице устройства нажмите Изменить графики, затем ✎ на графике или Добавить график. В разделе Источники данных нажмите Добавить запрос, выберите источник данных и напишите запрос. Попробовать выполняет его за период страницы и сообщает, какие ряды он возвращает (с числом точек), или ошибку базы данных. График может показывать до 6 запросов рядом со значениями устройства, каждый со своим именем ряда, единицей измерения и цветом.

На дашбордах добавьте виджет График из источника данных.

Ответы хранятся 20 секунд, поэтому дашборд на нескольких экранах обращается к базе данных один раз. Запрос возвращает не более 200 000 строк и 50 рядов и может выполняться до 20 секунд; значения прореживаются до ширины графика.

SQL (PostgreSQL, MySQL, SQL Server)

Запрос возвращает столбец времени (с именем time или первый столбец, содержащий время; подходят и секунды или миллисекунды Unix), один или несколько числовых столбцов (по ряду на каждый) и, при необходимости, текстовый столбец с именем ряда (metric или первый текстовый столбец) для таблиц с одной строкой на ряд и момент времени. Сортируйте по времени.

Макросы подставляют в запрос период графика:

МакросПревращается в
$__timeFilter(col)col между началом и концом периода
$__timeGroup(col)col, округлённый вниз до интервала графика; $__timeGroup(col, 300) — до 5 минут
$__timeFrom, $__timeToначало и конец как время
$__unixFrom, $__unixToначало и конец в секундах Unix
$__interval_sинтервал графика в секундах

Примеры:

-- заказы за интервал (одинаково для PostgreSQL, MySQL, SQL Server)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- по одному ряду на склад
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Пишите на PromQL, например rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Каждый ряд называется так, как его записывает Prometheus (name{label="value"}); имя ряда в редакторе заменяет это название. Шаг зависит от ширины графика.

InfluxDB

Пишите на InfluxQL с $timeFilter и $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 и 3 отвечают на InfluxQL через свой API 1.x: сопоставьте там bucket с базой данных, если это ещё не сделано.

JSON через HTTP

Запрос — это путь или параметры, добавляемые к адресу (например, /api/temps?room=server); WatchZit добавляет from, to и step в секундах Unix и понимает любой из этих ответов (время в секундах или миллисекундах):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
