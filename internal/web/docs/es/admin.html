Usuarios, configuración y actualizaciones

Quién puede hacer qué, cómo se protege la consola y cómo se mantiene WatchZit al día.

Cada usuario inicia sesión con una contraseña y el inicio de sesión en dos pasos (una aplicación de autenticación); los códigos de recuperación ayudan cuando se pierde el teléfono. Los administradores añaden usuarios en Usuarios y restablecen contraseñas y el inicio de sesión en dos pasos. El Registro de auditoría registra cada cambio; sus entradas están encadenadas, de modo que cualquier modificación del registro se nota.

Active Directory / LDAP e inicio de sesión único

Además de las cuentas locales, los usuarios pueden iniciar sesión con una cuenta del directorio. Las cuentas locales siempre siguen funcionando, así que un administrador puede iniciar sesión aunque el directorio o el proveedor de identidad estén caídos. Un nombre de usuario que pertenece a una cuenta local nunca lo asume un inicio de sesión del directorio.

  • Active Directory / LDAP (Configuración → Active Directory / LDAP): el servidor (ldaps://dc1.example.local, o ldap:// con StartTLS; las contraseñas nunca cruzan la red sin cifrar), opcionalmente el certificado de una CA de empresa, una cuenta de servicio que pueda leer usuarios y grupos, el DN base y el filtro de usuarios (Active Directory (&(objectClass=user)(sAMAccountName={username}))). En Active Directory se siguen los grupos anidados. El directorio comprueba la contraseña; WatchZit sigue pidiendo su propio segundo factor. Prueba comprueba una cuenta sin iniciar sesión y muestra los grupos y el rol que obtendría.
  • Inicio de sesión único (Configuración → Inicio de sesión único): OpenID Connect (Microsoft Entra ID, Google, Okta, Keycloak …: el emisor, el ID de cliente y el secreto; registre https://<consola>/login/sso/callback como URI de redirección) o SAML 2.0 (ADFS, Entra ID, Okta …: la URL o el XML de metadatos del proveedor de identidad; facilítele https://<consola>/login/sso/metadata; la dirección de respuesta es /login/sso/saml). La página de inicio de sesión recibe un botón. El segundo factor propio de WatchZit solo se pide también si lo marca; si no, decide la política del proveedor de identidad.
  • Grupos y roles: en cada inicio de sesión, los grupos deciden el rol (administradores, operadores u observadores; gana el más alto), y los usuarios que no están en ninguno de los grupos reciben el rol predeterminado o no pueden iniciar sesión. Un grupo es su nombre o su DN completo, o el nombre o el ID que envía el proveedor de identidad (Entra ID envía ID).
  • Las cuentas del directorio se crean en su primer inicio de sesión y muestran LDAP o SSO en la lista de usuarios. No tienen contraseña de WatchZit; desactívelas en WatchZit para mantenerlas fuera aunque el directorio las deje pasar.

Configuración

  • Red y acceso: los puertos de la consola y de los agentes, las redes que pueden llegar a cada uno, la dirección pública para agentes.
  • Inicio de sesión y seguridad: duración de la sesión, cuántos inicios de sesión fallidos bloquean una dirección y el levantamiento de un bloqueo.
  • Datos de medición: cuánto tiempo se conservan los valores en bruto, de 5 minutos y por hora, y cuánto espacio ocupan.
  • Certificado: el certificado propio de la consola, uno que usted suba o uno de Let's Encrypt (véase más abajo).
  • Campos personalizados: sus propios campos para los dispositivos (consulte Dispositivos).
  • Diagnóstico: dónde están los registros, las líneas más recientes del registro del servidor con un filtro y un ZIP para el soporte (registros, dispositivos, agentes, problemas, registro de auditoría) sin contraseñas, comunidades, tokens, códigos de inscripción ni claves; las configuraciones de dispositivos guardadas no se incluyen.
  • SNMP, Notificaciones, Herramientas, Pantallas quiosco: consulte sus capítulos.

Actualizaciones

Configuración → Actualizaciones y servidor muestra la versión en ejecución y la más reciente publicada. Si se instaló con los paquetes de Linux, WatchZit se actualiza solo:

  1. Solo se aceptan versiones firmadas con la clave de publicación de WatchZit.
  2. El asistente con permisos de root hace una copia de la base de datos y del programa, instala el paquete nuevo y comprueba que la consola arranca.
  3. Si no arranca, vuelve por sí solo a la versión anterior.

El Canal de actualización elige qué instala la consola: Versiones oficiales, o pruebas (versiones candidatas que llegan antes de una versión oficial, para una consola de prueba). Mantenga las consolas de producción en las versiones oficiales.

Las actualizaciones se pueden instalar con un clic o automáticamente a una hora elegida. Un espejo o una carpeta local pueden servir de origen (WATCHZIT_UPDATE_SOURCE en /etc/watchzit/server.env). La misma página define la zona horaria del servidor y reinicia el servicio.

Sin acceso a internet: en Instalar desde archivos suba manifest.json, manifest.json.sig y el paquete del servidor (.deb o .rpm) de una versión, descargados en otro equipo. Se comprueban como una descarga y se instalan de la misma manera.

Sistema operativo y SSH

La misma página muestra las Actualizaciones del sistema operativo del servidor (Debian, Ubuntu, AlmaLinux, Rocky Linux): cuántas están pendientes y cuántas son de seguridad, si las actualizaciones de seguridad automáticas están activadas y cuándo se ejecutaron por última vez. Instalar todas las actualizaciones las instala ahora; si necesitan un reinicio, la página lo indica y Reiniciar el servidor lo reinicia. La lista se actualiza sola dos veces al día, o con Comprobar ahora.

En el appliance de WatchZit, la página también define su red (DHCP o una dirección fija, puerta de enlace, DNS, nombre; los ajustes que dejan el appliance incomunicado se deshacen a los 30 segundos) y SSH: activado o desactivado y su puerto; un puerto que el servidor SSH rechace mantiene el ajuste anterior. En otros servidores, esto corresponde al sistema operativo.

Certificado

De fábrica, la consola usa su propio certificado, del que avisan los navegadores. En Configuración → Certificado:

  • Subir un certificado de su empresa: el certificado con su cadena y la clave privada en PEM (archivos o texto pegado), para el nombre DNS (o la dirección IP) que usan los navegadores. Se comprueba antes de usarlo.
  • Let's Encrypt: introduzca el nombre y una dirección de correo. Let's Encrypt comprueba el nombre a través del puerto 80 de este servidor (accesible desde internet) o, si la consola es interna, con un registro DNS a través de Cloudflare (un token de API con el permiso Zone → DNS → Edit). El certificado se renueva solo 30 días antes de caducar.
  • Servir el puerto 80 también redirige a la consola a los navegadores que escriben http://.

El certificado de confianza se sirve cuando la consola se abre por su nombre; si se abre por su dirección IP, la consola sigue usando su propio certificado. Los agentes no se ven afectados: usan el certificado propio del puerto de agentes, que anclaron en la inscripción. Para usar el puerto estándar, defina el puerto de la consola en 443 en Red y acceso.

Copia de la consola

Configuración → Copia de la consola hace una copia de seguridad de toda la consola: la base de datos con todas las mediciones, la clave secreta de las contraseñas guardadas, la clave del launcher y los certificados en los que confían los agentes; todo lo que un servidor nuevo necesita para tomar el relevo. Las copias se escriben en backups dentro del directorio de datos cada día a la hora elegida (y con Copiar ahora); se conservan las más recientes (7 de forma predeterminada).

  • Cifrado: con una frase de contraseña (al menos 12 caracteres), el archivo se cifra (AES-256-GCM). Guarde la frase de contraseña en otro lugar: sin ella, una copia no se puede restaurar.
  • Copia SFTP: cada copia también se copia a una carpeta de otro servidor (contraseña o clave privada). La primera vez, Probar la carpeta SFTP muestra la clave de host del servidor para que confíe en ella; las copias solo van a un servidor con esa clave. La carpeta conserva tantas copias como el servidor.
  • Correo cuando falla una copia envía un aviso a través del servidor SMTP de Configuración → Notificaciones.
  • La Restauración se ejecuta con el servidor detenido: en el appliance, con la opción Restaurar una copia de la consola del menú de configuración; con los paquetes de Linux, systemctl stop watchzit-server, después watchzit-server --data-dir /var/lib/watchzit --restore FILE como el usuario watchzit con /etc/watchzit/server.env cargado (una copia cifrada lee su frase de contraseña de WATCHZIT_BACKUP_PASSPHRASE o de --restore-passphrase-file), y luego inicie el servidor. La restauración lo sustituye todo en una sola transacción; una copia de una versión anterior se pone al día cuando arranca el servidor. Los agentes siguen funcionando: confían en el mismo certificado.

Seguridad

  • La consola usa solo HTTPS, una Content Security Policy estricta y protección contra peticiones entre sitios; solo responde a las redes permitidas.
  • Las contraseñas se guardan con hash Argon2id; los secretos guardados (contraseñas de SNMP, bases de datos y API, canales) se cifran con la clave secreta del servidor.
  • Los agentes se identifican con su propia clave; confían en el servidor por la huella anclada de su certificado de agentes.
  • Comunique las vulnerabilidades de forma privada: consulte SECURITY.md en el repositorio.
