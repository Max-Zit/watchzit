API REST

Los scripts y otros sistemas leen dispositivos, comprobaciones, gráficos y problemas, reconocen problemas y planifican mantenimientos a través de una API JSON.

Tokens

Cree un token en Mi cuenta → Tokens de API: un nombre y cuántos días es válido. Se muestra una sola vez. Un token actúa en su nombre, con su rol (el token de un observador solo puede leer); revóquelo cuando ya no lo necesite. Los tokens fallidos cuentan como inicios de sesión fallidos y bloquean la dirección durante un tiempo.

Envíelo en una cabecera; la API nunca acepta la cookie de sesión de la consola:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Endpoints

PeticiónRespuesta
GET /api/v1/statusversión, dispositivos por estado, problemas abiertos por gravedad
GET /api/v1/devicesdispositivos; filtros q, status, group
GET /api/v1/devices/{id}un dispositivo con sus comprobaciones y los id de sus series
GET /api/v1/series/{id}?range=24hlos puntos de una serie: hora, mínimo, media, máximo
GET /api/v1/problemsproblemas abiertos; view=history, severity, device
POST /api/v1/problems/{id}/ackreconocer: {"note": "…"}
GET /api/v1/maintenanceventanas de mantenimiento
POST /api/v1/maintenanceplanificar una: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Las horas siguen RFC 3339 (2026-11-01T22:00:00+01:00). Los errores son {"error": "…"} con el código de estado HTTP correspondiente. Los cambios se escriben en el registro de auditoría con el nombre del token.
