Orígenes de datos

Los gráficos y los paneles también pueden mostrar series temporales de fuera de WatchZit: tablas de sus propias bases de datos, Prometheus, InfluxDB o cualquier dirección que responda con JSON, junto a los valores de los agentes y las comprobaciones.

Añadir un origen de datos

Los administradores añaden orígenes de datos en Configuración → Orígenes de datos:

ClaseDirecciónInicio de sesión
PostgreSQLhost o host:puerto (5432), y la base de datosusuario y contraseña
MySQL / MariaDBhost o host:puerto (3306), y la base de datosusuario y contraseña
Microsoft SQL Serverhost o host:puerto (1433), y la base de datosusuario y contraseña de SQL Server
Prometheusla URL, por ejemplo http://prometheus:9090; también Thanos, VictoriaMetrics, Mimirninguno, usuario y contraseña, o un token bearer
InfluxDBla URL, por ejemplo http://influx:8086, y la base de datos (InfluxDB 2/3: el bucket)InfluxDB 1: usuario y contraseña; 2 y 3: solo el token
JSON por HTTPla URL base de su servicioninguno, usuario y contraseña, o un token bearer

Probar conexión prueba los ajustes sin guardarlos. La contraseña o el token se guardan cifrados y nunca se vuelven a mostrar; deje el campo vacío para conservarlos.

Para las bases de datos SQL, elija el cifrado: cuando el servidor lo ofrezca (predeterminado), siempre con cualquier certificado, siempre con un certificado de confianza, o nunca. Para las direcciones con https:// se puede aceptar un certificado autofirmado.

Dé a la consola un usuario que solo pueda leer las tablas que necesita. WatchZit ejecuta las consultas de PostgreSQL y MySQL en una transacción de solo lectura; SQL Server no tiene nada parecido, así que allí solo los permisos del usuario protegen los datos. Los operadores escriben las consultas; los observadores solo ven los gráficos.

Consultas en los gráficos

En la página de un dispositivo, haga clic en Editar gráficos y después en ✎ en un gráfico o en Añadir gráfico. En Orígenes de datos haga clic en Añadir consulta, elija el origen de datos y escriba la consulta. Probar la ejecuta sobre el periodo de la página e indica las series que devuelve (con su número de puntos) o el error de la base de datos. Un gráfico puede mostrar hasta 6 consultas junto a los valores del dispositivo, cada una con un nombre de serie, una unidad y un color.

En los paneles, añada el widget Gráfico de un origen de datos.

Las respuestas se conservan 20 segundos, de modo que un panel en varias pantallas consulta la base de datos una sola vez. Una consulta trae como máximo 200.000 filas y 50 series y puede tardar 20 segundos; los valores se reducen al ancho del gráfico.

SQL (PostgreSQL, MySQL, SQL Server)

La consulta devuelve una columna de tiempo (llamada time, o la primera columna que contenga horas; también sirven segundos o milisegundos Unix), una o varias columnas numéricas (una serie cada una) y, opcionalmente, una columna de texto que nombra la serie (metric, o la primera columna de texto) para tablas con una fila por serie y hora. Ordene por tiempo.

Las macros insertan el periodo del gráfico en la consulta:

MacroSe convierte en
$__timeFilter(col)col entre el inicio y el final del periodo
$__timeGroup(col)col redondeado hacia abajo al intervalo del gráfico; $__timeGroup(col, 300) a 5 minutos
$__timeFrom, $__timeToel inicio y el final como hora
$__unixFrom, $__unixToel inicio y el final en segundos Unix
$__interval_sel intervalo del gráfico en segundos

Ejemplos:

-- orders per interval (PostgreSQL, MySQL, SQL Server alike)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- one series per warehouse
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Escriba PromQL, por ejemplo rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Cada serie recibe el nombre tal como lo escribe Prometheus (name{label="value"}); un nombre de serie en el editor lo sustituye. El paso se ajusta al ancho del gráfico.

InfluxDB

Escriba InfluxQL con $timeFilter y $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 y 3 responden a InfluxQL a través de su API 1.x: asigne allí el bucket a una base de datos si aún no lo está.

JSON por HTTP

La consulta es una ruta o unos parámetros que se añaden a la dirección (por ejemplo /api/temps?room=server); WatchZit añade from, to y step en segundos Unix y lee cualquiera de estas respuestas (horas en segundos o milisegundos):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
