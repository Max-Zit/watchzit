Troubleshooting and FAQ

Ping says "ICMP is not allowed"

The server needs the right to send ICMP. The packaged service has it (CAP_NET_RAW). Elsewhere, give it with setcap cap_net_raw+ep /usr/bin/watchzit-server or allow unprivileged ping: sysctl net.ipv4.ping_group_range="0 2147483647".

SNMP shows "no answer"

  • Check the community or the SNMPv3 user, protocols and passwords in the profile.
  • Allow the WatchZit server's address on the device (many devices answer only listed managers) and UDP 161 on firewalls.
  • The message says it when a v3 user is unknown or the password is wrong.

An agent does not connect

  • The computer must reach the agent port 8444 of the server; check Settings → Network and access (allowed networks, public agent address).
  • Windows: Get-Service WatchZitAgent and the log in C:\ProgramData\WatchZit Agent. Linux: journalctl -u watchzit-agent.
  • "the server does not know this agent": the device was removed; enroll it again with a new code.

Notifications do not arrive

  • Send a test from Settings → Notifications; the channel list shows the last error.
  • Problems in maintenance or behind a down device are not sent; check the channel's lowest severity.

I locked myself out

After too many failed sign-ins the address is blocked for a while. On the server: watchzit-server --unblock-ip all. If the allowed networks exclude you: watchzit-server --reset-allowlist.

Where are the logs?

journalctl -u watchzit-server and /var/lib/watchzit/logs/server.log; the update helper writes /var/log/watchzit-helper/helper.log.

FAQ

Do devices need an agent? No. Ping, ports, SNMP, web, DNS, database and API checks run from the server; the agent adds what only the computer itself knows.

How many devices? One server polls thousands of checks per minute; measurements are compressed, so a year of data stays small.

Is it free? Yes, under the AGPL-3.0. MaxZit offers paid support.
