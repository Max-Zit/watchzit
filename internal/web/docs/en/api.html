REST API

Scripts and other systems read devices, checks, graphs and problems, acknowledge problems and plan maintenance over a JSON API.

Tokens

Create a token under My account → API tokens: a name and how many days it is valid. It is shown once. A token acts as you, with your role (a viewer's token can only read); revoke it when it is no longer needed. Failed tokens count like failed sign-ins and block the address for a while.

Send it in a header; the API never accepts the console's session cookie:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Endpoints

RequestAnswer
GET /api/v1/statusversion, devices by state, open problems by severity
GET /api/v1/devicesdevices; filters q, status, group
GET /api/v1/devices/{id}a device with its checks and the ids of their series
GET /api/v1/series/{id}?range=24hthe points of a series: time, minimum, average, maximum
GET /api/v1/problemsopen problems; view=history, severity, device
POST /api/v1/problems/{id}/ackacknowledge: {"note": "…"}
GET /api/v1/maintenancemaintenance windows
POST /api/v1/maintenanceplan one: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Times are RFC 3339 (2026-11-01T22:00:00+01:00). Errors are {"error": "…"} with a matching HTTP status. Changes are written to the audit log with the token's name.
