Users, settings and updates

Who may do what, how the console is protected, and how WatchZit stays up to date.

Users and roles

RoleMay
Administratoreverything, including users and settings
Operatormanage devices, checks, maps, triggers, maintenance, dashboards
Viewerlook only

Every user signs in with a password and two-factor sign-in (an authenticator app); recovery codes help when the phone is lost. Administrators add users under Users, reset passwords and two-factor sign-in. Audit log records every change; its entries are chained so changes to the log show.

Settings

  • Network and access — the console and agent ports, the networks allowed to reach each, the public agent address.
  • Sign-in and security — session length, how many failed sign-ins block an address, and lifting a block.
  • Metric data — how long raw values, 5-minute and hourly values are kept, and how much space they take.
  • Certificate — the console's own certificate, one you upload, or one from Let's Encrypt (see below).
  • SNMP, Notifications, Tools, Kiosk displays — see their chapters.

Updates

Settings → Updates and server shows the running version and the newest release. Installed with the Linux packages, WatchZit updates itself:

  1. Only releases signed with the WatchZit release key are accepted.
  2. The root helper backs up the database and the program, installs the new package and checks that the console starts.
  3. If it does not, it goes back to the old version by itself.

Updates can be installed by a click or automatically in a chosen hour. A mirror or a local folder can be the source (WATCHZIT_UPDATE_SOURCE in /etc/watchzit/server.env). The same page sets the server's time zone and restarts the service.

Without internet access: under Install from files upload manifest.json, manifest.json.sig and the server package (.deb or .rpm) of a release, downloaded on another computer. They are checked like a download and installed the same way.

Operating system and SSH

The same page shows the operating system updates of the server (Debian, Ubuntu, AlmaLinux, Rocky Linux): how many wait and how many are security updates, whether automatic security updates are on and when they last ran. Install all updates installs them now; when they need a restart, the page says so and Restart the server restarts it. The list is refreshed by itself twice a day, or with Check now.

On the WatchZit appliance the page also sets its network (DHCP or a fixed address, gateway, DNS, name — settings that cut the appliance off are undone after 30 seconds) and SSH: on or off and its port; a port the SSH server refuses leaves the old setting. On other servers these belong to the operating system.

Certificate

Out of the box the console uses its own certificate, which browsers warn about. Under Settings → Certificate:

  • Upload a certificate of your company: the certificate with its chain and the private key in PEM (files or pasted), for the DNS name — or the IP address — browsers use. It is checked before it is used.
  • Let's Encrypt: enter the name and an email address. Let's Encrypt checks the name over port 80 of this server (reachable from the internet) or, when the console is internal, with a DNS record through Cloudflare (an API token with the permission Zone → DNS → Edit). The certificate is renewed by itself 30 days before it expires.
  • Serve port 80 also sends browsers that type http:// to the console.

The trusted certificate is served when the console is opened under its name; opened by its IP address, the console keeps using its own certificate. Agents are not affected: they use the agent port's own certificate, which they pinned at enrollment. To use the standard port, set the console port to 443 under Network and access.

Security

  • The console uses HTTPS only, a strict Content Security Policy and protection against cross-site requests; it answers only the allowed networks.
  • Passwords are hashed with Argon2id; stored secrets (SNMP, database and API passwords, channels) are encrypted with the server's secret key.
  • Agents are identified by their own key; they trust the server by the pinned fingerprint of its agent certificate.
  • Report vulnerabilities privately: see SECURITY.md in the repository.
