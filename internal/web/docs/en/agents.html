Installing agents

The WatchZit agent is optional. It reports what the network cannot see from outside: CPU, memory, disks, interfaces and services of Windows and Linux computers, every minute, over one outbound connection.

Enrollment codes

Under Agents create an enrollment code: a name, how many days it is valid, how many computers may use it and the group new devices go to. The code is shown once; it contains the server address and the fingerprint of the agent certificate, so the agent trusts only your server.

Windows

Download the MSI from the Agents page and install it; it asks for the code. For many computers install it silently (GPO, Intune, a script):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

The agent runs as the service WatchZitAgent.

Linux

The Agents page shows a command that downloads the agent from the agent port, checks its SHA-256 and installs it with the code (systemd service watchzit-agent):

curl -fsSk https://<server>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Or install the deb or rpm package of the release (amd64 and arm64, from GitHub), then enroll and start it; updates come through the package manager or the agent's own updates:

sudo apt install ./watchzit-agent_<version>_amd64.deb      # or: sudo dnf install ./watchzit-agent-<version>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

What the agent reports

  • CPU load (and load average on Linux), memory and swap, every disk, every network interface with traffic — they become checks with graphs by themselves.
  • Inventory: operating system, CPU model, memory, vendor, model, serial number, addresses, services.
  • Hyper-V machines (Windows) and Docker containers (Linux), every five minutes, with their state, CPU, memory and addresses; they show on the device page and in hypervisor boxes on maps.
  • Watched services: choose them on the device page under Watch services; a service that stops opens a problem.
  • Watched processes: under Watch processes on the device page enter program names (for example nginx, sqlservr.exe, java); each gets a check with how many run, their CPU and memory, and none running opens a problem.
  • Error messages of the system — critical and error events of the Windows System and Application logs, and messages of priority err and worse from the systemd journal — go to Logs (kind Agents) with every report; a log trigger with the source Agents opens problems from them.

If a device with the same address or name exists, the agent joins it; otherwise a new device is created.

Agent updates

An agent older than the server gets the agent of the server's version when it connects (at most once an hour): it downloads the installer from the server over its own encrypted, pinned connection, checks its size and SHA-256 and installs it. Windows agents installed with the MSI run the new MSI; Linux agents (systemd) check that the new program starts, replace themselves and are restarted by systemd. The Agents page marks older agents; administrators switch the automatic updates off there under Agent updates and update all online agents with one click. Agents before 1.2 do not know updates yet and are updated once by hand.

Remote collectors

A device in another network — a branch office, a customer site behind NAT, a closed management VLAN — often cannot be reached from the console. Install the agent on any computer there (Linux or Windows; a small VM or a Raspberry Pi-class machine is enough) and click Use as a remote collector in the Agent box of its device page. Then choose it under Monitored from on the devices of that network (or for many at once in the device list under Change selected). The collector receives their checks — ping, TCP, SNMP, web pages and scenarios, certificates, DNS, databases, RouterOS, JSON APIs — with the passwords and SNMP settings they need, runs them on their intervals and sends the results over its own encrypted connection. It needs no open port at the site and has no web interface of its own; everything is set in the console.

If the collector goes offline, its devices' checks show unknown instead of down (the site may be fine), and the agent check of the collector opens a problem. Hypervisor checks, SNMP interface discovery and the topology of those devices still come from the console. Stop collecting gives the devices back to the console.

Network

Agents connect to the agent port 8444. Under Settings → Network and access set the public agent address when agents reach the server by another name (for example through a firewall), and limit the networks agents may come from.

Removing the agent on the device page makes its key unknown; to use the agent again, enroll the computer with a new code.
