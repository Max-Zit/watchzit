Devices, checks and SNMP

A device is anything with an address: a router, switch, server, printer, camera or a web site. Checks measure it; their results colour the device, the map and the graphs.

Adding a device

Under Devices → Add a device enter a name and an IP address or host name, choose its type and group, and leave Ping on. Optional:

  • SNMP — a profile with the community or the SNMPv3 user; WatchZit then reads the interfaces, traffic, CPU, memory and disks.
  • Depends on — the router or switch the device is reached through. While it is down, this device's problems are only "unreachable" and are not sent.
  • Remote access — the user name and ports that tools use.
  • TCP ports — each becomes a check that connects every minute.

The device's state comes from its checks: up when all are up, partly down when some are down, down when all are.

Discovery

Devices → Discovery finds the hosts of a network: add a range (e.g. 192.168.1.0/24, up to /22, or one address) and scan it now, every day or every week. WatchZit pings every address, tries common ports (SSH, Telnet, web, RDP, WinBox, SMB, printers, VNC), asks SNMP with your SNMP profiles for the name, description and maker, and looks up the DNS name. Hosts that are not devices yet are listed with their name, a guessed kind and what answered; tick them and click Add as devices (optionally into a group): each gets a ping check (or a TCP check when ping is blocked) and the SNMP profile that answered. Hide keeps a host out of the list; hidden hosts can be shown again. With a schedule, new hosts that appear in the network show up here by themselves.

Web links

Under Web links on a device, the Web interface address opens with the button on the device page and on maps; give the button another name if you like. Add more links for a server with several addresses, its iDRAC or iLO, or the page of a service; each becomes a button of its own.

Passwords and tokens of checks are stored encrypted and never shown again; leave the field empty when you edit a check to keep the stored one.

SNMP

  1. Create a profile under Settings → SNMP: v2c with a community, or v3 with a user (SHA-2 and AES are supported).
  2. Choose the profile on the device. WatchZit opens SNMP discovery: tick the interfaces, CPU, memory and disks to watch (loopbacks and interfaces without link are left out).
  3. The device page then shows ports with link state and live traffic, and graphs of every value.

MikroTik, Cisco, HP, Ubiquiti, printers and UPS devices speak SNMP. On Linux install snmpd; on Windows the SNMP service.

VLANs

WatchZit reads the VLANs of switches over SNMP once an hour (Q-BRIDGE-MIB: HP/Aruba, Cisco small business, Ubiquiti, Netgear, D-Link and most managed switches; CISCO-VTP-MIB: Cisco Catalyst access and trunk ports), from agents (Linux VLAN interfaces such as eth0.10, the VLAN ID of Windows network adapters) and of MikroTik bridges over the RouterOS API (with the device's MikroTik RouterOS (API) check) every ten minutes. The device page lists each VLAN with its tagged and untagged ports, and each port with its mode: Access (one untagged VLAN), Trunk (tagged VLANs; the untagged one is the native VLAN) or Hybrid (several untagged VLANs). Maps can show one VLAN at a time.

HA role

Devices that run VRRP report whether they are active (master) or standby (backup): read over SNMP (VRRP-MIB and VRRPv3-MIB, with the SNMP availability check) and from MikroTik RouterOS over the API (with the RouterOS API check). The device page shows the role and since when; maps show ACTIVE or STANDBY next to the device.

VXLAN

VXLAN interfaces (VTEPs) are read from MikroTik RouterOS 7 (with the RouterOS API check, every ten minutes) and from Linux agents (with iproute2, every five minutes): VNI, interface, own address, UDP port and remote VTEPs, also those in the forwarding table. The device page lists them; a remote VTEP that is the address of another device links to it. A VXLAN with no remote addresses uses multicast or EVPN. Maps draw a tunnel between two devices of the map that are each other's VTEPs.

Graphs

Every value is kept: raw for days, then as 5-minute and hourly minimum, average and maximum (Settings → Metric data). On a graph drag to zoom in, double-click to go back; the time range buttons go from one hour to a year.

The ⤢ button of a graph shows it over the whole window (Esc goes back).

Edit graphs (operators and administrators) arranges the graphs of a device like panels of a dashboard:

  • ✎ changes a graph: its title, kind (line, area or bars), stack the values (each on top of the ones before), the values it shows — also from several checks, for example CPU and memory together and the colour of each — the axis minimum and maximum, and a warning and critical line.
  • ↔ makes it as wide as the page, ↕ taller or lower, ▲ ▼ move it, × removes it (its values are not graphed until a graph shows them again).
  • Drag the lower right corner of a graph to set its width (1–4 columns) and its height; it is saved when you let go.
  • Add graph makes a new one from any values of the device. Values of new checks get their automatic graphs.
  • Automatic graphs removes the arrangement: one graph per check again.
