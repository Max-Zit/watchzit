Data sources

Graphs and dashboards can show time series from outside WatchZit too: tables of your own databases, Prometheus, InfluxDB or any address that answers JSON — next to the values of agents and checks.

Adding a data source

Administrators add data sources in Settings → Data sources:

Test connection tries the settings without saving them. The password or token is stored encrypted and never shown again; leave the field empty to keep it.

For SQL databases choose the encryption: when the server offers it (default), always with any certificate, always with a trusted certificate, or never. For addresses with https:// a self-signed certificate can be accepted.

Give the console a user that may only read the tables it needs. WatchZit runs PostgreSQL and MySQL queries in a read-only transaction; SQL Server has no such thing, so there only the user's rights protect the data. Operators write queries; viewers only see the graphs.

Queries on graphs

On a device page click Edit graphs, then ✎ on a graph or Add graph. Under Data sources click Add query, choose the data source and write the query. Try runs it over the page's time range and tells the series it gives (with their number of points) or the error of the database. A graph can show up to 6 queries next to the values of the device, each with a series name, a unit and a colour.

On dashboards add the widget Graph from a data source.

The answers are kept 20 seconds, so a dashboard on several screens asks the database once. A query brings at most 200,000 rows and 50 series and may take 20 seconds; the values are thinned to the width of the graph.

SQL (PostgreSQL, MySQL, SQL Server)

The query returns a time column (named time, or the first column that holds times; Unix seconds or milliseconds work too), one or more numeric columns (a series each) and, optionally, a text column that names the series (metric, or the first text column) for tables with one row per series and time. Order by time.

Macros put the graph's time range into the query:

MacroBecomes
$__timeFilter(col)col between the start and end of the range
$__timeGroup(col)col rounded down to the graph's interval; $__timeGroup(col, 300) to 5 minutes
$__timeFrom, $__timeTothe start and end as a time
$__unixFrom, $__unixTothe start and end in Unix seconds
$__interval_sthe graph's interval in seconds

Examples:

-- orders per interval (PostgreSQL, MySQL, SQL Server alike)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- one series per warehouse
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Write PromQL, for example rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Each series is named as Prometheus writes it (name{label="value"}); a series name in the editor replaces it. The step follows the width of the graph.

InfluxDB

Write InfluxQL with $timeFilter and $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 and 3 answer InfluxQL through their 1.x API: map the bucket to a database there if it is not mapped yet.

JSON over HTTP

The query is a path or parameters added to the address (for example /api/temps?room=server); WatchZit adds from, to and step in Unix seconds and reads any of these answers (times in seconds or milliseconds):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
