トラブルシューティングとよくある質問

Ping に「ICMP is not allowed」と表示される

サーバーには ICMP を送信する権限が必要です。パッケージ版のサービスにはその権限（CAP_NET_RAW）があります。それ以外の環境では、setcap cap_net_raw+ep /usr/bin/watchzit-server で権限を付与するか、非特権 Ping を許可してください：sysctl net.ipv4.ping_group_range="0 2147483647"。

SNMP に「応答なし」と表示される

  • プロファイルのコミュニティ、または SNMPv3 のユーザー、プロトコル、パスワードを確認してください。
  • デバイス側で WatchZit サーバーのアドレスを許可し（多くのデバイスは登録されたマネージャーにのみ応答します）、ファイアウォールで UDP 161 を許可してください。
  • v3 ユーザーが不明な場合やパスワードが間違っている場合は、メッセージにそのことが示されます。

エージェントが接続しない

  • コンピューターからサーバーのエージェント用ポート 8444 に到達できる必要があります。設定 → ネットワークとアクセス（許可するネットワーク、エージェント用公開アドレス）を確認してください。
  • Windows：Get-Service WatchZitAgent と C:\ProgramData\WatchZit Agent 内のログ。Linux：journalctl -u watchzit-agent。
  • 「the server does not know this agent」：デバイスが削除されています。新しいコードで再登録してください。

通知が届かない

  • 設定 → 通知からテストを送信してください。チャネルの一覧に最後のエラーが表示されます。
  • メンテナンス中の問題や、ダウンしたデバイスの背後にある問題は送信されません。チャネルの最小重大度を確認してください。

自分自身を締め出してしまった

サインインの失敗が多すぎると、そのアドレスは一定時間ブロックされます。サーバー上で watchzit-server --unblock-ip all を実行します。許可するネットワークから自分が外れている場合は watchzit-server --reset-allowlist を実行します。

ログはどこにありますか？

journalctl -u watchzit-server と /var/lib/watchzit/logs/server.log です。更新ヘルパーは /var/log/watchzit-helper/helper.log に書き込みます。設定 → 診断では最新の行が表示され、サポートに送るための秘密情報を含まない ZIP を取得できます。

よくある質問

デバイスにエージェントは必要ですか？いいえ。Ping、ポート、SNMP、Web、DNS、データベース、API のチェックはサーバーから実行されます。エージェントは、コンピューター自身にしかわからない情報を追加します。

何台のデバイスに対応できますか？1 台のサーバーで毎分数千件のチェックをポーリングできます。測定値は圧縮されるため、1 年分のデータでも小さく収まります。

無料ですか？はい、AGPL-3.0 のもとで無料です。MaxZit は有償サポートを提供しています。
