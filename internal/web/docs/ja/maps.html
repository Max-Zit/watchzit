ネットワークマップ

マップはネットワークの図であると同時に、ライブの監視画面でもあります。デバイスは状態に応じて色分けされ、ケーブルはトラフィックを示し、ポートは拡大して確認できます。

マップの描画

  1. マップでマップを追加し、編集をクリックします。
  2. デバイスを追加でデバイスをマップに配置し、ドラッグして位置を決めます。アイテムを追加では監視しないもの（パッチパネル、PDU）を追加します。編集中にアイテムのパネルで監視対象の機器を選ぶと、そのアイテムはコンソールのデバイスになります。画像、位置、ラックユニット、ケーブルはそのまま残り、デバイスの状態とメトリクスが表示されます。なし（画像のみ）を選ぶと、デバイスはアイテムに戻ります。
  3. 接続：2 台のデバイスをクリックし、両端のポートを選びます（SNMP またはエージェントのインターフェースから）。ケーブルにはそのポートのトラフィックが表示されます。
  4. 提案されたリンクには、デバイスの接続先（デバイスで見つかったリンクを参照）が表示され、ポート付きのケーブルと、マップに接続されているがマップ上にないデバイスが提案されます。すべて追加でそれらをすべて追加します。
  5. 保存（または Ctrl+S）をクリックします。変更は保存するまでページ内にのみ保持されます。キャンセルで保存済みのマップに戻ります。

画像、ラック、ケーブル

  • すべてのデバイスには、組み込みライブラリの画像（ポート付きのスイッチ、ルーター、サーバー、ファイアウォール、アクセスポイント、電話機、カメラ …）か、アップロードした画像があります。
  • ライブラリには、180 社を超えるメーカーの約 3,500 の実機モデルも含まれています：サーバー（G6 以降の HPE ProLiant、Dell PowerEdge、Lenovo、Supermicro、Cisco UCS、Fujitsu、Huawei/xFusion、Inspur）、NAS（Synology、QNAP、Asustor、TrueNAS ほか）、SAN ストレージと FC スイッチ（HPE MSA/3PAR/Nimble/Alletra、IBM Storwize/FlashSystem、Dell PowerVault/Unity/PowerStore、NetApp、Pure Storage、Lenovo、Fujitsu ETERNUS、Huawei OceanStor、Hitachi、Brocade、Cisco MDS）、スイッチ（Cisco、HPE Aruba、Dell、Juniper、Ubiquiti、Netgear、TP-Link、D-Link、Zyxel、Huawei、Arista、Extreme、Ruckus、Alcatel-Lucent、Ruijie、FS（fs.com：キャンパス、PoE、データセンター、産業用スイッチ、Wi-Fi、メディアコンバーター、光ファイバー収納箱）、QNAP、TRENDnet、Hikvision、Dahua、Lancom、DrayTek、産業用の Moxa、Siemens SCALANCE、Hirschmann、Phoenix Contact ほか）、ファイアウォール（Fortinet、Palo Alto、Sophos、WatchGuard、SonicWall、Check Point、Cisco ASA/Firepower、Netgate ほか）、MikroTik、家庭用・オフィス用ルーターとメッシュ Wi-Fi（TP-Link、ASUS、FRITZ!Box、Netgear、Linksys、D-Link、Huawei と ZTE の ONT ほか）、アクセスポイント、UPS（タワー型とラック型）、ビデオレコーダーと IP カメラ、屋外用のポイントツーポイント・セクター・無指向性アンテナ、プリンター、IP 電話と PBX、ブレードシャーシ、PDU、KVM とコンソールサーバー、環境モニターとミニ PC、GPON の OLT と ONT、サービスプロバイダー向けルーター、SD-WAN エッジ、NTP タイムサーバー、インターホン、ビデオ会議、PLC と HMI。汎用の画像にはラック用アクセサリーもあります：ケーブルマネージャー、ブラシパネル、棚板、ファントレイ、引き出し、ブランクパネル。汎用の画像には光ファイバーパッチパネル（LC デュプレックスのシングルモードとマルチモード、SC/APC と SC/UPC、12～96 ポート）と壁掛け光ファイバーボックスもあります。画像パネルでメーカー（またはすべてのメーカー）と種類（スイッチ、ルーター、ファイアウォール、サーバー、ストレージ / NAS、アクセスポイント …）を選ぶか、モデルを検索します（例：「DL380 Gen10」や「CRS326」）。汎用の画像で種類を選ぶか検索すると、すべてのメーカーから探します。図にはそのモデルのポートとドライブベイがあるため、ケーブルは正しいポートにつながります。デバイスの場合、パネルはそのメーカーで開きます。デバイスをマップに追加したときに、その SNMP の説明がライブラリのモデル（たとえば MikroTik）を示していれば、その画像が自動的に選ばれます。
  • 4～48 ユニットのラック：デバイスをドロップすると、空いているユニットに吸着します。ラックマウント用ではないもの — NAS、小型スイッチ、棚に置いたミニ PC — には、デバイスのパネルで独自の高さ（1～20U。指定しなければ画像の高さ）と幅（全幅、1/2、1/3、1/4）を、左から右への位置とともに設定できるため、同じユニットに複数台を横に並べられます。ラックにドロップすると、最も近い空き位置に収まります。
  • ケーブルには種類（銅線、光ファイバー、DAC、無線、VPN、WAN、シリアル、電源）と経路（直線、90° または 45° の折れ線、曲線）があります。点をドラッグすると曲げられ、点をダブルクリックすると削除できます。
  • サイズ、透明度、位置を設定できる背景画像（フロア図、敷地図）。
  • サブマップは他のマップにリンクし、そのマップで最も悪い状態を表示します。

マップの見方

  • 緑は稼働、オレンジは一部停止、赤は停止（点滅）です。グレーは不明または一時停止を意味します。
  • ケーブルは使用率に応じて太くなり、色が変わります（50 % 超でオレンジ、80 % 超で赤）。ポートにリンクがないケーブルは赤の破線になります。
  • ホイールまたは 2 本指で拡大縮小します。十分に近づくと名前とポートのラベルが表示されます。デバイスをクリックすると、チェック、ポート、ツールを含むパネルが開きます。オペレーターと管理者にはそこにデバイスを編集も表示され、保存するとマップに戻ります。ダブルクリックするとデバイスを開きます。
  • ケーブルをクリックするとパネルが開き、現在の双方向のトラフィックと、直近 1 時間、1 日、1 週間、1 か月のトラフィック履歴（どちらかの端のインターフェースチェックから）が表示されます。

HA グループ

  • 互いに代替となるデバイス — ファイアウォールの HA ペア、VRRP や HSRP のルーター、スイッチスタックや MLAG/vPC ペア、サーバーやストレージのクラスター — は HA グループを構成します。編集中に、最初のデバイスのパネルで HA グループ → 新しい HA グループを選び、他のデバイスのパネルで同じグループを選びます。グループはメンバーを囲む破線の枠で表示されます。ラックに搭載されたメンバーには細い輪郭線だけが付き、隣のメンバーと接する位置に小さな ⇅ HA タグが表示されるため、周囲のユニットは見やすいままです（タグをクリックするとグループが開きます）。各メンバーのタグの横には VRRP ロールが小さく表示されます — ACTIVE は緑、STANDBY はオレンジです。グループのパネルでは名前と種類を設定します。
  • 経路はグループのすべてのメンバーを通り、同等の経路をすべて表示します（たとえば 2 台のファイアウォールを通る 2 つの経路）。メンバー間のケーブル（ハートビート、同期、スタック、ピアリンク）には、ケーブルの種類 HA リンクを設定してください。これはトラフィックの経路にはなりません。
  • 枠（またはタグ）は、すべてのメンバーが稼働している間は緑、一部がダウンしていると冗長性喪失としてオレンジ、すべてがダウンしていると赤になります。その際、トリガー冗長性を失った HA グループが問題を発生させます（「アラート」を参照）。
  • VRRP を報告するメンバーには ACTIVE または STANDBY が表示され、グループのパネルにはその開始時刻が表示されます。

ハイパーバイザーと仮想マシン

  • ハイパーバイザーを追加（編集中）で仮想化ホスト用のボックスを追加します。ハイパーバイザー（VMware ESXi、Proxmox VE、Hyper-V、XCP-ng、KVM、Nutanix AHV、Docker、Kubernetes ほか）と、それが動作する物理サーバーを選びます（必須。クラスターの場合はクラスターで他のサーバーを追加します。経路はそのいずれを通ることもできます）。サーバーの状態はボックスに表示され、メトリクスはパネルから開けます。サーバーがマップ上にあれば、両者は破線で結ばれます。経路は、仮想マシンからハイパーバイザーと物理サーバーを経て、ケーブルに沿って進みます。
  • 仮想マシンをボックスにドラッグします：コンソールのデバイス（状態を表示するため）か、OS の画像を持つアイテム（Windows Server、Ubuntu、Debian、Red Hat、MikroTik CHR、pfSense、コンテナーなど。画像パネルで種類仮想マシンを選択）です。ボックス内ではグリッド状に並びます。ボックス内でドラッグすると順序を変え、ボックスの外へドラッグするとホストから外れます。デバイスのパネルにも実行するハイパーバイザーがあります。
  • ハイパーバイザーのマシンを自動で表示（新しいボックスでは既定でオン）は、ハイパーバイザーのチェック、エージェント（Hyper-V、Docker）、または vCenter がその物理サーバーについて報告するマシンでボックスを埋めます。実行中のものは緑、停止中のものはグレー、一時停止中のものは黄色です。アドレスまたは名前がコンソールのデバイスと一致するマシンは、そのデバイスとして表示されます。これらのマシンは、移動や接続を行うか、マップに配置を押すまでは、保存されたマップには含まれません。マシンをマップに配置ですべてを配置します。マシンの名前で自分で配置したアイテムにも、その状態が反映されます。
  • ボックスには、仮想マシンと物理サーバーのうち最も悪い状態が表示されます。レイヤーハイパーバイザーでボックスを非表示にできます。

画像ライブラリ

メニューの画像ライブラリには、独自のデバイス画像を保存します。画像をアップロードする（PNG、JPEG、GIF、WebP、SVG。正面図が最適です）か、組み込みの画像を使います。鉛筆は組み込みの画像そのものを変更し、それが使われているすべてのマップに反映されます（開くだけでは何も変わらず、変更を保存したときにのみ変更版が保存されます）（変更した画像を削除すると組み込みの画像に戻ります）。コピーは、そこから似たモデル用に独自の新しい画像を作成します。エディターでは次を設定します。

  • ポート：画像をクリックしてポートを追加します。最初はポート 1 です。ポートはドラッグで移動し、ダブルクリックで削除します。1 列分を作るには、ポート数を入力して最初と最後のポートをクリックします。2 段にすると、スイッチのように 1 の下に 2 が来る番号付けになります。最後の SFP ポートはオレンジで描かれ、光ファイバーケーブルが提案されます。
  • ラックユニット（ラックマウントしないデバイスは 0）、メーカー、種類、マップ上の幅。
  • コピーは、自分の画像の 1 つから似たモデル用の新しい画像を作成します。

画像はマップの画像パネルにメーカーと種類ごとに表示され、マップ上のケーブルは指定したポートにつながります。

レイヤーと経路

  • レイヤーでは、マップに表示するものを選びます：デバイス、ラック、アイテム、サブマップ、ケーブル、ポート名、トラフィック、VLAN ラベル、VXLAN トンネル、名前とアドレス、テキスト、背景を任意に組み合わせられます。選択はこのブラウザーに保存されます。
  • 経路：2 台のデバイスをクリックすると、マップはその間のケーブルのつながり（途中のパッチパネル、スイッチ、ラックを含む）だけを表示し、そこへ拡大します。もう一度「経路」をクリックするか Esc を押すと、マップ全体が表示されます。
  • ケーブル上のポート名は拡大したときに表示されるため、混み合ったマップでも読みやすさが保たれます。ポート名はケーブルの端に正確に表示されます：画像のポート上、またはポートのない画像からケーブルが出る位置です。すべてのケーブルの上に描かれるので、ケーブルに隠れることはありません。別のケーブルがすでに使っているポートは再び選べず、一覧にはそのケーブルの接続先が表示されます。
  • VLAN：マップ上のスイッチやルーターが VLAN を報告すると、ツールバーに VLAN の一覧が表示されます。VLAN を選ぶと、マップにはその VLAN を通すケーブルだけがタグ付き／タグなしの表示付きで示され、その VLAN を持たないデバイスは薄く表示されます。ケーブルのパネルには、そのポートの VLAN が一覧表示されます。
  • ケーブルには VLAN モードのラベルが付きます。たとえば Access 20 や Trunk · native 1 · 10, 20-25 です（レイヤー VLAN ラベル）。VLAN フィルターでは、タグ付きのみ、またはタグなしのみの VLAN を表示することもできます。両端の設定が一致しない場合 — アクセスポートとトランクの組み合わせ、両端でネイティブ VLAN が異なる場合 — ケーブルはオレンジの破線で描かれます。
  • 編集中は、ケーブルの VLAN モードを手動で設定できます：VLAN を指定したアクセス、またはネイティブ VLAN と許可する（タグ付き）VLAN（20-25 のような範囲も可）を指定したトランクです。自動はポートが報告する内容を使います。ケーブルには VXLAN VNI も設定でき、ケーブルの種類 VXLAN トンネルで手動でトンネルを描けます。
  • デバイスが報告する VXLAN トンネルは、VNI 付きの紫の破線の弧で描かれます（レイヤー VXLAN トンネル）。

キオスク表示

設定 → キオスク表示で、表示するマップと切り替え間隔を指定して表示を作成します。表示にはサインインせずにマップを全画面で開く秘密のリンクが発行されます — 監視用テレビ向けです。表示を削除すると、リンクは使えなくなります。

概要ではなくマップから始めるには、マイ アカウントでそのマップをスタートページに選びます。サインイン後やロゴをクリックしたときにそのマップが開き、メニューの概要では引き続き概要が開きます。ダッシュボードをスタートページにすることもできます。

マップの整列

編集中に整列を使うと、ケーブルに基づいてマップ全体を配置し直します：最も多く接続されたデバイス（同数の場合はスイッチよりルーターやファイアウォールを優先）を最上段に、それにつながるものを次の段に、というように並べます。ラックとハイパーバイザーボックスは中身ごと移動し、ケーブルのないものは下にグリッド状に並び、手で描いた折れ点は削除されます。保存をクリックするまで何も保存されず、キャンセルですべて元に戻ります。

デバイスで見つかったリンク

WatchZit は 15 分ごとに、SNMP を使って（MikroTik デバイスは RouterOS API チェックを使って）デバイスから接続先を読み取ります。確実性の高い順に次のとおりです。

  • ネイバーテーブル — LLDP、Cisco CDP、MikroTik discovery：両端とそのポート。2 台のデバイス間に実ポートがある場合は、実ポートだけが対象になります（VLAN、VXLAN、ブリッジ、VRRP のインターフェースは除外）。
  • スイッチの MAC アドレステーブル：デバイスの MAC アドレスが学習されたポート — デバイス自身のインターフェースの MAC、エージェントが報告するネットワークカード、またはルーターの ARP テーブルにあるそのアドレスの MAC（そのため、SNMP のないプリンター、カメラ、サーバーも見つかります）。アドレス数が最も少ないアクセスポートが採用され、他のスイッチへのポート（ネイバーがスイッチであるもの、またはアドレスが 8 個を超えるもの）は採用されません。
  • 別のデバイスを示すポートの説明（インターフェースのエイリアス、または保存された設定内の説明）。例：「uplink to sw2 ether7」。説明にポートが含まれていれば、そのポートも使われます。
  • 保存された設定（MikroTik、Cisco、FortiGate の設定のバックアップ）：同じポイントツーポイントネットワーク（/30 または /31）にアドレスを持つ 2 台のデバイス。

自動で描画（「提案されたリンク」パネル内）：マップは 15 分ごとに、マップ上のデバイス間で見つかったリンクを追加します。つながるデバイスも追加をオンにすると、マップに接続されているデバイスも、接続先のデバイスの隣に配置して追加します。このようなマップから削除したリンクやデバイスは削除されたままになります（オプションをオフにしてから再びオンにすると、その記録は消去されます）。デバイスを再読み取りで、マップのデバイスを今すぐ読み取ります。
