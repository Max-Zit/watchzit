デバイス、チェック、SNMP

デバイスとは、アドレスを持つあらゆるものです。ルーター、スイッチ、サーバー、プリンター、カメラ、Web サイトなどが該当します。チェックがそれを測定し、その結果によってデバイス、マップ、グラフの色が決まります。

デバイスの追加

デバイス → デバイスを追加で名前と IP アドレスまたはホスト名を入力し、種類とグループを選んで、Ping はオンのままにします。オプション：

  • SNMP — コミュニティまたは SNMPv3 ユーザーを設定したプロファイル。WatchZit はインターフェース、トラフィック、CPU、メモリー、ディスクを読み取ります。
  • 依存先 — デバイスへの経路となるルーターやスイッチ。それがダウンしている間、このデバイスの問題は「到達不能」としてのみ扱われ、通知されません。
  • リモート アクセス — ツールが使用するユーザー名とポート。
  • TCP ポート — それぞれが 1 分ごとに接続するチェックになります。

デバイスの状態はチェックから決まります。すべてが稼働していれば稼働、一部がダウンしていれば一部停止、すべてがダウンしていれば停止です。

検出

デバイス → 検出は、ネットワーク上のホストを見つけます。範囲（例：192.168.1.0/24、/22 まで、または 1 つのアドレス）を追加し、今すぐ、毎日、または毎週スキャンします。WatchZit はすべてのアドレスに Ping を送り、一般的なポート（SSH、Telnet、Web、RDP、WinBox、SMB、プリンター、VNC）を試し、SNMP プロファイルを使って名前、説明、メーカーを問い合わせ、DNS 名を調べます。まだデバイスになっていないホストは、名前、推定された種類、応答したものとともに一覧表示されます。チェックを入れてデバイスとして追加をクリックすると（必要に応じてグループに入れて）、それぞれに Ping チェック（Ping がブロックされている場合は TCP チェック）と、応答した SNMP プロファイルが設定されます。非表示にしたホストは一覧から外れますが、再表示することもできます。スケジュールを設定すると、ネットワークに新しく現れたホストが自動的にここに表示されます。リモートコレクターを使う場合は、どのコレクターが範囲をスキャンするかを選びます。コレクターは自身の拠点のネットワークをスキャンします。

Web リンク

デバイスの Web リンクで設定した Web 画面のアドレスは、デバイスページとマップ上のボタンで開きます。必要であればボタンに別の名前を付けられます。複数のアドレスを持つサーバー、その iDRAC や iLO、サービスのページなどには、リンクを追加できます。それぞれが独立したボタンになります。

カスタム フィールド

管理者は、設定 → カスタム フィールドでデバイス用の独自のフィールドを追加できます。テキスト、数値、日付のいずれかで、資産番号、保証期限、ラック、契約などに使えます。オペレーターはデバイスページのカスタム フィールドで値を入力します。値はデバイスの詳細とともに表示され、デバイス一覧の検索でも見つかります。フィールドを削除すると、その値も削除されます。

テンプレート

テンプレートは、Linux サーバー、MikroTik ルーター、プリンターといったデバイスの種類ごとのチェックのセットです。テンプレートで作成し、対象とするデバイスの種類を選んでチェックを追加します（Ping、TCP、Web ページ、TLS 証明書、DNS、SNMP のチェック。パスワードを必要とするチェックはデバイスごとに追加します）。適用先では、その種類のすべてのデバイス、グループ、またはすでにテンプレートが適用されているデバイスにもう一度チェックを追加します。デバイスページのテンプレートを適用は 1 台のデバイスに適用します。適用では、デバイスがまだ持っていないチェックだけが追加されます。既存のチェックはそのまま残るため、2 回適用しても問題ありません。この種類の新しいデバイスに自動で適用をオンにすると、後から（手動または検出で）追加されたすべてのデバイスにすぐチェックが設定されます。テンプレートを削除しても、デバイス上のチェックは残ります。

複数のデバイスを一度に変更

デバイス一覧でデバイスにチェックを入れ（ヘッダーのボックスで表示中のすべてにチェックが入ります）、選択したものを変更で次のいずれかを選びます：グループ、SNMP プロファイル、依存先のデバイス、種類、監視の一時停止・再開、テンプレートの適用、または（管理者のみ）チェックとデータを含めた削除。たとえば、ある拠点のプリンターをすべて選ぶには、先に一覧を絞り込んでください。

チェックの種類

チェック測定内容
Ping (ICMP)応答時間とパケットロス。
TCP ポートポートが接続を受け付けるかどうかと、その速さ。
Web ページ（HTTP）ステータスコード、応答時間、ページに含まれるべきテキスト、証明書の有効期限までの日数。
TLS 証明書有効期限までの日数と、信頼されているかどうか（任意の TLS ポート。SNI 用のサーバー名を指定可能）。
DNSデバイスが DNS サーバーである場合：名前に対してレコードの種類（A、AAAA、MX …）で応答し、必要に応じて期待される値を返す必要があります。
PostgreSQL、MySQL / MariaDB監視用ユーザーでのサインイン、バージョン、接続数、応答時間。
MikroTik RouterOS（API）RouterOS 7 の REST API による CPU、メモリー、稼働時間、温度。
JSON API の値任意の JSON API（FortiGate、vCenter、独自のサービス）から取得する 1 つの数値：アドレス、results.cpu.0.current のようなパス、オプションで Bearer または Basic 認証。
ハイパーバイザー (vSphere、Proxmox VE)VMware ESXi または vCenter（Web サービス API）、Proxmox VE（REST API）のホスト、仮想マシンとコンテナー、データストア：ホストの CPU とメモリー、稼働中のマシン、ダウンしたホスト、最も使用率の高いデータストア。ハイパーバイザーを参照してください。
SSH 経由の Linux、WinRM 経由の Windows（エージェントなし）何もインストールされていないマシンの CPU、メモリ、スワップまたはページファイル、最も使用率の高いディスク、稼働時間（Linux では負荷も）。エージェントなしのマシンを参照してください。
Web シナリオユーザーと同じように Web アプリケーションの複数の手順をたどります：サインインし、サインインが必要なページを開き、テキストを確認します。1 行に 1 ステップで、たとえば GET /login | 200 | Sign in、POST /login | 302 | | user=monitor&password={secret}、GET /dashboard | | Welcome のように記述します。メソッドとアドレス、続いて期待されるステータス、ページに含まれるべきテキスト、フォームデータです。Cookie はステップ間で引き継がれ、{secret} はチェックのパスワードです。全ステップの所要時間と成功したステップ数を測定し、アラートには失敗したステップが示されます。
SNMP可用性と稼働時間。検出で見つかったインターフェース、CPU、ストレージ。任意の数値 OID。

チェックのパスワードやトークンは暗号化して保存され、再表示されることはありません。チェックを編集するときにフィールドを空のままにすると、保存済みの値が維持されます。

SNMP

  1. 設定 → SNMPでプロファイルを作成します。コミュニティを使う v2c か、ユーザーを使う v3（SHA-2 と AES に対応）です。
  2. デバイスでプロファイルを選びます。WatchZit が SNMP 検出を開くので、監視するインターフェース、CPU、メモリー、ディスクにチェックを入れます（ループバックとリンクのないインターフェースは除外されます）。
  3. デバイスページには、リンク状態とライブのトラフィックを示すポートと、すべての値のグラフが表示されます。

検出では、その種類のデバイスが報告する情報も見つかります。プリンターの消耗品（トナー、インク、ドラム、廃トナーボックスの残量をパーセントで。既定のトリガートナー・インク残量わずかが 10 % 未満で警告します）、UPS（UPS-MIB、または APC カードの APC PowerNet MIB：バッテリー残量、残り稼働時間、負荷。UPS がバッテリーで動作している間やバッテリー残量が少ない間はチェックがダウンとなり、UPS の残り時間わずかが 10 分未満で警告します）、MikroTik のヘルスセンサー（温度、電圧、ファン、電力。それぞれ単位付きの OID チェックになります）です。

MikroTik、Cisco、HP、Ubiquiti、プリンター、UPS は SNMP に対応しています。Linux では snmpd を、Windows では SNMP サービスをインストールしてください。

VLAN

WatchZit は、スイッチの VLAN を 1 時間ごとに SNMP で読み取ります（Q-BRIDGE-MIB：HP/Aruba、Cisco のスモールビジネス向け製品、Ubiquiti、Netgear、D-Link、およびほとんどのマネージドスイッチ。CISCO-VTP-MIB：Cisco Catalyst のアクセスポートとトランクポート）。また、エージェントから（eth0.10 などの Linux の VLAN インターフェース、Windows のネットワークアダプターの VLAN ID）、MikroTik のブリッジからは RouterOS API で（デバイスの MikroTik RouterOS（API）チェックを使用）10 分ごとに読み取ります。デバイスページには、各 VLAN とそのタグ付き／タグなしのポート、および各ポートのモードが表示されます：アクセス（タグなし VLAN が 1 つ）、トランク（タグ付き VLAN。タグなしのものがネイティブ VLAN）、ハイブリッド（タグなし VLAN が複数）。マップでは一度に 1 つの VLAN を表示できます。

HA ロール

VRRP を実行しているデバイスは、自身がアクティブ（マスター）かスタンバイ（バックアップ）かを報告します。これは SNMP（VRRP-MIB と VRRPv3-MIB、SNMP 可用性チェックを使用）と、MikroTik RouterOS からは API（RouterOS API チェックを使用）で読み取ります。デバイスページにはロールとその開始時刻が表示され、マップではデバイスの横に ACTIVE または STANDBY が表示されます。

VXLAN

VXLAN インターフェース（VTEP）は、MikroTik RouterOS 7 から（RouterOS API チェックで 10 分ごと）、Linux エージェントから（iproute2 で 5 分ごと）読み取ります：VNI、インターフェース、自身のアドレス、UDP ポート、およびフォワーディングテーブル内のものも含めたリモート VTEP です。デバイスページに一覧表示され、リモート VTEP が別のデバイスのアドレスであれば、そのデバイスへリンクします。リモートアドレスのない VXLAN は、マルチキャストまたは EVPN を使用しています。マップでは、互いの VTEP となっている 2 台のデバイスの間にトンネルが描かれます。

グラフ

すべての値が保存されます。数日間は生データのまま、その後は 5 分ごとおよび 1 時間ごとの最小値・平均値・最大値として保存されます（設定 → 測定データ）。グラフ上でドラッグすると拡大し、ダブルクリックで元に戻ります。期間ボタンは 1 時間から 1 年まで選べます。

グラフの ⤢ ボタンでウィンドウ全体に表示します（Esc で戻ります）。

グラフを編集（オペレーターと管理者）では、デバイスのグラフをダッシュボードのパネルのように配置できます。

  • ✎ でグラフを変更します：タイトル、種類（折れ線、面、棒）、値を積み上げる（各値を前の値の上に重ねる）、表示する値（複数のチェックからも選べます。たとえば CPU とメモリーを一緒に表示し、それぞれの色を設定）、軸の最小値と最大値、警告ラインと重大ライン。
  • ↔ でページ幅いっぱいに広げ、↕ で高さを変え、▲ ▼ で移動し、× で削除します（その値は、再びグラフに表示するまでグラフ化されません）。
  • グラフの右下の角をドラッグすると、幅（1～4 列）と高さを設定できます。マウスを離すと保存されます。
  • グラフを追加では、デバイスの任意の値から新しいグラフを作成します。新しいチェックの値には自動のグラフが作成されます。
  • 自動のグラフは配置を削除し、チェックごとに 1 つのグラフに戻します。

設定のバックアップ

オペレーターと管理者は、ネットワークデバイスの設定を保存できます。デバイスの設定のバックアップセクションで方式を選びます — MikroTik RouterOS（/export terse show-sensitive）、Cisco IOS（show running-config）、FortiGate（show full-configuration）、または独自のコマンド — そして SSH のユーザー、ポート、パスワードまたは秘密鍵を指定します。パスワードと鍵は暗号化して保存されます。読み取り専用のユーザーを使用してください。

  • バックアップは毎晩 02:00（サーバー時刻）に、また今すぐバックアップで実行されます。新しいバージョンは設定が変わった場合にのみ保存され、各デバイスの最新 50 バージョンが保持されます。
  • SSH ホストキーは最初のバックアップ時に保存され、以降は照合されます。ホストキーが変わるとバックアップは失敗します。想定どおりの変更（新しいデバイスやファームウェア）であれば、ホストキーを忘れるを使ってください。
  • 各バージョンには前のバージョンとの差分が表示され（+ 追加行、− 削除行。すべてを見るには設定全体）、テキストファイルとしてダウンロードできます。
  • 変更と失敗はデバイスのログ（タグ config-backup）に記録されるため、ログトリガーでこれらを通知できます。
  • 閲覧者は、設定内容もバックアップの設定も見ることができません。

ハイパーバイザー

ESXi ホスト、vCenter、または Proxmox VE ノードのデバイスに、チェックハイパーバイザー (vSphere、Proxmox VE)を追加します（クラスターのどのノードからでもクラスター全体を読み取れます）。読み取り専用のユーザーで十分です：vSphere では Read-only ロール、Proxmox VE では / に対する PVEAuditor、または API トークン（ユーザーとして user@realm!name、パスワードとしてそのシークレット）。ポートを空にすると 443（vSphere）または 8006（Proxmox VE）になります。これらが既定で持つ自己署名証明書のために、信頼されていない証明書を受け入れるにチェックを入れてください。

  • 実行のたびに、すべてのホストの CPU とメモリー、稼働中のマシン数と総数、ダウンしたホスト、最も使用率の高いデータストアの使用率が保存されます。トリガーデータストアの残りわずか（90 % 超）とハイパーバイザーホストのダウンも一緒に用意されます。
  • デバイスページには、ホスト、すべての仮想マシンとコンテナー（状態、CPU、メモリー、アドレス、ゲスト OS）、データストアが一覧表示されます。ゲスト OS とアドレスは 10 分ごとに読み取られます（Proxmox VE は QEMU ゲストエージェントを通じてアドレスを読み取ります）。
  • Hyper-V と Docker にはチェックは不要です。Windows ホスト（Hyper-V あり）または Linux ホスト（Docker あり）上の WatchZit エージェントが、5 分ごとにマシンやコンテナーを報告します。
  • マップ上のハイパーバイザーボックスでは、これらのマシンを自動的に表示できます（マップのガイドを参照）。

エージェントなしのマシン

エージェントをインストールできない場所では、WatchZit はマシンにすでにある仕組みを通じて読み取ります。値の名前はエージェントと同じなので、トリガー High CPU load、Memory almost full、Disk almost full、Disk full はこれらのチェックも監視します。エージェントのほうが引き続き多くを表示します（すべてのドライブ、インターフェース、サービス、プロセス、ログ）。

  • SSH 経由の Linux: サインインできる任意のユーザーで、パスワードまたはパスフレーズのない秘密鍵を使います。WatchZit は /proc、df、uname だけを読む固定のコマンドを 1 つ実行し、何も書き込みません。ホスト鍵は初回に受け入れ、以後の実行ごとに照合します。変わった場合はチェックがダウンし、新しい鍵を示します（再インストールしたマシンでは保存したホスト鍵を破棄にチェック）。鍵を自分で入力することもできます: ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub。
  • WinRM 経由の Windows: winrm quickconfig で WinRM を有効にします（Windows Server では有効です）。HTTP（ポート 5985）では WatchZit は NTLMv2 でサインインし、Windows の要求どおりすべてのメッセージをサインインの鍵で暗号化します。HTTPS（5986、HTTPS リスナーが必要）では TLS が保護し、サインインは証明書に結び付けられます。ユーザーは name、DOMAIN\name、name@domain の形式で、管理者か、root\cimv2 に WMI 権限を持つ Remote Management Users のメンバーです。
  • 1 回の実行には数秒かかります（プロセッサーを 1 秒間測定するため）。そのためタイムアウトは最低 15 秒で、間隔は 1 分以上で十分です。
  • リモートコレクター経由では、ホスト鍵をチェックに入力する必要があります。コレクターは鍵を保存できないため、見えた鍵を表示します。
