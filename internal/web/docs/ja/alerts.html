問題、アラート、通知

トリガーはチェックの結果を監視し、問題を発生させます。問題は条件が解消すると自動的に閉じます。問題が未解決の間は対応済みにでき、通知チャネルに送信されます。

トリガー

問題 → トリガーで設定します。WatchZit には最初から次のトリガーがあります。

独自のトリガーも追加できます：値（CPU 負荷、応答時間、トラフィック、接続数 …）、しきい値より上またはより下、継続時間（分。短い落ち込みでは問題になりません）、重大度、そしてすべてのデバイス、グループ、1 台のデバイスのどれに適用するかを指定します。

新しいデータなしは、チェックが設定した分数のあいだ新しい値を受け取らなかったときに問題を発生させます — 報告を止めたエージェント、SNMP に応答しなくなったデバイス、停止したデータソースなどです。必要に応じてチェックの種類を限定できます。

値がしきい値に達する見込み (予測) は先を見越して判断します：値の直近 1 週間（最低 6 時間の履歴）に直線を当てはめ、その線が設定した日数以内にしきい値に達するときに問題を発生させます — 10 日後に満杯になるディスク、埋まりつつあるプール、上昇し続ける温度などです。問題には現在の値、1 日あたりの変化の速さ、到達する日付が示されます。傾向が期限内に到達しなくなると問題は閉じます。

1 つのチェック。デバイスページでチェックの横にあるベルのボタンを押すと、そのチェック専用のトリガーが追加されます。SNMP OID の値（°C の温度、V の電圧）はそれぞれ単位が異なるため必須であり、重要なディスクやポート 1 つだけを監視したいときにも便利です。このようなトリガーは適用先にデバイスとチェックを表示し、チェックと一緒に削除されます。

問題

問題には未解決のものが重大な順に一覧表示されます。メニューの数字は送信された問題の数です（重大なものがあると赤になります）。問題に対応するときはメモを添えると、誰かが対応中であることが他の人にもわかります。解決済みの問題は 1 年間履歴に残ります。

依存関係

デバイスに依存先を設定します（たとえば支社のルーター）。そのルーターがダウンすると、その背後にあるデバイスは到達不能としてのみ扱われます。問題は記録されますが送信されません — 50 通ではなく、ルーターについての 1 通だけが届きます。マップでは、このようなデバイスは赤ではなく破線の輪郭付きのグレーで表示され、パネルには問題が上位にあることが示されます。

ネットワーク全体に一度に設定するには、マップを開いて依存関係をクリックします。ネットワークの起点となるデバイス（既定ではケーブルが最も多いルーターまたはファイアウォール。必要なら別のものを選べます）からケーブルをたどり、各デバイスに 1 つ手前のデバイスを依存先として提案します — スイッチはルーターに、アクセスポイントはスイッチに、仮想マシンはそのサーバーに依存します。電源、HA、VXLAN のケーブルは対象外です。依存先のないデバイスにはチェックが入り、すでに別のデバイスに依存しているものは表示されますがチェックは入りません。チェックした依存関係を設定をクリックします。

メンテナンス

問題 → メンテナンスで、デバイスまたはグループのメンテナンス期間を計画します。期間中もデバイスは監視され問題も記録されますが、何も送信されません。期間の終了時にまだ未解決の問題は、その時点で送信されます。可用性レポートではメンテナンス時間が別に表示されます。繰り返しを設定すると、期間が毎日、毎週、毎月（夜間のバックアップ、月例のパッチ適用日）繰り返され、必要に応じて最終日まで続きます。一覧には次回の期間が表示され、削除でシリーズ全体を終了します。

通知

設定 → 通知（管理者）：

  • メールサーバー — STARTTLS、TLS、または暗号化なしの SMTP。パスワードは暗号化して保存されます。テストメールを送信できます。
  • チャネル — メールの宛先、Webhook（JSON。キーを設定すると X-WatchZit-Signature に HMAC-SHA256 の署名が付きます）、Slack、Microsoft Teams、Discord、Telegram（@BotFather のボットトークンとチャット ID）、ntfy（ntfy.sh または独自の ntfy サーバー経由でスマートフォンへプッシュ）、PagerDuty（Events API v2 のインテグレーションキー。問題に応じてインシデントを作成・解決します）、Twilio による SMS（アカウント SID、認証トークン、送信元、電話番号）、または独自ゲートウェイによる SMS（メッセージが入る位置に {text} を含む任意の HTTP アドレス）。各チャネルには最小重大度があり、問題が解決したときにも通知できます。
  • 通知の言語と、通知内のリンクに使うコンソールアドレス。

エスカレーションと当番

チャネルのエスカレーションと当番時間で設定します。

  • 通知までの待ち時間 (分) — チャネルは、その時間を過ぎてもまだ未解決の問題だけを受け取ります。たとえば、一次対応者が反応しなかった場合に 15 分後にチームリーダーへ通知します。繰り返し間隔を設定すると、問題が未解決の間は繰り返し通知します。
  • 確認済みの問題も含めるがオンでない限り、対応済みの問題はエスカレーションも繰り返し通知もされません。
  • 特定の曜日と時間のみにすると、そのチャネルは当番になります。例：夜勤への SMS を月曜～金曜の 18 時から 8 時までと週末終日に送信。当番時間外に始まった問題は、当番の開始時にまだ未解決であれば、そのときに届きます。ローテーションには、担当者やチームごとに独自の曜日と時間を設定したチャネルを 1 つずつ追加します。
  • 問題を通知されたチャネルには、その解決も通知されます。他のチャネルには通知されません。

Syslog と SNMP トラップ

デバイスはログメッセージと SNMP トラップを WatchZit に送信できます。設定 → Syslog とトラップでオンにします：既定では Syslog は UDP 514、トラップ（SNMP v1 と v2c。inform には応答します）は UDP 162 で受信し、必要に応じて特定のコミュニティのトラップのみに限定でき、30 日間保存されます。サーバーのファイアウォールでこれらのポートを開け、デバイスで送信先を WatchZit に設定します。例：MikroTik では /system logging action set remote remote=<サーバー> とアクション remote のロギングルール、FortiGate では config log syslogd setting、Linux では rsyslog の *.* @<サーバー>:514 の行。

  • ログには、メッセージが新しい順に一覧表示され、検索、デバイス、ソース（Syslog またはトラップ）、最低の重要度レベル（0 emergency … 7 debug）で絞り込めます。デバイスではないアドレスからのメッセージは、そのアドレスとともに表示されます。各デバイスページにはログボタンがあります。
  • 種類 Syslog メッセージまたはトラップのトリガーは、選択したレベル以上の重要度で、メッセージがテキストを含む（またはスラッシュで囲んだ正規表現に一致する。例：/link (down|failure)/）ときに問題を発生させます。このようなメッセージが届き続ける間は問題が未解決のままで、トリガーの時間内にメッセージが届かなければ閉じます。これらの問題は、レポートではダウンタイムとして数えられません。

トラフィックフロー（NetFlow、IPFIX、sFlow）

ルーター、スイッチ、ファイアウォールは、自身を通過するトラフィックの情報を送信できます。設定 → トラフィックフローでコレクターをオンにします：既定では NetFlow v5、NetFlow v9、IPFIX は UDP 2055、sFlow v5 は UDP 6343 で受信し、7 日間（1～90）保存されます。サーバーのファイアウォールでこれらのポートを開け、WatchZit をコレクターとして設定します。例：MikroTik では /ip traffic-flow set enabled=yes と /ip traffic-flow target add dst-address=<サーバー> port=2055 version=ipfix、FortiGate では config system netflow、sFlow 対応スイッチではこのサーバーをコレクターとする sFlow エージェント。

  • WatchZit は、フローを 1 分ごと・エクスポーターごとに、通信（送信元、宛先、プロトコル、サービスポート — 2 つのポートのうち小さい方）単位で集計します。各分にはエクスポーターごとに上位 1,000 件の通信が保持され、残りはアドレスなしの 1 行にまとめられるため、合計は正しく保たれます。サンプリングされたフロー（sFlow、またはサンプリングレートを設定した NetFlow）には、そのレートが掛けられます。
  • トラフィックフローには、直近 1 時間、6 時間、1 日、1 週間について、1 つまたはすべてのエクスポーターのトラフィックの推移と、上位の送信元、宛先、サービス、エクスポーター、通信が表示されます。コンソールのデバイスのアドレスは、そのデバイスとして表示されます。エクスポーターのデバイスページにはトラフィックフローボタンがあります。
  • デバイスではないアドレスからも受信がオンでない限り、デバイスではないアドレスのフローは除外されます。
