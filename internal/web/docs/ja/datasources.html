データソース

グラフとダッシュボードには、WatchZit の外部にある時系列データも表示できます。独自のデータベースのテーブル、Prometheus、InfluxDB、または JSON で応答する任意のアドレスのデータを、エージェントやチェックの値と並べて表示できます。

データソースの追加

管理者は設定 → データソースでデータソースを追加します。

種類アドレスサインイン
PostgreSQLhost または host:port（5432）、およびデータベースユーザーとパスワード
MySQL / MariaDBhost または host:port（3306）、およびデータベースユーザーとパスワード
Microsoft SQL Serverhost または host:port（1433）、およびデータベースSQL Server のユーザーとパスワード
PrometheusURL（例：http://prometheus:9090）。Thanos、VictoriaMetrics、Mimir も可なし、ユーザーとパスワード、または Bearer トークン
InfluxDBURL（例：http://influx:8086）とデータベース（InfluxDB 2/3 ではバケット）InfluxDB 1：ユーザーとパスワード。2 と 3：トークンのみ
JSON over HTTPサービスのベース URLなし、ユーザーとパスワード、または Bearer トークン

接続をテストは、設定を保存せずに試します。パスワードやトークンは暗号化して保存され、再表示されることはありません。保持するにはフィールドを空のままにしてください。

SQL データベースでは暗号化を選びます：サーバーが提供する場合（既定）、常に（任意の証明書で）、常に（信頼された証明書で）、または使用しない。https:// のアドレスでは、自己署名証明書を受け入れることができます。

コンソールには、必要なテーブルを読み取るだけのユーザーを割り当ててください。WatchZit は PostgreSQL と MySQL のクエリを読み取り専用トランザクションで実行します。SQL Server にはそのような仕組みがないため、データを守るのはユーザーの権限だけです。オペレーターはクエリを作成でき、閲覧者はグラフを見ることだけができます。

グラフ上のクエリ

デバイスページでグラフを編集をクリックし、グラフの ✎ またはグラフを追加をクリックします。データソースでクエリを追加をクリックし、データソースを選んでクエリを記述します。試すはページの期間でクエリを実行し、得られた系列（とそのポイント数）またはデータベースのエラーを表示します。1 つのグラフには、デバイスの値と並べて最大 6 つのクエリを表示でき、それぞれに系列名、単位、色を設定できます。

ダッシュボードでは、ウィジェットデータソースのグラフを追加します。

応答は 20 秒間キャッシュされるため、複数の画面に表示したダッシュボードでもデータベースへの問い合わせは 1 回です。1 つのクエリで取得できるのは最大 200,000 行、50 系列で、実行時間は最大 20 秒です。値はグラフの幅に合わせて間引かれます。

SQL（PostgreSQL、MySQL、SQL Server）

クエリは、時刻列（time という名前の列、または時刻を含む最初の列。Unix 秒やミリ秒も使えます）、1 つ以上の数値列（それぞれが 1 系列）、そしてオプションで系列名を示すテキスト列（metric、または最初のテキスト列。系列と時刻ごとに 1 行を持つテーブル用）を返します。時刻順に並べてください。

マクロはグラフの期間をクエリに埋め込みます。

マクロ展開結果
$__timeFilter(col)col が期間の開始と終了の間にある条件
$__timeGroup(col)col をグラフの間隔に切り捨てた値。$__timeGroup(col, 300) で 5 分単位
$__timeFrom、$__timeTo開始と終了（時刻型）
$__unixFrom、$__unixTo開始と終了（Unix 秒）
$__interval_sグラフの間隔（秒）

例：

-- 間隔ごとの注文数（PostgreSQL、MySQL、SQL Server 共通）
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- 倉庫ごとに 1 系列
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

PromQL を記述します。例：rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8。各系列には Prometheus の表記どおりの名前（name{label="value"}）が付きますが、エディターで系列名を指定するとそれに置き換わります。ステップはグラフの幅に従います。

InfluxDB

$timeFilter と $__interval を使って InfluxQL を記述します。

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 と 3 は、1.x API を通じて InfluxQL に応答します。バケットがまだデータベースにマッピングされていない場合は、そちらでマッピングしてください。

JSON over HTTP

クエリは、アドレスに付け加えるパスまたはパラメーターです（例：/api/temps?room=server）。WatchZit は Unix 秒で from、to、step を付加し、次のいずれかの形式の応答を読み取ります（時刻は秒またはミリ秒）。

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
