ユーザー、設定、更新

誰が何をできるか、コンソールがどのように保護されているか、そして WatchZit をどのように最新の状態に保つかを説明します。

すべてのユーザーは、パスワードと 2 要素サインイン（認証アプリ）でサインインします。スマートフォンを紛失した場合はリカバリーコードが役立ちます。管理者はユーザーでユーザーを追加し、パスワードと 2 要素サインインをリセットします。監査ログはすべての変更を記録します。エントリーは連鎖しているため、ログが改変されるとわかります。

Active Directory / LDAP とシングルサインオン

ローカルアカウントのほかに、ディレクトリのアカウントでもサインインできます。ローカルアカウントは常に使えるため、ディレクトリや ID プロバイダーがダウンしていても管理者はサインインできます。ローカルアカウントに属するユーザー名が、ディレクトリのサインインによって乗っ取られることはありません。

  • Active Directory / LDAP（設定 → Active Directory / LDAP）：サーバー（ldaps://dc1.example.local、または StartTLS を使う ldap:// — パスワードが暗号化されずにネットワークを流れることはありません）、必要に応じて社内 CA の CA 証明書、ユーザーとグループを読み取れるサービスアカウント、ベース DN、ユーザーフィルター（Active Directory では (&(objectClass=user)(sAMAccountName={username}))）を指定します。Active Directory では、入れ子になったグループもたどります。パスワードはディレクトリが確認しますが、WatchZit は独自の 2 要素目も要求します。テストは、サインインせずにアカウントを確認し、そのグループと付与されるロールを表示します。
  • シングルサインオン（設定 → シングルサインオン）：OpenID Connect（Microsoft Entra ID、Google、Okta、Keycloak …：発行者、クライアント ID、シークレット。https://<コンソール>/login/sso/callback をリダイレクト URI として登録します）または SAML 2.0（ADFS、Entra ID、Okta …：ID プロバイダーのメタデータ URL または XML。ID プロバイダーには https://<コンソール>/login/sso/metadata を渡し、応答先アドレスは /login/sso/saml です）。サインインページにボタンが追加されます。WatchZit 独自の 2 要素目は、チェックを入れた場合にのみ要求されます。それ以外は ID プロバイダーのポリシーに従います。
  • グループとロール：サインインのたびに、グループによってロール（管理者、オペレーター、閲覧者。最も高いものが優先）が決まります。どのグループにも属さないユーザーは、既定のロールが付与されるか、サインインできません。グループは名前または完全な DN、あるいは ID プロバイダーが送る名前または ID で指定します（Entra ID は ID を送ります）。
  • ディレクトリのアカウントは最初のサインイン時に作成され、ユーザー一覧に LDAP または SSO と表示されます。これらには WatchZit のパスワードはありません。ディレクトリがサインインを許可しても締め出したい場合は、WatchZit でアカウントを無効にしてください。

設定

  • ネットワークとアクセス — コンソールとエージェントのポート、それぞれにアクセスを許可するネットワーク、エージェント用公開アドレス。
  • サインインとセキュリティ — セッションの長さ、何回のサインイン失敗でアドレスをブロックするか、ブロックの解除。
  • 測定データ — 生の値、5 分ごとの値、1 時間ごとの値をどれくらいの期間保持するか、そしてそれらが使用する容量。
  • 証明書 — コンソール独自の証明書、アップロードした証明書、または Let's Encrypt の証明書（下記参照）。
  • カスタム フィールド — デバイス用の独自のフィールド（「デバイス」を参照）。
  • 診断 — ログの場所、フィルター付きのサーバーログの最新行、サポート用の ZIP（ログ、デバイス、エージェント、問題、監査ログ）。ZIP からはパスワード、コミュニティ、トークン、登録コード、鍵が除かれ、保存されたデバイスの設定も含まれません。
  • SNMP、通知、ツール、キオスク表示 — それぞれの章を参照してください。

更新

設定 → アップデートとサーバーには、実行中のバージョンと最新のリリースが表示されます。Linux パッケージでインストールした場合、WatchZit は自身を更新します。

  1. WatchZit のリリースキーで署名ありのリリースだけが受け付けられます。
  2. root ヘルパーがデータベースとプログラムをバックアップし、新しいパッケージをインストールして、コンソールが起動することを確認します。
  3. 起動しない場合は、自動的に以前のバージョンに戻ります。

更新チャネルでは、コンソールがインストールするものを選びます：公式リリース、またはテスト — 公式リリースに先立つリリース候補で、テスト用コンソール向けです。本番のコンソールは公式リリースのままにしてください。

更新はクリックでインストールするか、指定した時間帯に自動でインストールできます。ミラーやローカルフォルダーを更新元にすることもできます（/etc/watchzit/server.env の WATCHZIT_UPDATE_SOURCE）。同じページで、サーバーのタイムゾーンの設定とサービスの再起動も行えます。

インターネットに接続できない場合：ファイルからインストールで、別のコンピューターでダウンロードしたリリースの manifest.json、manifest.json.sig、サーバーパッケージ（.deb または .rpm）をアップロードします。これらはダウンロードと同じように検証され、同じ方法でインストールされます。

オペレーティングシステムと SSH

同じページには、サーバー（Debian、Ubuntu、AlmaLinux、Rocky Linux）の OS の更新も表示されます：待機中の更新の数とそのうちのセキュリティ更新の数、自動セキュリティ更新がオンかどうか、最後に実行された日時です。すべての更新をインストールで今すぐインストールします。再起動が必要な場合はページにそう表示され、サーバーを再起動で再起動できます。一覧は 1 日 2 回自動的に更新されるほか、今すぐ確認でも更新できます。

WatchZit アプライアンスでは、このページでアプライアンスのネットワーク（DHCP または固定アドレス、ゲートウェイ、DNS、名前。アプライアンスとの接続が切れるような設定は 30 秒後に元に戻されます）と SSH（オン／オフとポート。SSH サーバーが受け付けないポートの場合は以前の設定のままになります）も設定できます。その他のサーバーでは、これらはオペレーティングシステム側で設定します。

証明書

初期状態では、コンソールは独自の証明書を使用するため、ブラウザーが警告を表示します。設定 → 証明書で次のいずれかを設定します。

  • 証明書をアップロード：会社の証明書を使います。ブラウザーが使う DNS 名（または IP アドレス）に対する、チェーン付きの証明書と秘密鍵を PEM 形式で（ファイルまたは貼り付けで）指定します。使用前に検証されます。
  • Let's Encrypt：名前とメールアドレスを入力します。Let's Encrypt は、このサーバーの ポート 80（インターネットから到達可能）で名前を確認するか、コンソールが社内にある場合は Cloudflare 経由の DNS レコード（権限 Zone → DNS → Edit を持つ API トークン）で確認します。証明書は有効期限の 30 日前に自動的に更新されます。
  • ポート 80 で待ち受けると、http:// と入力したブラウザーもコンソールへ転送されます。

信頼された証明書は、コンソールをその名前で開いたときに使われます。IP アドレスで開いた場合、コンソールは引き続き独自の証明書を使います。エージェントには影響しません。エージェントは、登録時にピン留めしたエージェント用ポート独自の証明書を使います。標準のポートを使うには、「ネットワークとアクセス」でコンソールのポートを 443 に設定してください。

コンソールのバックアップ

設定 → コンソールのバックアップは、コンソール全体をバックアップします：すべての測定値を含むデータベース、保存されたパスワードの秘密鍵、Launcher の鍵、エージェントが信頼する証明書 — 新しいサーバーが引き継ぐのに必要なすべてです。バックアップは毎日指定した時刻に（および今すぐバックアップで）データディレクトリ内の backups に書き込まれ、最新のもの（既定では 7 個）が保持されます。

  • 暗号化：パスフレーズ（12 文字以上）を設定すると、ファイルは暗号化されます（AES-256-GCM）。パスフレーズは別の場所に保管してください。パスフレーズがないとバックアップを復元できません。
  • SFTP コピー：すべてのバックアップは、別のサーバー上のフォルダーにもコピーされます（パスワードまたは秘密鍵）。最初の SFTP フォルダーをテストで、信頼するサーバーのホストキーが表示されます。コピーはそのキーを持つサーバーにのみ送られます。フォルダーには、サーバーと同じ数のバックアップが保持されます。
  • バックアップ失敗時にメールは、「設定 → 通知」の SMTP サーバーを通じて通知を送ります。
  • 復元はサーバーを停止した状態で実行します：アプライアンスではセットアップメニューの項目コンソールのバックアップを復元を使います。Linux パッケージでは、systemctl stop watchzit-server を実行し、次に /etc/watchzit/server.env を読み込んだ状態でユーザー watchzit として watchzit-server --data-dir /var/lib/watchzit --restore FILE を実行し（暗号化されたバックアップは、パスフレーズを WATCHZIT_BACKUP_PASSPHRASE または --restore-passphrase-file から読み取ります）、その後サーバーを起動します。復元は 1 つのトランザクションですべてを置き換えます。古いバージョンのバックアップは、サーバーの起動時に最新の状態に更新されます。エージェントは同じ証明書を信頼しているため、そのまま動作し続けます。

セキュリティ

  • コンソールは HTTPS のみを使用し、厳格な Content Security Policy とクロスサイトリクエストへの保護を備えています。許可されたネットワークにのみ応答します。
  • パスワードは Argon2id でハッシュ化されます。保存された秘密情報（SNMP、データベース、API のパスワード、通知チャネル）は、サーバーの秘密鍵で暗号化されます。
  • エージェントは自身の鍵で識別されます。エージェントは、ピン留めしたエージェント証明書のフィンガープリントによってサーバーを信頼します。
  • 脆弱性は非公開で報告してください：リポジトリの SECURITY.md を参照してください。
