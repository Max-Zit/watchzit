エージェントのインストール

WatchZit エージェントはオプションです。外部のネットワークからは見えない情報、つまり Windows と Linux コンピューターの CPU、メモリー、ディスク、インターフェース、サービスを、1 本の外向き接続で 1 分ごとに報告します。

登録コード

エージェントで登録コードを作成します。名前、有効日数、使用できるコンピューターの台数、新しいデバイスが入るグループを指定します。コードは一度だけ表示されます。コードにはサーバーのアドレスとエージェント証明書のフィンガープリントが含まれているため、エージェントはお使いのサーバーだけを信頼します。

Windows

エージェントのページから MSI をダウンロードしてインストールします。インストール中にコードの入力を求められます。多数のコンピューターにはサイレントインストールを使います（GPO、Intune、スクリプト）。

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

エージェントはサービス WatchZitAgent として動作します。

Linux

エージェントのページには、エージェント用ポートからエージェントをダウンロードし、SHA-256 を確認して、コードを使ってインストールするコマンドが表示されます（systemd サービス watchzit-agent）。

curl -fsSk https://<サーバー>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

または、リリースの deb または rpm パッケージ（amd64 と arm64、GitHub から入手）をインストールしてから、登録して起動します。更新はパッケージマネージャー、またはエージェント自身の更新機能で行われます。

sudo apt install ./watchzit-agent_<バージョン>_amd64.deb      # または: sudo dnf install ./watchzit-agent-<バージョン>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

エージェントが報告する内容

  • CPU 負荷（Linux ではロードアベレージも）、メモリーとスワップ、すべてのディスク、すべてのネットワークインターフェースとそのトラフィック。これらは自動的にグラフ付きのチェックになります。
  • インベントリ：オペレーティングシステム、CPU モデル、メモリー、ベンダー、モデル、シリアル番号、アドレス、サービス。
  • Hyper-V のマシン（Windows）と Docker コンテナー（Linux）を 5 分ごとに、その状態、CPU、メモリー、アドレスとともに報告します。これらはデバイスページと、マップ上のハイパーバイザーボックスに表示されます。
  • 監視対象のサービス：デバイスページのサービスを監視で選びます。サービスが停止すると問題が発生します。
  • 監視対象のプロセス：デバイスページのプロセスを監視でプログラム名を入力します（例：nginx, sqlservr.exe, java）。それぞれに、実行数、CPU、メモリーを測るチェックが作成され、1 つも実行されていなければ問題が発生します。
  • システムのエラーメッセージ — Windows のシステムログと Application ログの重大イベントとエラーイベント、および systemd ジャーナルの優先度 err 以上のメッセージ — は、報告のたびにログ（種類エージェント）に送られます。ソースをエージェントにしたログトリガーで、これらから問題を発生させられます。

同じアドレスまたは名前のデバイスが存在する場合、エージェントはそのデバイスに統合されます。存在しない場合は新しいデバイスが作成されます。

エージェントの更新

サーバーより古いエージェントは、接続時に（最大で 1 時間に 1 回）サーバーと同じバージョンのエージェントを受け取ります。エージェントは自身の暗号化・ピン留めされた接続でサーバーからインストーラーをダウンロードし、サイズと SHA-256 を確認してインストールします。MSI でインストールした Windows エージェントは新しい MSI を実行し、Linux エージェント（systemd）は新しいプログラムが起動することを確認してから自身を置き換え、systemd によって再起動されます。エージェントページには古いエージェントが表示されます。管理者はそこでエージェントの更新から自動更新をオフにしたり、オンラインのすべてのエージェントをワンクリックで更新したりできます。1.2 より前のエージェントは更新機能を持たないため、一度だけ手動で更新してください。

リモートコレクター

別のネットワーク — 支社、NAT の内側にある顧客拠点、閉じた管理用 VLAN — にあるデバイスには、コンソールから到達できないことがよくあります。そのネットワーク内の任意のコンピューター（Linux または Windows。小さな VM や Raspberry Pi クラスのマシンで十分です）にエージェントをインストールし、そのデバイスページのエージェントボックスでリモートコレクターとして使用をクリックします。次に、そのネットワークのデバイスで監視元としてそれを選びます（多数のデバイスをまとめて設定するには、デバイス一覧の選択したものを変更を使います）。コレクターはそれらのチェック — Ping、TCP、SNMP、Web ページとシナリオ、証明書、DNS、データベース、RouterOS、JSON API — を、必要なパスワードや SNMP 設定とともに受け取り、それぞれの間隔で実行して、自身の暗号化された接続で結果を送信します。拠点で開けるポートは不要で、コレクター自体に Web インターフェースはありません。設定はすべてコンソールで行います。

コンソールとの接続が切れている間も、コレクターはチェックを実行し続けます。結果（最大 1 日分、最新の 200,000 件）はコレクター上で待機し、接続が戻ると送信されるため、グラフに欠落は生じません。その間、そのデバイスのチェックはダウンではなく不明と表示され（拠点自体は正常な可能性があるため）、コレクターのエージェントチェックで問題が発生します。保持された結果はコレクターの再起動後には残りません。コレクターはコンソールからチェックを再取得します。

予備コレクター：拠点の 2 台目のコンピューターにエージェントをインストールし、これもコレクターにして、監視元の横の予備で選びます（多数のデバイスにはデバイス一覧の選択したものを変更 → 予備コレクターを使います）。1 台目がオフラインの間は予備がチェックを実行し、1 台目が戻ると再び 1 台目が引き継ぎます。

検出と SNMP：デバイス → 検出で、新しい範囲の横でコレクターを選びます。コレクターは自身の拠点のそのネットワークをスキャンし、そこから追加したデバイスはそのコレクターから監視されます。デバイスページの SNMP 検出や、ファクト、インターフェース、VLAN の読み取りもコレクターを経由します。ハイパーバイザーのチェックはコンソールに残ります。収集を停止すると、デバイスはコンソールに戻ります。

ネットワーク

エージェントはエージェント用ポート 8444 に接続します。エージェントが別の名前でサーバーに到達する場合（たとえばファイアウォール経由）は、設定 → ネットワークとアクセスでエージェント用公開アドレスを設定し、エージェントの接続を許可するネットワークを制限してください。

デバイスページでエージェントを削除すると、その鍵は不明なものになります。エージェントを再び使うには、新しいコードでコンピューターを登録してください。
