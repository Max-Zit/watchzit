API REST

Script e altri sistemi leggono dispositivi, controlli, grafici e problemi, prendono in carico i problemi e pianificano manutenzioni tramite un'API JSON.

Token

Crea un token in Il mio account → Token API: un nome e per quanti giorni è valido. Viene mostrato una sola volta. Un token agisce come te, con il tuo ruolo (il token di un osservatore può solo leggere); revocalo quando non serve più. I token errati contano come accessi falliti e bloccano l'indirizzo per un po'.

Invialo in un'intestazione; l'API non accetta mai il cookie di sessione della console:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Endpoint

RichiestaRisposta
GET /api/v1/statusversione, dispositivi per stato, problemi aperti per gravità
GET /api/v1/devicesdispositivi; filtri q, status, group
GET /api/v1/devices/{id}un dispositivo con i suoi controlli e gli id delle loro serie
GET /api/v1/series/{id}?range=24hi punti di una serie: ora, minimo, media, massimo
GET /api/v1/problemsproblemi aperti; view=history, severity, device
POST /api/v1/problems/{id}/ackprendi in carico: {"note": "…"}
GET /api/v1/maintenancefinestre di manutenzione
POST /api/v1/maintenancepianificane una: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Gli orari sono in formato RFC 3339 (2026-11-01T22:00:00+01:00). Gli errori sono {"error": "…"} con lo stato HTTP corrispondente. Le modifiche vengono scritte nel registro di controllo con il nome del token.
