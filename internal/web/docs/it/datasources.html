Origini dati

Grafici e dashboard possono mostrare anche serie temporali esterne a WatchZit: tabelle dei tuoi database, Prometheus, InfluxDB o qualsiasi indirizzo che risponda in JSON, accanto ai valori di agenti e controlli.

Aggiungere un'origine dati

Gli amministratori aggiungono le origini dati in Impostazioni → Origini dati:

GenereIndirizzoAccesso
PostgreSQLhost o host:porta (5432), e il databaseutente e password
MySQL / MariaDBhost o host:porta (3306), e il databaseutente e password
Microsoft SQL Serverhost o host:porta (1433), e il databaseutente e password di SQL Server
Prometheusl'URL, ad esempio http://prometheus:9090; anche Thanos, VictoriaMetrics, Mimirnessuno, utente e password, o un bearer token
InfluxDBl'URL, ad esempio http://influx:8086, e il database (InfluxDB 2/3: il bucket)InfluxDB 1: utente e password; 2 e 3: solo il token
JSON su HTTPl'URL di base del tuo servizionessuno, utente e password, o un bearer token

Prova connessione prova le impostazioni senza salvarle. La password o il token vengono salvati cifrati e non vengono mai più mostrati; lascia il campo vuoto per mantenerli.

Per i database SQL scegli la cifratura: quando il server la offre (predefinito), sempre con qualsiasi certificato, sempre con un certificato attendibile, oppure mai. Per gli indirizzi https:// si può accettare un certificato autofirmato.

Assegna alla console un utente che possa solo leggere le tabelle di cui ha bisogno. WatchZit esegue le query PostgreSQL e MySQL in una transazione di sola lettura; SQL Server non ha nulla di simile, quindi lì solo i permessi dell'utente proteggono i dati. Gli operatori scrivono le query; gli osservatori vedono solo i grafici.

Query nei grafici

Sulla pagina di un dispositivo fai clic su Modifica grafici, poi su ✎ su un grafico o su Aggiungi grafico. In Origini dati fai clic su Aggiungi query, scegli l'origine dati e scrivi la query. Prova la esegue sul periodo della pagina e indica le serie che restituisce (con il loro numero di punti) o l'errore del database. Un grafico può mostrare fino a 6 query accanto ai valori del dispositivo, ognuna con un nome di serie, un'unità e un colore.

Nelle dashboard aggiungi il widget Grafico da un'origine dati.

Le risposte vengono conservate per 20 secondi, così una dashboard su più schermi interroga il database una sola volta. Una query restituisce al massimo 200.000 righe e 50 serie e può durare 20 secondi; i valori vengono sfoltiti in base alla larghezza del grafico.

SQL (PostgreSQL, MySQL, SQL Server)

La query restituisce una colonna temporale (chiamata time, oppure la prima colonna che contiene orari; vanno bene anche secondi o millisecondi Unix), una o più colonne numeriche (una serie ciascuna) e, facoltativamente, una colonna di testo che dà il nome alla serie (metric, oppure la prima colonna di testo) per le tabelle con una riga per serie e orario. Ordina per tempo.

Le macro inseriscono nella query il periodo del grafico:

MacroDiventa
$__timeFilter(col)col tra l'inizio e la fine del periodo
$__timeGroup(col)col arrotondato per difetto all'intervallo del grafico; $__timeGroup(col, 300) a 5 minuti
$__timeFrom, $__timeTol'inizio e la fine come orario
$__unixFrom, $__unixTol'inizio e la fine in secondi Unix
$__interval_sl'intervallo del grafico in secondi

Esempi:

-- orders per interval (PostgreSQL, MySQL, SQL Server alike)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- one series per warehouse
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Scrivi PromQL, ad esempio rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Ogni serie prende il nome così come lo scrive Prometheus (name{label="value"}); un nome di serie nell'editor lo sostituisce. Il passo segue la larghezza del grafico.

InfluxDB

Scrivi InfluxQL con $timeFilter e $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

InfluxDB 2 e 3 rispondono a InfluxQL tramite la loro API 1.x: lì associa il bucket a un database, se non è ancora associato.

JSON su HTTP

La query è un percorso o dei parametri aggiunti all'indirizzo (ad esempio /api/temps?room=server); WatchZit aggiunge from, to e step in secondi Unix e legge una qualsiasi di queste risposte (orari in secondi o millisecondi):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
