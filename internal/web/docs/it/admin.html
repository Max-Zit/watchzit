Utenti, impostazioni e aggiornamenti

Chi può fare cosa, come è protetta la console e come WatchZit resta aggiornato.

Utenti e ruoli

RuoloPuò
Amministratoretutto, inclusi utenti e impostazioni
Operatoregestire dispositivi, controlli, mappe, trigger, manutenzioni, dashboard
Osservatoresolo guardare

Ogni utente accede con una password e l'accesso a due fattori (un'app di autenticazione); i codici di recupero aiutano quando si perde il telefono. Gli amministratori aggiungono utenti in Utenti e reimpostano password e accesso a due fattori. Il Registro di controllo registra ogni modifica; le sue voci sono concatenate, così qualsiasi alterazione del registro diventa visibile.

Active Directory / LDAP e single sign-on

Oltre agli account locali, gli utenti possono accedere con un account della directory. Gli account locali continuano sempre a funzionare, così un amministratore può accedere anche quando la directory o l'identity provider non sono disponibili. Un nome utente che appartiene a un account locale non viene mai rilevato da un accesso tramite directory.

  • Active Directory / LDAP (Impostazioni → Active Directory / LDAP): il server (ldaps://dc1.example.local, oppure ldap:// con StartTLS; le password non attraversano mai la rete in chiaro), facoltativamente il certificato di una CA aziendale, un account di servizio che possa leggere utenti e gruppi, il DN di base e il filtro utenti (Active Directory (&(objectClass=user)(sAMAccountName={username}))). Su Active Directory vengono seguiti i gruppi annidati. La directory verifica la password; WatchZit chiede comunque il proprio secondo fattore. Test verifica un account senza accedere e mostra i gruppi e il ruolo che otterrebbe.
  • Single sign-on (Impostazioni → Single sign-on): OpenID Connect (Microsoft Entra ID, Google, Okta, Keycloak …: l'issuer, il client ID e il secret; registra https://<console>/login/sso/callback come redirect URI) oppure SAML 2.0 (ADFS, Entra ID, Okta …: l'URL o l'XML dei metadati dell'identity provider; fornisci all'identity provider https://<console>/login/sso/metadata, l'indirizzo di risposta è /login/sso/saml). La pagina di accesso riceve un pulsante. Il secondo fattore di WatchZit viene richiesto anche solo se lo spunti; altrimenti decide la policy dell'identity provider.
  • Gruppi e ruoli: a ogni accesso i gruppi decidono il ruolo (amministratori, operatori o osservatori; vince il più alto), e gli utenti che non appartengono a nessuno dei gruppi ricevono il ruolo predefinito oppure non possono accedere. Un gruppo è il suo nome o il DN completo, oppure il nome o l'ID inviato dall'identity provider (Entra ID invia ID).
  • Gli account della directory vengono creati al primo accesso e mostrano LDAP o SSO nell'elenco utenti. Non hanno una password WatchZit; disattivali in WatchZit per tenerli fuori anche se la directory li lascia entrare.

Impostazioni

  • Rete e accesso: le porte della console e degli agenti, le reti autorizzate a raggiungere ciascuna, l'indirizzo pubblico per gli agenti.
  • Accesso e sicurezza: durata della sessione, quanti accessi falliti bloccano un indirizzo e la rimozione di un blocco.
  • Dati di misura: per quanto tempo vengono conservati i valori grezzi, a 5 minuti e orari, e quanto spazio occupano.
  • Certificato: il certificato proprio della console, uno caricato da te o uno di Let's Encrypt (vedi sotto).
  • Campi personalizzati: i tuoi campi per i dispositivi (vedi Dispositivi).
  • Diagnostica: dove si trovano i log, le righe più recenti del log del server con un filtro e uno ZIP per l'assistenza (log, dispositivi, agenti, problemi, registro di controllo) da cui sono rimossi password, community, token, codici di registrazione e chiavi; le configurazioni dei dispositivi salvate non sono incluse.
  • SNMP, Notifiche, Strumenti, Schermi kiosk: vedi i rispettivi capitoli.

Aggiornamenti

Impostazioni → Aggiornamenti e server mostra la versione in esecuzione e l'ultima versione pubblicata. Se installato con i pacchetti Linux, WatchZit si aggiorna da solo:

  1. Vengono accettate solo versioni firmate con la chiave di rilascio di WatchZit.
  2. L'helper con privilegi di root esegue il backup del database e del programma, installa il nuovo pacchetto e verifica che la console si avvii.
  3. Se non si avvia, torna da solo alla versione precedente.

Il Canale di aggiornamento sceglie cosa installa la console: Versioni ufficiali, oppure test (release candidate che precedono una versione ufficiale, per una console di prova). Tieni le console di produzione sulle versioni ufficiali.

Gli aggiornamenti si possono installare con un clic o automaticamente a un'ora scelta. Un mirror o una cartella locale possono fare da origine (WATCHZIT_UPDATE_SOURCE in /etc/watchzit/server.env). La stessa pagina imposta il fuso orario del server e riavvia il servizio.

Senza accesso a internet: in Installa da file carica manifest.json, manifest.json.sig e il pacchetto del server (.deb o .rpm) di una versione, scaricati su un altro computer. Vengono verificati come un download e installati allo stesso modo.

Sistema operativo e SSH

La stessa pagina mostra gli Aggiornamenti del sistema operativo del server (Debian, Ubuntu, AlmaLinux, Rocky Linux): quanti sono in attesa e quanti sono di sicurezza, se gli aggiornamenti di sicurezza automatici sono attivi e quando sono stati eseguiti l'ultima volta. Installa tutti gli aggiornamenti li installa subito; se richiedono un riavvio, la pagina lo segnala e Riavvia il server lo riavvia. L'elenco si aggiorna da solo due volte al giorno, oppure con Verifica ora.

Sull'appliance WatchZit la pagina imposta anche la rete (DHCP o un indirizzo fisso, gateway, DNS, nome; le impostazioni che isolano l'appliance vengono annullate dopo 30 secondi) e SSH: attivo o no e la sua porta; una porta rifiutata dal server SSH mantiene l'impostazione precedente. Sugli altri server queste impostazioni spettano al sistema operativo. L'SSH dell'appliance non consente l'accesso come root né l'inoltro (nessun tunnel SSH attraverso di essa).

Certificato

Di serie la console usa un proprio certificato, per il quale i browser mostrano un avviso. In Impostazioni → Certificato:

  • Carica un certificato della tua azienda: il certificato con la sua catena e la chiave privata in formato PEM (file o testo incollato), per il nome DNS (o l'indirizzo IP) usato dai browser. Viene verificato prima di essere usato.
  • Let's Encrypt: inserisci il nome e un indirizzo email. Let's Encrypt verifica il nome tramite la porta 80 di questo server (raggiungibile da internet) oppure, se la console è interna, con un record DNS tramite Cloudflare (un token API con il permesso Zone → DNS → Edit). Il certificato si rinnova da solo 30 giorni prima della scadenza.
  • Servi la porta 80 indirizza inoltre alla console i browser che digitano http://.

Il certificato attendibile viene servito quando la console è aperta tramite il suo nome; se aperta tramite indirizzo IP, la console continua a usare il proprio certificato. Gli agenti non sono interessati: usano il certificato proprio della porta degli agenti, che hanno vincolato al momento della registrazione. Per usare la porta standard, imposta la porta della console su 443 in Rete e accesso.

Backup della console

Impostazioni → Backup della console esegue il backup dell'intera console: il database con tutte le misure, la chiave segreta delle password salvate, la chiave del launcher e i certificati di cui si fidano gli agenti; tutto ciò che serve a un nuovo server per subentrare. I backup vengono scritti in backups nella directory dei dati ogni giorno all'ora scelta (e con Backup ora); vengono conservati i più recenti (7 di default).

  • Cifratura: con una passphrase (almeno 12 caratteri) il file viene cifrato (AES-256-GCM). Conserva la passphrase altrove: senza di essa un backup non si può ripristinare.
  • Copia SFTP: ogni backup viene copiato anche in una cartella su un altro server (password o chiave privata). Il primo Prova la cartella SFTP mostra la chiave host del server da considerare attendibile; le copie vanno solo a un server con quella chiave. La cartella conserva tanti backup quanti il server.
  • Email se un backup fallisce invia un avviso tramite il server SMTP di Impostazioni → Notifiche.
  • Il Ripristino si esegue con il server fermo: sull'appliance con la voce di menu Ripristina un backup della console; con i pacchetti Linux systemctl stop watchzit-server, poi watchzit-server --data-dir /var/lib/watchzit --restore FILE come utente watchzit con /etc/watchzit/server.env caricato (un backup cifrato legge la passphrase da WATCHZIT_BACKUP_PASSPHRASE o da --restore-passphrase-file), quindi avvia il server. Il ripristino sostituisce tutto in un'unica transazione; un backup di una versione precedente viene aggiornato all'avvio del server. Gli agenti continuano a funzionare: si fidano dello stesso certificato.

Sicurezza

  • La console usa solo HTTPS, una Content Security Policy rigorosa e una protezione contro le richieste cross-site; risponde solo alle reti autorizzate.
  • Le password sono sottoposte a hash con Argon2id; i segreti salvati (password di SNMP, database e API, canali) sono cifrati con la chiave segreta del server.
  • Gli agenti sono identificati dalla propria chiave; si fidano del server tramite l'impronta vincolata del suo certificato degli agenti.
  • Segnala le vulnerabilità in modo riservato: vedi SECURITY.md nel repository.
