Instalar agentes

O agente WatchZit é opcional. Comunica o que a rede não consegue ver de fora: CPU, memória, discos, interfaces e serviços de computadores Windows e Linux, a cada minuto, através de uma única ligação de saída.

Códigos de registro

Em Agentes crie um código de registro: um nome, quantos dias é válido, quantos computadores o podem usar e o grupo para onde vão os novos dispositivos. O código é mostrado uma única vez; contém o endereço do servidor e a impressão digital do certificado dos agentes, para que o agente só confie no seu servidor.

Windows

Transfira o MSI a partir da página Agentes e instale-o; ele pede o código. Para muitos computadores, instale-o de forma silenciosa (GPO, Intune, um script):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

O agente corre como o serviço WatchZitAgent.

Linux

A página Agentes mostra um comando que transfere o agente a partir da porta dos agentes, verifica o seu SHA-256 e instala-o com o código (serviço systemd watchzit-agent):

curl -fsSk https://<servidor>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Em alternativa, instale o pacote deb ou rpm da versão (amd64 e arm64, a partir do GitHub) e depois registe-o e inicie-o; as atualizações chegam através do gestor de pacotes ou das atualizações do próprio agente:

sudo apt install ./watchzit-agent_<versão>_amd64.deb      # ou: sudo dnf install ./watchzit-agent-<versão>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

O que o agente comunica

  • Carga da CPU (e a carga média no Linux), Memória e swap, cada Disco, cada interface de rede com o tráfego — tornam-se verificações com gráficos automaticamente.
  • Inventário: sistema operativo, modelo da CPU, memória, fabricante, modelo, número de série, endereços, serviços.
  • Máquinas Hyper-V (Windows) e contentores Docker (Linux), a cada cinco minutos, com o estado, CPU, memória e endereços; aparecem na página do dispositivo e nas caixas de hipervisor dos mapas.
  • Serviços vigiados: escolha-os na página do dispositivo em Vigiar serviços; um serviço que pare abre um problema.
  • Processos vigiados: em Vigiar processos na página do dispositivo introduza nomes de programas (por exemplo nginx, sqlservr.exe, java); cada um recebe uma verificação com quantos estão em execução, a sua CPU e memória, e se nenhum estiver em execução abre-se um problema.
  • Mensagens de erro do sistema — eventos críticos e de erro dos logs Sistema e Application do Windows, e mensagens de prioridade err ou pior do journal do systemd — vão para Registos (tipo Agentes) com cada relatório; um gatilho de log com a origem Agentes abre problemas a partir delas.

Se já existir um dispositivo com o mesmo endereço ou nome, o agente junta-se a ele; caso contrário é criado um novo dispositivo.

Atualizações dos agentes

Um agente mais antigo do que o servidor recebe o agente da versão do servidor quando se liga (no máximo uma vez por hora): transfere o instalador do servidor através da sua própria ligação cifrada e fixada, verifica o tamanho e o SHA-256 e instala-o. Os agentes Windows instalados com o MSI executam o novo MSI; os agentes Linux (systemd) verificam que o novo programa arranca, substituem-se a si próprios e são reiniciados pelo systemd. A página Agentes assinala os agentes mais antigos; aí, os administradores desligam as atualizações automáticas em Atualizações dos agentes e atualizam todos os agentes online com um clique. Os agentes anteriores à 1.2 ainda não conhecem as atualizações e são atualizados uma vez à mão.

Coletores remotos

Um dispositivo noutra rede — uma filial, o local de um cliente atrás de NAT, uma VLAN de gestão fechada — muitas vezes não é alcançável a partir da consola. Instale o agente num computador qualquer desse local (Linux ou Windows; basta uma pequena VM ou uma máquina da classe Raspberry Pi) e clique em Usar como coletor remoto na caixa Agente da página desse dispositivo. Depois escolha-o em Monitorado a partir de nos dispositivos dessa rede (ou para muitos de uma vez na lista de dispositivos em Alterar selecionados). O coletor recebe as verificações deles — ping, TCP, SNMP, páginas e cenários web, certificados, DNS, bases de dados, RouterOS, APIs JSON — com as palavras-passe e definições SNMP de que precisam, executa-as nos respetivos intervalos e envia os resultados pela sua própria ligação cifrada. Não precisa de nenhuma porta aberta no local nem tem interface web própria; tudo é configurado na consola.

Enquanto a ligação à consola estiver em baixo, o coletor continua a executar as verificações; os resultados (até um dia, os 200 000 mais recentes) ficam à espera nele e chegam quando a ligação regressa, pelo que os gráficos não ficam com falhas. Entretanto, as verificações dos seus dispositivos mostram Desconhecido em vez de em baixo (o local pode estar bem), e a verificação de agente do coletor abre um problema. Os resultados guardados não sobrevivem a um reinício do coletor: este volta a receber as suas verificações da consola.

Coletor de reserva: instale o agente num segundo computador do local, faça dele também um coletor e escolha-o como Reserva junto a Monitorado a partir de (ou para muitos dispositivos na lista de dispositivos em Alterar selecionados → Coletor de reserva). Enquanto o primeiro estiver offline, o de reserva executa as verificações; quando o primeiro regressa, volta a assumi-las.

Descoberta e SNMP: em Dispositivos → Descoberta escolha o coletor junto a um novo intervalo: ele analisa essa rede do seu local, e os dispositivos que adicionar a partir daí são monitorados por ele. A descoberta SNMP na página do dispositivo e a leitura de dados, interfaces e VLAN também passam pelo coletor. As verificações de hipervisor ficam na consola. Parar a coleta devolve os dispositivos à consola.

Rede

Os agentes ligam-se à porta dos agentes 8444. Em Configurações → Rede e acesso defina o Endereço público para agentes quando os agentes chegam ao servidor por outro nome (por exemplo, através de uma firewall), e limite as redes de onde os agentes podem vir.

Remover o agente na página do dispositivo torna a sua chave desconhecida; para voltar a usar o agente, registe o computador com um novo código.
