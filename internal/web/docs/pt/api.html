API REST

Scripts e outros sistemas leem dispositivos, verificações, gráficos e problemas, reconhecem problemas e planeiam manutenções através de uma API JSON.

Tokens

Crie um token em Minha conta → Tokens de API: um nome e quantos dias é válido. É mostrado uma única vez. Um token age em seu nome, com a sua função (o token de um observador só pode ler); revogue-o quando já não for necessário. Tokens inválidos contam como inícios de sessão falhados e bloqueiam o endereço durante algum tempo.

Envie-o num cabeçalho; a API nunca aceita o cookie de sessão da consola:

curl -H "Authorization: Bearer wzat_…" https://monitor.example.com:8443/api/v1/status

Endpoints

PedidoResposta
GET /api/v1/statusversão, dispositivos por estado, problemas abertos por gravidade
GET /api/v1/devicesdispositivos; filtros q, status, group
GET /api/v1/devices/{id}um dispositivo com as suas verificações e os ids das respetivas séries
GET /api/v1/series/{id}?range=24hos pontos de uma série: tempo, mínimo, média, máximo
GET /api/v1/problemsproblemas abertos; view=history, severity, device
POST /api/v1/problems/{id}/ackreconhecer: {"note": "…"}
GET /api/v1/maintenancejanelas de manutenção
POST /api/v1/maintenanceplanear uma: {"name", "starts_at", "ends_at", "device_ids", "group_ids"}

Os tempos estão em RFC 3339 (2026-11-01T22:00:00+01:00). Os erros são {"error": "…"} com o estado HTTP correspondente. As alterações ficam registadas no log de auditoria com o nome do token.
