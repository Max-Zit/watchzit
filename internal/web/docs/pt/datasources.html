Fontes de dados

Os gráficos e os painéis também podem mostrar séries temporais de fora do WatchZit: tabelas das suas próprias bases de dados, Prometheus, InfluxDB ou qualquer endereço que responda em JSON — ao lado dos valores dos agentes e das verificações.

Adicionar uma fonte de dados

Os administradores adicionam fontes de dados em Configurações → Fontes de dados:

TipoEndereçoAutenticação

MySQL / MariaDBanfitrião ou anfitrião:porta (3306), e a base de dadosutilizador e palavra-passe
Microsoft SQL Serveranfitrião ou anfitrião:porta (1433), e a base de dadosutilizador e palavra-passe do SQL Server

InfluxDBo URL, por exemplo http://influx:8086, e a base de dados (InfluxDB 2/3: o bucket)InfluxDB 1: utilizador e palavra-passe; 2 e 3: apenas o token

Testar ligação experimenta as definições sem as guardar. A palavra-passe ou o token é guardado cifrado e nunca volta a ser mostrado; deixe o campo vazio para o manter.

Para bases de dados SQL escolha a cifragem: quando o servidor a oferece (predefinição), sempre com qualquer certificado, sempre com um certificado confiável, ou nunca. Para endereços com https:// pode ser aceite um certificado autoassinado.

Dê à consola um utilizador que só possa ler as tabelas de que precisa. O WatchZit executa as consultas PostgreSQL e MySQL numa transação só de leitura; o SQL Server não tem nada parecido, por isso aí apenas os direitos do utilizador protegem os dados. Os operadores escrevem consultas; os observadores apenas veem os gráficos.

Consultas nos gráficos

Na página de um dispositivo clique em Editar gráficos e depois em ✎ num gráfico ou em Adicionar gráfico. Em Fontes de dados clique em Adicionar consulta, escolha a fonte de dados e escreva a consulta. Experimentar executa-a sobre o intervalo de tempo da página e indica as séries que devolve (com o respetivo número de pontos) ou o erro da base de dados. Um gráfico pode mostrar até 6 consultas ao lado dos valores do dispositivo, cada uma com um nome de série, uma unidade e uma cor.

Nos painéis adicione o widget Gráfico de uma fonte de dados.

As respostas são guardadas durante 20 segundos, por isso um painel em vários ecrãs consulta a base de dados uma só vez. Uma consulta devolve no máximo 200 000 linhas e 50 séries e pode demorar até 20 segundos; os valores são reduzidos à largura do gráfico.

SQL (PostgreSQL, MySQL, SQL Server)

A consulta devolve uma coluna de tempo (chamada time, ou a primeira coluna que contém tempos; segundos ou milissegundos Unix também funcionam), uma ou mais colunas numéricas (uma série cada) e, opcionalmente, uma coluna de texto que dá nome às séries (metric, ou a primeira coluna de texto) para tabelas com uma linha por série e por tempo. Ordene por tempo.

As macros colocam o intervalo de tempo do gráfico na consulta:

MacroTorna-se
$__timeFilter(col)col entre o início e o fim do intervalo
$__timeGroup(col)col arredondado para baixo ao intervalo do gráfico; $__timeGroup(col, 300) a 5 minutos
$__timeFrom, $__timeToo início e o fim como tempo
$__unixFrom, $__unixToo início e o fim em segundos Unix
$__interval_so intervalo do gráfico em segundos

Exemplos:

-- encomendas por intervalo (igual em PostgreSQL, MySQL e SQL Server)
SELECT $__timeGroup(created_at) AS time, count(*) AS orders
FROM orders WHERE $__timeFilter(created_at)
GROUP BY 1 ORDER BY 1

-- uma série por armazém
SELECT $__timeGroup(ts) AS time, warehouse AS metric, avg(temp) AS value
FROM sensor_readings WHERE $__timeFilter(ts)
GROUP BY 1, 2 ORDER BY 1

Prometheus

Escreva PromQL, por exemplo rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8. Cada série recebe o nome que o Prometheus lhe dá (name{label="value"}); um nome de série no editor substitui-o. O passo acompanha a largura do gráfico.

InfluxDB

Escreva InfluxQL com $timeFilter e $__interval:

SELECT mean("usage_idle") FROM "cpu" WHERE $timeFilter GROUP BY time($__interval), "host"

O InfluxDB 2 e 3 respondem a InfluxQL através da sua API 1.x: mapeie aí o bucket para uma base de dados, se ainda não estiver mapeado.

JSON por HTTP

A consulta é um caminho ou parâmetros acrescentados ao endereço (por exemplo /api/temps?room=server); o WatchZit acrescenta from, to e step em segundos Unix e lê qualquer uma destas respostas (tempos em segundos ou milissegundos):

[{"target": "temp", "datapoints": [[21.5, 1793268000000], ...]}, ...]
{"temp": [[1793268000, 21.5], ...], "humidity": [[1793268000, 40], ...]}
[[1793268000, 21.5], [1793268060, 21.7], ...]
