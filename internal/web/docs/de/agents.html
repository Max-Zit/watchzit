Agenten installieren

Der WatchZit-Agent ist optional. Er meldet, was das Netzwerk von außen nicht sehen kann: CPU, Arbeitsspeicher, Datenträger, Schnittstellen und Dienste von Windows- und Linux-Computern, jede Minute, über eine einzige ausgehende Verbindung.

Registrierungscodes

Legen Sie unter Agenten einen Registrierungscode an: einen Namen, wie viele Tage er gültig ist, wie viele Computer ihn verwenden dürfen und die Gruppe, in die neue Geräte kommen. Der Code wird einmal angezeigt; er enthält die Serveradresse und den Fingerabdruck des Agenten-Zertifikats, sodass der Agent nur Ihrem Server vertraut.

Windows

Laden Sie das MSI von der Seite Agenten herunter und installieren Sie es; es fragt nach dem Code. Für viele Computer installieren Sie es unbeaufsichtigt (GPO, Intune, ein Skript):

msiexec /i watchzit-agent-x64.msi ENROLLCODE="WZ1-…" /qn

Der Agent läuft als Dienst WatchZitAgent.

Linux

Die Seite Agenten zeigt einen Befehl, der den Agenten vom Agenten-Port herunterlädt, seine SHA-256-Prüfsumme kontrolliert und ihn mit dem Code installiert (systemd-Dienst watchzit-agent):

curl -fsSk https://<server>:8444/agent/download/watchzit-agent-linux-amd64 -o /tmp/watchzit-agent && … sudo /tmp/watchzit-agent install --code "WZ1-…"

Oder installieren Sie das deb- oder rpm-Paket der Version (amd64 und arm64, von GitHub), registrieren Sie den Agenten und starten Sie ihn; Updates kommen über den Paketmanager oder die eigenen Updates des Agenten:

sudo apt install ./watchzit-agent_<version>_amd64.deb      # oder: sudo dnf install ./watchzit-agent-<version>-1.x86_64.rpm
sudo watchzit-agent enroll --code "WZ1-…"
sudo systemctl start watchzit-agent

Was der Agent meldet

  • CPU-Last (unter Linux auch die Load Average), Arbeitsspeicher und Swap, jeden Datenträger, jede Netzwerkschnittstelle mit Datenverkehr — daraus werden von selbst Prüfungen mit Diagrammen.
  • Inventar: Betriebssystem, CPU-Modell, Arbeitsspeicher, Hersteller, Modell, Seriennummer, Adressen, Dienste.
  • Hyper-V-Maschinen (Windows) und Docker-Container (Linux), alle fünf Minuten, mit Zustand, CPU, Arbeitsspeicher und Adressen; sie erscheinen auf der Geräteseite und in Hypervisor-Kästen auf Karten.
  • Überwachte Dienste: Wählen Sie sie auf der Geräteseite unter Dienste überwachen; ein Dienst, der stoppt, öffnet ein Problem.
  • Überwachte Prozesse: Geben Sie unter Prozesse überwachen auf der Geräteseite Programmnamen ein (zum Beispiel nginx, sqlservr.exe, java); jeder erhält eine Prüfung mit der Anzahl laufender Instanzen, ihrer CPU und ihrem Arbeitsspeicher, und läuft keine, wird ein Problem geöffnet.
  • Fehlermeldungen des Systems — kritische und Fehlerereignisse der Windows-Protokolle System und Application sowie Meldungen der Priorität err und schlimmer aus dem systemd-Journal — gehen mit jeder Meldung an Protokolle (Art Agenten); ein Protokoll-Trigger mit der Quelle Agenten öffnet daraus Probleme.

Gibt es bereits ein Gerät mit derselben Adresse oder demselben Namen, schließt sich der Agent ihm an; andernfalls wird ein neues Gerät angelegt.

Agent-Updates

Ein Agent, der älter ist als der Server, erhält beim Verbinden (höchstens einmal pro Stunde) den Agenten in der Version des Servers: Er lädt das Installationsprogramm über seine eigene verschlüsselte, gepinnte Verbindung vom Server herunter, prüft Größe und SHA-256 und installiert es. Mit dem MSI installierte Windows-Agenten führen das neue MSI aus; Linux-Agenten (systemd) prüfen, ob das neue Programm startet, ersetzen sich selbst und werden von systemd neu gestartet. Die Seite Agenten kennzeichnet ältere Agenten; Administratoren schalten dort unter Agent-Updates die automatischen Updates aus und aktualisieren alle verbundenen Agenten mit einem Klick. Agenten vor Version 1.2 kennen noch keine Updates und werden einmalig von Hand aktualisiert.

Remote-Kollektoren

Ein Gerät in einem anderen Netzwerk — einer Zweigstelle, einem Kundenstandort hinter NAT, einem abgeschotteten Management-VLAN — ist von der Konsole aus oft nicht erreichbar. Installieren Sie den Agenten auf einem beliebigen Computer dort (Linux oder Windows; eine kleine VM oder ein Gerät der Raspberry-Pi-Klasse genügt) und klicken Sie im Agenten-Kasten seiner Geräteseite auf Als Remote-Kollektor verwenden. Wählen Sie ihn dann bei den Geräten dieses Netzwerks unter Überwacht von (oder für viele auf einmal in der Geräteliste unter Auswahl ändern). Der Kollektor erhält ihre Prüfungen — Ping, TCP, SNMP, Webseiten und Szenarien, Zertifikate, DNS, Datenbanken, RouterOS, JSON-APIs — mit den nötigen Passwörtern und SNMP-Einstellungen, führt sie in ihren Intervallen aus und sendet die Ergebnisse über seine eigene verschlüsselte Verbindung. Er braucht am Standort keinen offenen Port und hat keine eigene Weboberfläche; alles wird in der Konsole eingestellt.

Solange die Verbindung zur Konsole unterbrochen ist, führt der Kollektor die Prüfungen weiter aus; die Ergebnisse (bis zu einem Tag, die neuesten 200.000) warten auf ihm und kommen an, sobald die Verbindung wieder steht, sodass die Diagramme keine Lücke haben. Die Prüfungen seiner Geräte zeigen in der Zwischenzeit unbekannt statt ausgefallen (am Standort kann alles in Ordnung sein), und die Agenten-Prüfung des Kollektors öffnet ein Problem. Zwischengespeicherte Ergebnisse überstehen keinen Neustart des Kollektors: Er erhält seine Prüfungen dann erneut von der Konsole.

Ersatz-Kollektor: Installieren Sie den Agenten auf einem zweiten Computer des Standorts, machen Sie ihn ebenfalls zum Kollektor und wählen Sie ihn als Ersatz neben Überwacht von (oder für viele Geräte in der Geräteliste unter Auswahl ändern → Ersatz-Kollektor). Solange der erste offline ist, führt der Ersatz ihre Prüfungen aus; ist der erste wieder da, übernimmt er sie erneut.

Erkennung und SNMP: Wählen Sie unter Geräte → Erkennung den Kollektor neben einem neuen Bereich: Er scannt dieses Netzwerk seines Standorts, und die Geräte, die Sie daraus hinzufügen, werden von ihm überwacht. Auch die SNMP-Erkennung auf der Geräteseite und das Auslesen von Fakten, Schnittstellen und VLANs laufen über den Kollektor. Hypervisor-Prüfungen bleiben bei der Konsole. Sammeln beenden gibt die Geräte an die Konsole zurück.

Netzwerk

Agenten verbinden sich mit dem Agenten-Port 8444. Legen Sie unter Einstellungen → Netzwerk und Zugriff die öffentliche Agenten-Adresse fest, wenn Agenten den Server unter einem anderen Namen erreichen (zum Beispiel über eine Firewall), und beschränken Sie die Netzwerke, aus denen Agenten kommen dürfen.

Wenn Sie den Agenten auf der Geräteseite entfernen, wird sein Schlüssel unbekannt; um den Agenten wieder zu verwenden, registrieren Sie den Computer mit einem neuen Code.
