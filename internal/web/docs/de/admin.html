Benutzer, Einstellungen und Updates

Wer was darf, wie die Konsole geschützt ist und wie WatchZit auf dem neuesten Stand bleibt.

Betrachternur ansehen

Jeder Benutzer meldet sich mit einem Passwort und der Zwei-Faktor-Anmeldung (einer Authenticator-App) an; Wiederherstellungscodes helfen, wenn das Telefon verloren geht. Administratoren fügen Benutzer unter Benutzer hinzu und setzen Passwörter und die Zwei-Faktor-Anmeldung zurück. Das Prüfprotokoll zeichnet jede Änderung auf; seine Einträge sind verkettet, sodass Änderungen am Protokoll auffallen.

Active Directory / LDAP und Single Sign-On

Neben lokalen Konten können sich Benutzer mit einem Verzeichniskonto anmelden. Lokale Konten funktionieren immer weiter, sodass sich ein Administrator anmelden kann, wenn das Verzeichnis oder der Identitätsanbieter ausgefallen ist. Ein Benutzername, der zu einem lokalen Konto gehört, wird nie durch eine Verzeichnisanmeldung übernommen.

  • Active Directory / LDAP (Einstellungen → Active Directory / LDAP): der Server (ldaps://dc1.example.local oder ldap:// mit StartTLS — Passwörter gehen nie unverschlüsselt über das Netzwerk), optional das CA-Zertifikat einer Unternehmens-CA, ein Dienstkonto, das Benutzer und Gruppen lesen darf, die Basis-DN und der Benutzerfilter (Active Directory (&(objectClass=user)(sAMAccountName={username}))). Verschachtelten Gruppen wird im Active Directory gefolgt. Das Verzeichnis prüft das Passwort; WatchZit fragt trotzdem nach seinem eigenen zweiten Faktor. Test prüft ein Konto, ohne sich anzumelden, und zeigt die Gruppen und die Rolle, die es erhalten würde.
  • Single Sign-On (Einstellungen → Single Sign-On): OpenID Connect (Microsoft Entra ID, Google, Okta, Keycloak …: Aussteller, Client-ID und Geheimnis; registrieren Sie https://<konsole>/login/sso/callback als Weiterleitungs-URI) oder SAML 2.0 (ADFS, Entra ID, Okta …: die Metadaten-URL oder das XML des Identitätsanbieters; geben Sie ihm https://<konsole>/login/sso/metadata, die Antwortadresse ist /login/sso/saml). Die Anmeldeseite erhält eine Schaltfläche. Den eigenen zweiten Faktor von WatchZit fragt die Konsole nur dann zusätzlich ab, wenn Sie das markieren; andernfalls entscheidet die Richtlinie des Identitätsanbieters.
  • Gruppen und Rollen: Bei jeder Anmeldung entscheiden die Gruppen über die Rolle — Administratoren, Operatoren oder Betrachter, die höchste gewinnt —, und Benutzer in keiner der Gruppen erhalten die Standardrolle oder können sich nicht anmelden. Eine Gruppe ist ihr Name oder ihre vollständige DN oder der Name bzw. die ID, die der Identitätsanbieter sendet (Entra ID sendet IDs).
  • Verzeichniskonten werden bei ihrer ersten Anmeldung angelegt und zeigen in der Benutzerliste LDAP oder SSO. Sie haben kein WatchZit-Passwort; deaktivieren Sie sie in WatchZit, um sie auszusperren, auch wenn das Verzeichnis sie hereinlässt.

Einstellungen

  • Netzwerk und Zugriff — die Konsolen- und Agenten-Ports, die Netzwerke, die jeweils zugreifen dürfen, die öffentliche Agenten-Adresse.
  • Anmeldung und Sicherheit — Sitzungsdauer, wie viele fehlgeschlagene Anmeldungen eine Adresse sperren, und das Aufheben einer Sperre.
  • Messdaten — wie lange Rohwerte, 5-Minuten- und Stundenwerte aufbewahrt werden und wie viel Platz sie belegen.
  • Zertifikat — das eigene Zertifikat der Konsole, eines, das Sie hochladen, oder eines von Let's Encrypt (siehe unten).
  • Eigene Felder — Ihre eigenen Felder für Geräte (siehe Geräte).
  • Diagnose — wo die Protokolle liegen, die neuesten Zeilen des Serverprotokolls mit einem Filter und ein ZIP für den Support (Protokolle, Geräte, Agenten, Probleme, Prüfprotokoll), aus dem Passwörter, Communities, Tokens, Registrierungscodes und Schlüssel entfernt sind; gespeicherte Gerätekonfigurationen sind nicht enthalten.
  • SNMP, Benachrichtigungen, Werkzeuge, Kiosk-Anzeigen — siehe die jeweiligen Kapitel.

Updates

Einstellungen → Updates und Server zeigt die laufende Version und die neueste Version. Mit den Linux-Paketen installiert, aktualisiert sich WatchZit selbst:

  1. Nur Versionen, die mit dem WatchZit-Release-Schlüssel signiert sind, werden akzeptiert.
  2. Der root-Helfer sichert die Datenbank und das Programm, installiert das neue Paket und prüft, ob die Konsole startet.
  3. Falls nicht, kehrt er von selbst zur alten Version zurück.

Der Update-Kanal legt fest, was die Konsole installiert: Offizielle Versionen oder Test — Release-Kandidaten, die vor einer offiziellen Version erscheinen, für eine Testkonsole. Belassen Sie Produktionskonsolen auf den offiziellen Versionen.

Updates lassen sich per Klick oder automatisch zu einer gewählten Stunde installieren. Ein Spiegelserver oder ein lokaler Ordner kann die Quelle sein (WATCHZIT_UPDATE_SOURCE in /etc/watchzit/server.env). Auf derselben Seite stellen Sie die Zeitzone des Servers ein und starten den Dienst neu.

Ohne Internetzugang: Laden Sie unter Aus Dateien installieren manifest.json, manifest.json.sig und das Serverpaket (.deb oder .rpm) einer Version hoch, die Sie auf einem anderen Computer heruntergeladen haben. Sie werden wie ein Download geprüft und auf dieselbe Weise installiert.

Betriebssystem und SSH

Dieselbe Seite zeigt die Betriebssystem-Updates des Servers (Debian, Ubuntu, AlmaLinux, Rocky Linux): wie viele anstehen und wie viele davon Sicherheitsupdates sind, ob automatische Sicherheitsupdates eingeschaltet sind und wann sie zuletzt liefen. Alle Updates installieren installiert sie sofort; brauchen sie einen Neustart, sagt die Seite das, und Server neu starten startet ihn neu. Die Liste aktualisiert sich zweimal täglich von selbst oder mit Jetzt prüfen.

Auf der WatchZit-Appliance stellt die Seite außerdem ihr Netzwerk ein (DHCP oder eine feste Adresse, Gateway, DNS, Name — Einstellungen, die die Appliance abschneiden, werden nach 30 Sekunden rückgängig gemacht) sowie SSH: ein oder aus und den Port; ein Port, den der SSH-Server ablehnt, lässt die alte Einstellung bestehen. Auf anderen Servern gehören diese Dinge zum Betriebssystem.

Zertifikat

Ab Werk verwendet die Konsole ihr eigenes Zertifikat, vor dem Browser warnen. Unter Einstellungen → Zertifikat:

  • Zertifikat hochladen: das Zertifikat Ihres Unternehmens mit seiner Kette und dem privaten Schlüssel im PEM-Format (als Dateien oder eingefügt), für den DNS-Namen — oder die IP-Adresse —, den die Browser verwenden. Es wird vor der Verwendung geprüft.
  • Let's Encrypt: Geben Sie den Namen und eine E-Mail-Adresse ein. Let's Encrypt prüft den Namen über Port 80 dieses Servers (aus dem Internet erreichbar) oder, wenn die Konsole intern ist, mit einem DNS-Eintrag über Cloudflare (ein API-Token mit der Berechtigung Zone → DNS → Edit). Das Zertifikat wird 30 Tage vor Ablauf von selbst erneuert.
  • Port 80 bedienen leitet außerdem Browser, die http:// eingeben, zur Konsole weiter.

Das vertrauenswürdige Zertifikat wird ausgeliefert, wenn die Konsole unter ihrem Namen geöffnet wird; über ihre IP-Adresse geöffnet, verwendet die Konsole weiterhin ihr eigenes Zertifikat. Agenten sind nicht betroffen: Sie verwenden das eigene Zertifikat des Agenten-Ports, das sie bei der Registrierung gepinnt haben. Um den Standardport zu verwenden, setzen Sie den Konsolenport unter Netzwerk und Zugriff auf 443.

Konsolensicherung

Einstellungen → Konsolensicherung sichert die ganze Konsole: die Datenbank mit allen Messwerten, den geheimen Schlüssel der gespeicherten Passwörter, den Launcher-Schlüssel und die Zertifikate, denen die Agenten vertrauen — alles, was ein neuer Server zur Übernahme braucht. Sicherungen werden jeden Tag zur gewählten Stunde (und mit Jetzt sichern) nach backups im Datenverzeichnis geschrieben; die neuesten werden aufbewahrt (standardmäßig 7).

  • Verschlüsselung: Mit einer Passphrase (mindestens 12 Zeichen) wird die Datei verschlüsselt (AES-256-GCM). Bewahren Sie die Passphrase an einem anderen Ort auf: Ohne sie lässt sich eine Sicherung nicht wiederherstellen.
  • SFTP-Kopie: Jede Sicherung wird außerdem in einen Ordner auf einem anderen Server kopiert (Passwort oder privater Schlüssel). Der erste Klick auf SFTP-Ordner testen zeigt den Host-Schlüssel des Servers, dem Sie vertrauen sollen; Kopien gehen nur an einen Server mit diesem Schlüssel. Der Ordner behält so viele Sicherungen wie der Server.
  • E-Mail bei fehlgeschlagener Sicherung sendet eine Nachricht über den SMTP-Server aus Einstellungen → Benachrichtigungen.
  • Wiederherstellung läuft bei gestopptem Server: auf der Appliance über den Menüpunkt Konsolensicherung wiederherstellen des Einrichtungsmenüs; mit Linux-Paketen systemctl stop watchzit-server, dann watchzit-server --data-dir /var/lib/watchzit --restore FILE als Benutzer watchzit mit geladener /etc/watchzit/server.env (eine verschlüsselte Sicherung liest ihre Passphrase aus WATCHZIT_BACKUP_PASSPHRASE oder --restore-passphrase-file), anschließend den Server starten. Die Wiederherstellung ersetzt alles in einer Transaktion; eine Sicherung einer älteren Version wird beim Start des Servers auf den aktuellen Stand gebracht. Agenten arbeiten weiter: Sie vertrauen demselben Zertifikat.

Sicherheit

  • Die Konsole verwendet ausschließlich HTTPS, eine strikte Content Security Policy und Schutz vor Cross-Site-Anfragen; sie antwortet nur den erlaubten Netzwerken.
  • Passwörter werden mit Argon2id gehasht; gespeicherte Geheimnisse (SNMP-, Datenbank- und API-Passwörter, Kanäle) werden mit dem geheimen Schlüssel des Servers verschlüsselt.
  • Agenten werden an ihrem eigenen Schlüssel erkannt; sie vertrauen dem Server anhand des gepinnten Fingerabdrucks seines Agenten-Zertifikats.
  • Melden Sie Sicherheitslücken vertraulich: siehe SECURITY.md im Repository.
